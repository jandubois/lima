Design Observations ¶

Concerns ¶

  • Config.Validate() cannot succeed on Linux yet (in-scope for the series). Every value this PR interpolates into a root command line is safe because identifiers.Validate constrains it to [A-Za-z0-9]+([._-][A-Za-z0-9]+)*, which admits no whitespace and no sudoers or fnmatch metacharacter. But validatePath returns errors.New("vmnet code must not be called on non-Darwin") at validate.go:174 for any non-empty Paths entry, and the shared template always sets socketVMNet and varRun. So Validate() errors out on every Linux host today, and the identifier checks plus the Linux bridge-length check at validate.go:42 are unreachable on the platform they were written for. #5485 has to port that gate. Claude Opus 5
  • The digest invalidates the sudoers file on every lima upgrade (future). Today only a socket_vmnet upgrade forces a regeneration, and sudoers.go:117 already reports that as "out of sync and must be regenerated". Pinning the helper's own bytes extends that to every lima release. Worth deciding deliberately rather than discovering it in a bug report. Gemini 3.1 Pro
  • One string serves two grammars (in-scope). StartCmd and TapCmd produce a single string that is both split into argv by reconcile and embedded in sudoers. A typed specification holding a path plus an argument slice, with separate renderers for the two consumers, would put validation in one place and remove the whitespace coupling behind I2. Codex GPT 5.6 Sol
  • The helper path varies with how limactl was invoked (in-scope for #5485). SelfDirs() starts from exec.LookPath(os.Args[0]). Since VerifySudoAccess compares the whole generated text against the installed file, a user whose limactl resolves through a different prefix gets "out of sync" rather than a working network. Claude Opus 5

Strengths ¶

  • Character classes instead of * is the right call, and the comment's reasoning matches sudoers(5): command arguments are matched as one concatenated string, so * crosses word boundaries. Claude Opus 5 Codex GPT 5.6 Sol Gemini 3.1 Pro Gemini 3.5 Flash

Review Process Notes ¶

Skill improvements ¶

  • When a finding's severity depends on a mechanism that a companion PR introduces, state which of the two outcomes the mechanism produces before assigning the severity. A defect that renders an invalid privileged command and one that renders a valid but wrong one read identically in a diff, and they differ by an order of magnitude in consequence.
  • Before crediting a wildcard, glob, or character class in a generated configuration file as a safety property, identify which library evaluates it at runtime and whether its behaviour depends on locale, case folding, or path separators. A pattern that is exact under the C locale is not exact under every locale, and the tool's own default is what settles it.
  • When a test guards itself with a runtime capability check, run the suite and confirm the guarded body executes before crediting it as coverage. A test that skips on every platform reads as coverage in a diff and in a coverage summary.

Repo context updates ¶

  • [repo] usrlocal.LibexecLima() never returns a non-nil error; its only return statement is return candidates, nil. A caller that writes if err != nil || len(dirs) == 0 { return "", err } therefore reports "not found" as success. Flag that shape wherever it appears.
  • [repo] pkg/networks/validate.go applies its path safety checks (absolute, no whitespace, no symlink, root-owned, not group-writable) only to fields of the Paths struct. Any other path that reaches a sudoers file or a sudo command line gets none of them. The file-level comment in commands.go states the no-whitespace invariant as though it were global.
  • [repo] pkg/networks/reconcile/reconcile.go splits the rendered command string on a single space before handing it to sudo, so whitespace anywhere in an interpolated value shifts every later argument.
  • [repo] REMOVE nothing from deep-review-context.md this round; no entry was contradicted by the code under review.
