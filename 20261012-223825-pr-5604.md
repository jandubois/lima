## Executive Summary

The PR makes `ssh.overVsock=true` krunkit's Linux default again. It replaces the dial-only probe, which krunkit always satisfied, with a 10 s wait for an `SSH-` banner, and a boot script re-runs the systemd generator so systemd ≥ 259 guests get `sshd-vsock.socket`. The banner probe fixes the #5085 hang. But `templates/default.yaml` and the port docs now misstate the default, and every start of a Linux guest without vsock sshd blocks for 10 s.

With the default now `true`, `Start` runs this probe for every Linux guest, after `WaitOpeningSSHPort` and before `ConfigureDriver` exposes the usernet SSH port (`krunkit_driver_darwin_arm64.go:131-148`). package krunkit

import (
	"net"

// probeServe mimics krunkit's host-side socket: it accepts every connection,
// writes reply (empty when no sshd listens on the guest vsock port), and closes.
func probeServe(t *testing.T, reply string) string {
	t.Chdir(t.TempDir())
	var lc net.ListenConfig
	l, err := lc.Listen(t.Context(), "unix", "p.sock")
	if err != nil {
		t.Fatal(err)
	}
	t.Cleanup(func() { l.Close() })
	go func() {
		for {
			c, err := l.Accept()
			if err != nil {
				return
			}
			_, _ = c.Write([]byte(reply))
			c.Close()
		}
	}()
	return "p.sock"
}

			err := startVsockForwarder(t.Context(), sock, "127.0.0.1:0")
			t.Logf("err=%v elapsed=%v", err, time.Since(start).Round(100*time.Millisecond))
		})
	}
}

## Suggestions

S1. **Plain mode never runs the boot script** — `pkg/driver/krunkit/krunkit_driver_darwin_arm64.go:320` [Gemini 3.5 Flash]

```go
			entryPath := "boot.Linux/" + entry.Name()
```

`boot.sh` skips `boot.Linux/` in plain mode (`pkg/cidata/cidata.TEMPLATE.d/boot.sh:73-77`). A systemd ≥ 259 guest started with `plain: true` therefore never gets `sshd-vsock.socket`, and falls back to usernet after I2's 10 s.

`cidata` accepts a driver script under any `boot.<OS>/` directory (`pkg/cidata/cidata.go:456-463`). `boot.essential.Linux/` runs in plain mode too, and ahead of every `boot.Linux/` script, which also shortens the race described under Design Observations.

Fix: emit the script as `boot.essential.Linux/00-sshd-vsock.sh`.

S2. **The boot script runs even when `ssh.overVsock` is false, and no test pins the selection** — `pkg/driver/krunkit/krunkit_driver_darwin_arm64.go:317` [Claude Opus 5.5]

```go
			if isFedora && entry.Name() != "00-sshd-vsock.sh" {
```

`BootScripts` ships `00-sshd-vsock.sh` whatever the config says. On a systemd ≥ 259 guest that opted out, the script still runs `systemctl daemon-reload` and starts a vsock sshd listener on every boot. Krunkit does not expose a port-22 device in that case (`krunkit_darwin_arm64.go:58`), so nothing on the host can reach that listener.

The Fedora branch also matches the file by a string literal. If the file is renamed, Fedora guests drop the workaround with no error.

Fix: skip the script unless `l.Instance.Config.SSH.OverVsock` is true, and add a `BootScripts` test covering a Fedora image and an opted-out instance.

S3. **CI never runs the new banner tests** — `pkg/driver/krunkit/krunkit_driver_darwin_arm64_test.go:72` [Codex GPT 6 Astra]

```go
func TestWaitVsockSSHBanner(t *testing.T) {
```

The file builds only on darwin/arm64. The `unit` job runs `go test ./...` on ubuntu-24.04, the macOS jobs that run `go test` use Intel runners, and the one arm64 macOS runner runs only golangci-lint. A revert to the dial-only probe would therefore pass CI. The gap predates the PR and covers the whole package.

Fix: `waitVsockSSHBanner` and `readVsockSSHBanner` use only the standard library, so move them and their tests into files without the `_darwin_arm64` suffix, where the `unit` job runs them.

S4. **The fallback diagnostics name one cause and hide the timeout** — `pkg/driver/krunkit/krunkit_driver_darwin_arm64.go:141` [Claude Opus 5.5, Gemini 3.5 Flash]

```go
				Debugf("Failed to start vsock forwarder (systemd is older than v256?)")
```

The fallback now also fires when the boot script has not started `sshd-vsock.socket` within the window, and in plain mode. And `waitVsockSSHBanner` wraps only the last attempt's error (`krunkit_darwin_arm64.go:230`), so after 10 s the log reads `no SSH banner on "…": EOF`, with no sign that a window expired.

Fix: put the timeout in the error, as in `fmt.Errorf("no SSH banner on %q within %s: %w", unixSockPath, timeout, err)`, and name both causes in the hint.

S5. **The closed-socket test waits 2 s** — `pkg/driver/krunkit/krunkit_driver_darwin_arm64_test.go:85` [Gemini 3.5 Flash]

```go
	assert.ErrorContains(t, waitVsockSSHBanner(t.Context(), sock, 2*time.Second), "no SSH banner")
```

The retry loop sleeps 1 s between attempts, so this test takes 2.00 s. With a 100 ms timeout it takes 0.10 s and still passes through the same EOF and `ctx.Done()` branches (run against the review SHA).

Fix: pass `100*time.Millisecond`.

## Design Observations

### Concerns

- **Whether vsock gets used depends on boot timing** (in-scope) [Codex GPT 6 Astra, Claude Opus 5.5, Gemini 3.5 Flash]. The 10 s window opens when guest TCP 22 answers, but the boot script runs much later. `cloud-final` is ordered `After=multi-user.target`, so it starts after sshd. Within it, `package_update_upgrade_install` runs before `scripts_per_boot` (cloud-init's `config/cloud.cfg.tmpl`) and runs once per instance, so with `upgradePackages: true` the first boot almost certainly misses the window. Inside `boot.sh`, `00-check-rtc-and-wait-ntp.sh` and `00-modprobe.sh` sort ahead of the script. libkrun ships a PL031 RTC, so the NTP wait probably exits at once, though no guest confirmed it. A miss means usernet for that boot, the merge-base transport, which is why this is not a finding. The PR's log excerpt does not show the margin; the author could post `journalctl` timestamps for `sshd.service` and `sshd-vsock.socket` on a first boot and a restart. The fixes in I2 and S1 both narrow the race.

### Strengths

- **The banner probe fixes the false positive behind #5085** [Claude Opus 5.5, Codex GPT 6 Astra, Gemini 3.1 Pro, Gemini 3.5 Flash]. At the merge-base, `startVsockForwarder` returned success at once on a socket with no sshd behind it (I2's merge-base run), so SSH went into a dead vsock port. Reading for `SSH-` refuses that case.
- **The boot script is narrowly guarded and idempotent** [Claude Opus 5.5, Codex GPT 6 Astra, Gemini 3.1 Pro]. It exits without `systemctl`, without the generator, or when the socket is already active, and the path it checks matches where `systemd-ssh-generator` v259 writes `sshd-vsock.socket` (its normal `arg_dest`).
- **The probe bounds its reads** [Codex GPT 6 Astra, Gemini 3.1 Pro, Gemini 3.5 Flash]. A read deadline stops a silent peer and an 8 KiB `LimitReader` stops a chatty one, and preamble lines before the version string are accepted, as RFC 4253 allows.
