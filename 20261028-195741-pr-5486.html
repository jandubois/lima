Executive Summary ¶

The PR enables the Linux shared, host and bridged networks, and its new commit replaces the pkill -F stop grant with a stop subcommand that checks the target's executable. That closes the root kill. But when a helper killed with SIGKILL leaves its PID file and another process gets the PID, stop refuses and keeps the root-owned file, so every limactl start, stop and delete fails until that PID frees. The new experimental warning also fires for user-v2.

A start killed with SIGKILL (the OOM killer, cgroup.kill) leaves its PID file behind. Once another process gets that PID, store.ReadPIDFile reports the network running, since it counts EPERM as alive (pkg/store/instance.go:279-283), and stopNetwork calls stop, which refuses and keeps the file. Reconcile stops every unused network and returns the first error (pkg/networks/reconcile/reconcile.go:69-81), which limactl start returns (cmd/limactl/start.go:641-644). So no instance starts, stops or deletes until the PID frees, and the user cannot remove the root-owned file. pkill -F cleared this state by killing the process. The probe's last line, for a free PID, is the control.

Concerns ¶

  • limactl still decides "running" from a PID it cannot verify (future) Claude Opus 5.5 Codex GPT 6 Astra: after I1's patch, a network that the starting instance itself uses still stays down. startNetwork (pkg/networks/reconcile/reconcile.go:229-235) sees the reused PID, skips start, and attaches the tap to a bridge without dnsmasq, so the guest does not get a DHCP lease until a stop clears the file. A helper status subcommand that answers from the lock would replace the guess.
  • A caller-controlled stderr can hold up teardown (future) Codex GPT 6 Astra: the log write before <-sig (cmd/lima-privileged-net/network_linux.go:130) blocks on a full pipe, so a SIGTERM waits until the caller reads. limactl hands the helper a log file, so only a direct caller can do this, and the code at the merge-base did the same.
  • Reinstalling the helper while a network is up (in-scope) Claude Opus 5.5: stop is now digest-pinned, so sudo rejects it until the regenerated sudoers file is installed, and the old helper keeps running meanwhile. linux.md:66-68 says to reinstall the file; telling users to stop their instances first would close the gap.
  • Round 2's concerns still apply (future) Codex GPT 6 Astra Gemini 3.5 Flash Claude Opus 5.5: Reconcile is not serialized across processes, stopNetwork waits only 5 s for the PID file, and on macOS one LIMA_HOME stopping its last instance still stops socket_vmnet under another.

  • The verified stop closes the root kill (in-scope) Claude Opus 5.5 Codex GPT 6 Astra Gemini 3.5 Flash: in a Linux instance, stop refused a PID file that named a root sleep, which kept running, and it stopped a live helper process.
  • The PID file is written atomically (in-scope) Codex GPT 6 Astra Claude Opus 5.5: under a 2-byte file-size limit on Linux, a direct write left 35 in an existing PID file, while writePIDFile kept the old content and removed its .tmp file.
