## Important Issues

I1. **A new test fixture depends on the process umask, so `go test ./...` fails under `umask 077`** — `pkg/blockdevice/block_device_darwin_test.go:435` [Claude Opus 5]

```go
	publicDir := filepath.Join(shortTempDir(t), "public")
	assert.NilError(t, os.Mkdir(publicDir, 0o755))
	err := validatePrivateSocketPath(filepath.Join(publicDir, "block-device.sock"), uid)
	assert.ErrorContains(t, err, "must not be accessible by group or other users")
```

`os.Mkdir` masks its mode argument with the process umask, so under `umask 077` this creates a `0700` directory. `validatePrivateSocketPath` (`pkg/blockdevice/block_device_darwin.go:365`) then correctly returns nil and the assertion fails. The production check is right; the fixture is wrong.

`pkg/blockdevice` is new in this PR, so the merge-base carried no such test, and this is the only failure anywhere in the tree under a hardened umask. CI runs at umask 022 and never sees it, so a contributor who hardens their umask meets a red suite on an unmodified checkout and has no reason to suspect the test rather than the code.


## Design Observations

### Concerns

**`pkg/limayaml` now links the privileged helper implementation** *(in-scope)* [Claude Opus 5]. `pkg/limayaml/validate.go` imports `pkg/blockdevice` for two pure-string helpers, but on darwin that package also carries the sudo invocation, the SCM_RIGHTS protocol and the `getattrlist` ACL probe. I measured it: `go list -deps ./pkg/limayaml` on darwin now includes `github.com/balajiv113/fd`, the merge-base `validate.go` had no `blockdevice` import at all, and the edge is absent under `GOOS=linux`. Every darwin binary that validates a `lima.yaml`, including `lima-driver-qemu` and `limactl-mcp`, now links that code. Moving `path.go` into a leaf package would answer this and the dependency half of round-5 S13, which the decline did not address.

**Nothing refuses the host's boot disk** *(future)* [Claude Opus 5]. `disk.md:148` warns against granting it, and that sentence is the only guard. A first cut would compare the requested whole-disk name against the device behind `statfs("/")`, refusing rather than allowing when APFS synthesis makes the comparison ambiguous.

**`--block-device` can only add, never remove** *(future)* [Claude Opus 5]. `cmd/limactl/editflags/editflags.go:379` emits `.blockDevices += [...] | .blockDevices |= unique`, and `cmd/limactl/start.go:301` applies edit flags to existing instances. So `limactl start foo --block-device=/dev/disk4` followed by `--block-device=/dev/rdisk4` now fails the new overlap check with no CLI way to drop the first entry. The instance survives, because validation runs before the write, but the user has to reach for `limactl edit`.

**Block-device grants stay per-user inside a file every user rewrites** *(in-scope)* [carried from round 5]. Round 6 answered the documentation half (S3 of round 5), and `disk.md:131-134` now states the limit plainly. The model itself is unchanged and remains the author's decision.

### Strengths

- **The fd handoff authenticates in both directions at the right moments** [Claude Opus 5]. The helper checks the listener's uid before sending the caller-supplied nonce (`block_device_darwin.go:108-113`), and the receiver checks peer uid, nonce, device type and `Rdev` before accepting the descriptor (`:633-668`).
- **`retainedFileDescriptors.CloseAll` is idempotent and every failure path calls it** [Claude Opus 5]. That is what releases the whole-disk `flock` even when the `sendErrCh` send blocks forever.
- **The ACL check is neither vacuous nor a false-positive trap** [Claude Opus 5]. Replicating `pathHasExtendedSecurityACL` over `/`, `/usr`, `/usr/local`, `/opt`, `/private`, `/System` and `/Applications` reports no ACL, while `~/Desktop`, which carries a stock ACL, reports one.
- **`TestContainsActiveFragmentLineContinuations` checks the sudoers logic against real `visudo`** [Claude Opus 5], an oracle independent of the code under test. It is the strongest test in the PR.
- **Whole-disk locking normalizes raw/block aliases and partitions correctly** [Codex GPT 5.6 Sol, Gemini 3.1 Pro, Gemini 3.5 Flash].
- **Both round-6 regression tests fail when their fix is reverted** (verified during consolidation; see Testing Assessment).

## Testing Assessment

I ran the following in a clean lead worktree at `cb78c1b3` with the BATS submodules initialized. `go build ./...`, `go test ./...`, `GOOS=linux go build ./...` and `GOOS=windows go build ./...` all exit 0 with no failures. Hosted CI for this SHA reports 34 checks passing and 2 Netlify checks skipped, with none failing or pending.

Both round-6 regression tests fail when their fix is reverted, so they pin real behavior:

With the submodule initialized, `bats --count ./hack/bats/extras/vz-block-device.bats` reports 3 and exits 0. Running two throwaway suites under `LIMA_BATS_ALL_TESTS_RETRIES=2`, the unguarded test body executed three times and a body carrying the round-6 `BATS_TEST_RETRIES=0` executed once. The file-scope assignment takes effect after `helpers/load.bash:13` and wins, so the guard holds even if the environment variable returns.

Required:

1. **`Open`'s nonce comparison** (`pkg/blockdevice/block_device_darwin.go:645-649`) has no Go test. Measured coverage for the package is 46.6%, with `Open` at 0.0% and `ServeSudoOpenBlockDevice` at 10.8%. A security gate that stops working silently is invisible to users, and this one is unit-testable without root: listen the way `Open` does and connect from a goroutine that sends the wrong nonce. The peer-uid half is already covered at 83.3%.
2. **Byte-stability of `networks.Config.Sudoers()` inside its own package** (S6). The invariant governs every existing installation and the only literal pin is a darwin-only test in another package.

Optional tests: `unix.O_NOFOLLOW` on the lock file (`pkg/driver/vz/block_device_darwin.go:74`), and the empty-path branch at `cmd/limactl/editflags/editflags.go:373-375`.

Already covered, do not re-add: grant ordering and de-duplication, cross-instance lock aliases and release, sudoers continuations against real `visudo`, peer-UID ordering, socket symlink rejection, descriptor identity, `FD_CLOEXEC` on the dup, per-driver `blockDevices` rejection in the four non-VZ drivers, and the real guest-to-host round trip.

## Documentation Assessment

`disk.md`'s rewritten setup section is accurate on every behavioral claim I checked against the code: the macOS 14 gate, the symlink-relative helper lookup, per-user scoping, the 0444 install, the `--check` semantics, the 20-byte identifier cap and whole-disk locking. The `--check` paragraph at `:142-145` matches `verifySudoersFile` exactly, including the containment fallback that applies only without `--block-device`.

The documented fallback revocation, `sudo visudo -f /etc/sudoers.d/lima`, does not undo the 0444 install. I checked whether visudo normalizes the mode on write-back, since that would recreate round-5 I1: editing a 0644 file with visudo 1.9.17p2 writes the edit back and leaves the mode at 644, so it preserves what it finds.

Four gaps: S13 above, plus three omissions. The docs never say that two overlapping paths are now rejected, and `disk.md:167-171` presents `/dev/rdiskN` as an interchangeable alternative while the YAML sample sidesteps the question by pairing `disk4` with `rdisk5`. The docs do not mention that the helper path may contain no whitespace or sudoers metacharacters (`block_device_darwin.go:438-440`), nor that an extended ACL on any ancestor is fatal (`:481-494`), so `/opt/my lima` fails with an error the page does not anticipate. `internals.md` documents the new lock files well but omits the handoff socket (S15).

## Acknowledged Limitations

Each re-resolved against `cb78c1b3`.

- **`--check --block-device` on a subset of installed grants is deliberate.** `verifySudoersFile:131` gates the containment fallback on `len(blockDevices) == 0`. The negative BATS assertion is now at `vz-block-device.bats:311-312` with new expected text and pins the same failure. Do not re-suggest making that branch tolerant.

## Review Process Notes

S14 is about the commit message, so it cites the short SHA and quotes the body rather than a file. The citation lint counts that as a finding without a leading block; the warning is expected and inventing a file reference would point the reader at code the finding is not about.

### Skill improvements

- **When a review adds or changes test fixtures, run the suite under a hardened process umask as well as the default.** `os.Mkdir`, `os.WriteFile`, `os.OpenFile` and their equivalents in other languages mask the mode argument with the umask, so a fixture that creates a deliberately permissive file or directory silently creates a restrictive one for any contributor whose umask differs from CI's. The test then asserts against behavior it never produced. One extra run of the suite settles it.

- **When a fix removes a dead symbol, grep for its siblings before accepting the fix as complete.** Dead code is usually found one symbol at a time, and a helper that had no callers often has an exported neighbour in the same file with the same problem. Enumerate the callers of every nearby symbol with a related name, not only the one the previous round named.

- **A test whose child process or subcommand carries the assertion needs a positive signal that the child ran.** A process that silently does nothing usually exits 0, so a parent asserting only on the exit status passes when the child was never invoked, when a filter excluded it, or when it was renamed. Require the parent to observe something the child could only have produced by running.

### Repo context updates

- **[repo] The only CI job that runs `hack/validate-artifact.sh` is `release` in `release.yml`, not `Artifacts Darwin`.** The `release` job builds the Linux and Windows archives and downloads the Darwin ones, so it is the single place where assertions about release-archive contents execute for every platform. `Artifacts Darwin` only builds and uploads.

- **[repo] Darwin-only Go tests run in CI, but only on Intel.** `go test ./...` runs in four jobs: `unit` (ubuntu), `windows` (WSL2), `qemu` = "Integration tests (QEMU, macOS host)" (macos-15-large, Intel), and `vmnet` restricted to `./pkg/networks/...`. Every macOS job that runs `go test` uses `macos-15-large`, annotated Intel; the only other macOS runner in `test.yml` is `macos-26` in the `lint-go` matrix (`:80`), whose single step runs golangci-lint. So a `_darwin_test.go` file does execute in CI, while a `_darwin_arm64_test.go` file is only type-checked by that matrix and never runs.

- **[repo] `BATS_TEST_RETRIES` set at file scope in a `.bats` file overrides `hack/bats/helpers/load.bash`.** `load.bash:13` assigns it from `LIMA_BATS_ALL_TESTS_RETRIES`, and a later file-scope assignment in the suite wins because bats sources the file after resetting the variable. The comment at `load.bash:11-12` warns that the value cannot be imported from the parent environment, which is about the environment rather than about a file-scope assignment. Measured: a suite setting `BATS_TEST_RETRIES=0` runs a failing test once under `LIMA_BATS_ALL_TESTS_RETRIES=2`, where an unguarded suite runs it three times.

- **[repo] macOS `visudo` preserves a sudoers file's existing mode on write-back.** It does not normalize to `SUDOERS_MODE`. Editing a 0644 file leaves it 0644, so a documented `visudo -f` procedure does not undo an install mode chosen elsewhere. Run as a non-root user it refuses a file it cannot write, reporting "Permission denied" before invoking the editor. It also invokes the editor as `$EDITOR -- <file>`, so a script used as `$EDITOR` must take its last argument, not `$1`.

### Concerns

**`pkg/limayaml` now links the privileged helper implementation** *(in-scope)*

`pkg/limayaml/validate.go` imports `pkg/blockdevice` for two pure-string helpers, but on darwin that package also carries `block_device_darwin.go`: the sudo invocation, the SCM_RIGHTS protocol, and the `getattrlist` ACL probe. ### Design Observations

#### Concerns

None. The design is exceptionally well-compartmentalized. Delegating generic sudoer compilation and verification to `pkg/sudoers` cleanly decouples block-device logic from general networking and VM orchestration.

#### Strengths

- **Whole-Disk lock reuse**: Partition and alias deduplication via base disk name lock keys is highly robust. Allowing partition reuse *within the same VM* while rejecting separate VM attempts on raw/block aliases prevents storage corruption beautifully.
- **SCM_RIGHTS descriptor handoff**: Returning file descriptors through a secure Unix socket ensures that the root-owned helper is only run momentarily on startup to open `/dev/diskN` and then exits, avoiding long-lived root daemons or rootless credential leaks.
- **Stable grant sorting**: Applying `slices.Sort` and `slices.Compact` to generated sudoers entries avoids spurious out-of-sync warnings when `--check` parses files, establishing a reliable verification loop.

### Acknowledged Limitations

The following limitations are explicitly acknowledged by design or documented in the comments and are excluded from being flagged as issues:
1. **Partial check limitations**: `--check` reports combined multi-user or manually preserved files as out of sync by design because `--check --block-device` performs strict byte-for-byte formatting comparisons. This is documented in `disk.md` and verified in `vz-block-device.bats:311-312`.
2. **Teardown sequence**: Teardown in `vz-block-device.bats:27` aborts if the sudoers grant cannot be removed, to prevent physical device reuse/collisions on macOS.
3. **No `/dev` node guest guarantee**: Basename-to-id mapping is capped at 20 bytes (e.g. `virtio-disk4`) and does not guarantee `/dev` node naming.
4. **Non-blocking drain on failure**: The non-blocking drain after helper open failures is designed to prevent descriptor receive hangs.
5. **No network ACL checking**: Extended ACL validation is restricted to block-device paths and deferred for network paths.
