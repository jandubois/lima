## Executive Summary

The PR moves tap-device naming into `lima-privileged-net`, which derives the name from `SUDO_UID`. It also validates the helper path and makes the command renderers testable on every host. But the new sudoers entry ends in a bare `*`, so a group member can put `--bridge=docker0` ahead of the instance name and attach a tap they own to any host bridge. And the 32-bit name hash still lets one member block another's device after a one-minute search.

## Important Issues

I1. **The sudoers `*` lets a caller override the pinned `--bridge`** — `pkg/networks/commands.go:255` [Claude Opus 5.5, Codex GPT 6 Astra, Gemini 3.1 Pro, Gemini 3.5 Flash]

```go
func (c *Config) tapCmd(daemonPath, netName, instArg string) string {
	return fmt.Sprintf("%s tap --bridge=%s --network=%s %s", daemonPath, c.BridgeName(netName), netName, instArg)
}
```

sudo joins the arguments with spaces and matches them with `fnmatch(pattern, args, 0)`, so the `*` that `TapCmdPattern` renders also matches `--bridge=docker0 default`. `SetInterspersed(false)` stops flag parsing at the first positional argument. The smuggled flag comes before it, so the last `--bridge` wins.

`tapUp` accepts any existing bridge (`cmd/lima-privileged-net/network_linux.go:409`), so the caller gets a tap they own on `docker0` or `virbr0`, with raw layer-2 access to that network. The merge-base entry used a character class that did not match whitespace, and the comment at `commands.go:245-249` promises the protection this code lacks.

The finding is latent, because nothing on master calls `TapCmdPattern`; #5486's `sudoers.go:59` installs it.

I2. **A 32-bit tap name still lets one group member pre-create another's device** — `pkg/networks/commands.go:266` [Claude Opus 5.5]

```go
func TapName(uid int, instName, netName string) string {
	sum := sha256.Sum256(fmt.Appendf(nil, "%d/%s/%s", uid, instName, netName))
	return fmt.Sprintf("%s%x", tapPrefix, sum)[:len(tapPrefix)+tapDigits]
}
```

The name keeps 8 hex digits of the hash, 32 bits. An attacker searches for an instance name `x` whose `TapName(attackerUID, x, net)` equals the victim's name and runs the permitted `tap` command for `x`, which creates the device under the attacker's uid. When the victim starts, `tapUp` finds a device someone else owns and refuses (`network_linux.go:431-433`). Tap names show in `ip link` and vanish at reboot, so the attacker can learn a name and claim it first.

The search below took 48 s on 8 cores. The `TapName` comment still promises that no member can "create, and thereby deny, another member's device". Like I1, this is latent until #5486's `sudoers.go:59` installs the entry.

## Suggestions

S1. **`daemonPath` promises an empty-path guard it does not have** — `pkg/networks/commands.go:204` [Claude Opus 5.5, Gemini 3.5 Flash]

```go
// daemonPath panics instead of returning an error because the command renderers
// below interpolate the result into a root command line, where an empty path
// would silently turn the first argument into the program to run.
func (c *Config) daemonPath(daemon string) string {
	path, err := c.DaemonPath(daemon)
	if err != nil {
		panic(fmt.Errorf("failed to get the path of daemon %#q: %w", daemon, err))
	}
	return path
}
```

`DaemonPath(SocketVMNet)` returns `("", nil)` when `paths.socketVMNet` is unset, and `daemonPath` panics only on an error. The PR also dropped the `c.Paths.SocketVMNet == ""` panic from the rendering arm. Nothing breaks today, because `StartCmd` still panics first through `IsDaemonInstalled`, which reports an empty path as not installed, and nothing else calls `startCmd`. So the dropped guard was unreachable, and the comment credits `daemonPath` with a check that only `StartCmd`'s precondition performs.

Fix: add `if path == "" { panic(...) }` to `daemonPath`, which makes the comment true for every renderer.

S2. **`TapCmd` takes the instance first, unlike `tapCmd` and every other `Config` method** — `pkg/networks/commands.go:241` [Gemini 3.5 Flash, Claude Opus 5.5]

```go
func (c *Config) TapCmd(instName, netName string) string {
	return c.tapCmd(c.daemonPath(LimaPrivilegedNet), netName, instName)
}
```

`StartCmd`, `StopCmd`, `PIDFile`, `BridgeName`, `TapCmdPattern` and `tapCmd` all take the network name first. `TapCmd` reverses the order of two strings the compiler cannot tell apart, and no test calls it, since `daemonPath` panics unless the test binary's prefix has a non-empty `libexec/lima`. I swapped the arguments inside `TapCmd` and `go test ./pkg/networks/` still passed. #5486's `reconcile.go:265` calls it in the right order today.

Fix: take the network name first, matching `tapCmd`.

S3. **The helper-path check lets sudoers metacharacters through** — `pkg/networks/config.go:206` [Claude Opus 5.5]

```go
	if strings.ContainsAny(path, " \t\n") {
		return "", fmt.Errorf("path %#q contains whitespace", path)
	}
```

The path goes verbatim into the sudoers file, where sudoers(5) requires a backslash before `!`, `=`, `:`, `,`, `(`, `)` and `\`. `Sudoers()` escapes none of them, so once #5485 adds the helper's entries, an install prefix containing a comma or colon corrupts the rule. `validateVarRunString` (`validate.go:127-144`) already solves this for `paths.varRun` by requiring every component to be an identifier.

Fix: reject those characters along with whitespace, or apply the identifier rule to each component the way `validateVarRunString` does.

## Design Observations

### Concerns

- **One string serves two grammars** (future) [Claude Opus 5.5, Codex GPT 6 Astra]: the sudoers `fnmatch` pattern and the argv that `reconcile.go` splits on spaces both come from one `fmt.Sprintf`, and I1 grew out of that coupling. A command type holding the path and an argument slice, with one renderer for sudoers and one for exec, would keep `--`, escaping (S3) and splitting in one place.
- **#5486's sudoers comment repeats I1's claim** (future) [Codex GPT 6 Astra]: `sudoers.go:56-58` in #5486 says the positional wildcard stops smuggling. It needs the same correction when #5486 rebases onto the fix.
- **`limaPrivilegedNetPath` takes `dirs[0]`** (future) [Codex GPT 6 Astra, Gemini 3.1 Pro, Gemini 3.5 Flash]: the prior review's S1 is still open. A `libexec/lima` directory without the helper shadows a later one that has it. This predates the PR.

### Strengths

- **The root side names the device** (in-scope) [Claude Opus 5.5, Codex GPT 6 Astra, Gemini 3.1 Pro, Gemini 3.5 Flash]: `SUDO_UID` is the one uid the caller cannot forge. The unprivileged callers in #5486 (`reconcile.go:261`, `qemu.go:868`) use `os.Getuid()`, which matches what sudo reports.
- **Rendering runs on every host** (in-scope) [Claude Opus 5.5, Codex GPT 6 Astra, Gemini 3.1 Pro, Gemini 3.5 Flash]: `startCmd` and `tapCmd` take a resolved path, so the privileged-net subtest passes instead of skipping, and the `bridged` expectation (`en0`) now matches `networks.TEMPLATE.yaml`.
- **Both sides accept the same names** (in-scope) [Claude Opus 5.5]: the helper checks `--network` and the instance with `identifiers.Validate`, the rule `dirnames.ValidateInstName` builds on.

## Review Process Notes

### Skill improvements

- **Truncated hash as an ownership key**: when a change relies on a hash to keep one principal from producing another principal's identifier (a device, socket, lock or cache name), count the bits left after truncation and estimate a preimage search at commodity hashing speed. An identifier squeezed into a short name limit rarely keeps enough, and putting the principal's own id in clear closes the gap by construction.

### Repo context updates

- **[repo] Generated sudoers command lines and the helper's parser form one contract**: sudo matches a rule's arguments as one space-joined string with `fnmatch`, so `*` spans whitespace and matches flags. Every wildcard argument in a rule `pkg/networks` renders must follow a pinned `--`, or be a character class that excludes whitespace, and the privileged helper must reject surplus positional arguments. Flag a wildcard that cobra could parse as a flag, and check the renderer and the helper's flag setup together, since a diff often shows only one side.

#### Design Observations

#### Concerns

- **Sudoers wildcard argument termination without `--` delimiter (in-scope)**:
  Using a wildcard `*` in sudoers rules assumes that the target application terminates option parsing before the wildcard is evaluated. With POSIX-style CLI parsers like `pflag`, `SetInterspersed(false)` only terminates flag parsing on the first non-flag argument. If the wildcard expansion begins with a flag (such as `--bridge=...`), the parser continues to process flags and overrides earlier pinned settings. Emitting an explicit `--` delimiter in the sudoers pattern and the corresponding invocation ensures that everything matched by `*` is treated strictly as positional arguments.

- **`limaPrivilegedNetPath` directory shadowing (future)**:
  `limaPrivilegedNetPath()` takes `dirs[0]` from `usrlocal.LibexecLima()` (`pkg/networks/config.go:202`) without checking if the binary actually exists in that candidate directory. If an earlier candidate directory exists without `privileged/lima-privileged-net`, it shadows later candidate directories that do contain the binary. Iterating through `dirs` to find the first existing binary would mirror the discovery logic in `pkg/plugins` and `pkg/registry`.

#### Strengths

- **Deriving tap device names from `SUDO_UID`**:
  Moving tap device naming from caller-supplied arguments to root-side derivation using `SUDO_UID` (`cmd/lima-privileged-net/network_linux.go:420`) cleanly closes the denial-of-service vulnerability identified in PR #5484 without complicating the sudoers configuration.
- **Decoupling rendering tests from host environment**:
  Extracting `startCmd` and `tapCmd` (`pkg/networks/commands.go:171,254`) allows verifying the rendered root command lines across macOS and Linux host runners without requiring helper installation.
