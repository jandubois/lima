## Executive Summary

The PR stops identifying additional disks by label and tests for a filesystem on the partition instead. That fixes the reformat-on-every-boot bug, and the test-misc CI job's restart check passes on Ubuntu. Two defects break Alpine guests. Bash arrays make `05-lima-disks.sh` unparseable under the ash that Lima runs as `/bin/bash`, so no additional disk mounts. And the `blkid` guard tests an exit status that stays 0 for a partition without a filesystem.

Four reviewers ran and all finished. Claude found both Critical defects, and Gemini 3.5 Flash pointed at the second with the wrong mechanism. This review reproduced both by booting Alpine guests with a fresh disk, and with both patches applied the same boots mounted the disk and kept it across a restart. The four Important findings are smaller. A warning fires for disks Lima never labels, a new test passes against the merge-base, comments and the commit message misstate how `mkfs.xfs` treats long labels, and a drift test skips the ext arm.

## Critical Issues

C1. **Bash arrays make the disk script unparseable on Alpine, so no additional disk is set up** — `pkg/cidata/cidata.TEMPLATE.d/boot.Linux/05-lima-disks.sh:51-54` [Claude Opus 5]

```bash

		LABEL_ARGS=(-L "$FSLABEL")
```

On Alpine, `/bin/bash` is a shim that execs BusyBox `ash` whenever GNU bash is missing, and neither pinned Alpine image ships bash. Ash has no arrays, so it rejects the whole script at line 51.

C2. **The guard reads `blkid`'s exit status, which is 0 for a partition without a filesystem** — `pkg/cidata/cidata.TEMPLATE.d/boot.Linux/05-lima-disks.sh:75` [Claude Opus 5, Gemini 3.5 Flash]

```bash
	if ! blkid -o value -s TYPE "$PARTITION" >/dev/null 2>&1; then
```

`-s TYPE` filters what `blkid` prints but not its exit status.

BusyBox `blkid`, alpine-iso's `/sbin/blkid`, ignores `-o` and `-s` and exits 0 for a missing device. With C1 fixed, first-time setup never runs there and the `mount` fails on every boot, so this patch must land with C1's.

util-linux `blkid` exits 0 for a GPT partition without a filesystem. So the script never formats such a partition, though lines 70-74 say the TYPE query handles it. At the merge-base, the next boot retried. An interrupted boot or a failed `mkfs` leaves that state, and so does the merge-base for every xfs disk with a name over 7 characters, since `mkfs.xfs` rejects its unclamped label after `sfdisk` has run (I3).


## Review Process Notes

**Skill improvements**

- When a reply claims a fix, verify the fix against the original concern; the author-dismissed gate covers only replies that dismiss, explain, or defer a finding. Report a fix that leaves the defect in place as a finding, never as an Acknowledged Limitation, because the thread's resolved status otherwise hides the defect from every later reader.
- When a changed script runs on several targets (guest distributions, container base images, CI runners), parse and run it under each target's interpreter and core tools, not only under the interpreter its shebang names. A target can map the shebang's path to another shell or ship BusyBox versions of the tools, and a linter checks only the shebang's dialect.

**Repo context updates**

- `[repo]` ADD: On Alpine guests, `boot.essential.Linux/01-alpine-ash-as-bash.sh` makes `/bin/bash` exec BusyBox `ash` whenever GNU bash is missing, and neither pinned Alpine image (alpine-iso, nocloud) ships bash. Every `#!/bin/bash` boot script must therefore parse and run under ash, which has no arrays; `[[`, `${var:off:len}` and `set -o pipefail` do work, although the shim's own comment says `[[` does not. Check with `busybox sh -n`; shellcheck follows the shebang and cannot see this. No CI job attaches an additional disk to an Alpine template, so a broken disk script there stays green.
- `[repo]` ADD: `/sbin/blkid` is BusyBox on the alpine-iso image and util-linux on the Alpine nocloud and Ubuntu images. BusyBox `blkid` ignores `-o` and `-s`, prints its default line, and always exits 0; util-linux `blkid -s TAG` exits 0 whenever the device has any tag, TAG or not. A guard built on `blkid` must test its output, not its exit status.
- `[repo]` ADD: Only `boot.Linux/05-lima-disks.sh` reads `LIMA_CIDATA_DISK_*`. Darwin and FreeBSD guests get their additional disks attached, but nothing formats, labels or mounts them, so a host-side warning or default about disk formatting applies to Linux guests only.
- `[repo]` ADD: `limayaml.Validate(y, true)` runs `warnExperimental`, which dereferences `mountType`, and `Load` leaves `mountType` nil until the driver resolves it. A unit test that validates with `warn` set must give its fixture a `mountType`, or it panics. `github.com/sirupsen/logrus/hooks/test` captures the warnings through the existing logrus dependency.

### Design Observations

**Concerns**

##### I1. **BusyBox `blkid` flag incompatibility causes continuous formatting and data loss on Alpine guests** — `pkg/cidata/cidata.TEMPLATE.d/boot.Linux/05-lima-disks.sh:75`

```bash
	if ! blkid -o value -s TYPE "$PARTITION" >/dev/null 2>&1; then
```

The guard relies on standard `util-linux` flags (`-o` and `-s`). However, BusyBox `blkid` (the default on Alpine Linux) supports absolutely no flags or options other than `--help`. Passing `-o` or `-s` causes BusyBox `blkid` to exit with an error (non-zero). Because the command fails, the `if ! blkid ...` block (line 75) evaluates to `true` on every boot, forcing `mkfs` (line 87) to run on every boot and silently wipe the disk on Alpine guests.

Fix: Check filesystem presence by matching `TYPE=` on the raw output of `blkid "$PARTITION"`, which is fully compatible with both BusyBox and `util-linux` `blkid` implementations:

```diff
-	if ! blkid -o value -s TYPE "$PARTITION" >/dev/null 2>&1; then
+	if ! blkid "$PARTITION" 2>/dev/null | grep -q 'TYPE="'; then
```
