Executive Summary ¶

The PR cleanly consolidates external-driver config-filling into Configure and makes the gRPC server persistent per-instance. Two regressions block merge: moving default-filling out of ResolveVMType leaves MountType nil for store.Inspect consumers, so limactl factory-reset panics on the default instance after deleting its files (C1); and a create failure orphans the spawned driver server (I1). The rest are robustness and UX suggestions.

All three reviewers agreed the refactor is sound and builds/tests green. Codex alone caught the crash-class C1; Gemini alone caught the Windows signal regression (I2); Claude gave the sharpest account of I1. The three findings barely overlap, so each reviewer carried real weight.

I2. server.Stop never kills processes on Windows Gemini¶
pkg/driver/external/server/server.go

On Windows, os.Process.Signal supports only os.Kill; every other signal — including Signal(0) and SIGTERM — returns an error. The liveness pre-check therefore always fails, the loop removes the PID file and continues, and neither the graceful SIGTERM nor the force SIGKILL branch runs. External-driver processes are never stopped, and their PID files vanish. StopForcibly previously used the cross-platform osutil.SysKill, so this regresses Windows cleanup for external drivers.

Fix: signal and probe liveness through osutil.SysKill / a Windows-aware helper instead of raw proc.Signal.

S1. ResolveVMType failure is now fatal in prune/template scans Claude¶

Previously these logged a warning and continued; now they return the error. ResolveVMType (pkg/driverutil/vm.go:25) errors only when VMType names a driver absent from both limatype.VMTypes and the registry. So one template pinning an uninstalled external driver aborts the whole limactl prune or template-validation scan. Built-in types are unaffected. Keep the non-fatal behavior for multi-item scans, or confirm the stricter behavior is intended.

S4. Registry singleton mutation leaks clients across instances Gemini¶

CreateConfiguredDriver overwrites extDriver.Client on the shared registry.ExternalDriver. A command that processes several instances leaves earlier clients unclosed; Disconnect then closes only the last. Return an instance-scoped client instead of mutating the global.

S5. Stop can signal a reused PID or orphan a socket Codex¶

A stale PID file can outlive its process; the SIGTERM→SIGKILL escalation (10s window) may then hit a recycled PID. Conversely, a live socket with no PID file is unlinked without stopping its server. Verify process identity before signaling, and unlink a socket only once its process has exited. Low likelihood on a single host, and the stale-PID pattern predates this PR.

S6. create rollback can delete a concurrently created instance Codex¶

The existence check (line 43) and MkdirAll (line 66) do not atomically claim instDir. Two concurrent create calls for the same name can both pass the check; if the second fails, its os.RemoveAll deletes the first's instance. Claim the directory with os.Mkdir and install the rollback only after a successful claim.

Design Observations ¶

Concerns

  • No reaper for short-lived CLI callers (in-scope) Claude Codex — the root of C1 and I1. Removing the idle timer means any CLI command that spawns a server but never calls server.Stop (create on success, snapshot on a stopped instance) leaves an idle server running until a later start/stop/delete. Consider a bounded idle backstop, or have non-hostagent callers stop the server they spawn.
  • Keep config normalization side-effect-free (in-scope) Codex — C1 stems from merging default-filling into runtime Configure. A pure "fill defaults + validate" layer, shared by store.Inspect, template validation, factory-reset, and startup, would let every consumer normalize without spawning a server or mutating driver state.
  • isServerRunning infers health from a successful dial (in-scope) Gemini — a shutting-down or hung server whose socket still accepts connections is treated as ready.

Strengths

  • The Configure gRPC round-trip — the server marshals the filled instance back (server/methods.go:82-89) and the client unmarshals it (client/methods.go:309) — cleanly propagates driver defaults and keeps in-tree and external drivers symmetric. Claude Codex
  • Socket-file polling with a procExit channel (server.go:223-262) replaces the fragile stdout handshake and distinguishes "died early" from "timed out." Claude
  • Splitting Disconnect from Stop, moving the socket into the instance directory, and rejecting non-positive PIDs before signaling (server.go:281) are all sound. Claude Codex

Review Process Notes ¶

Skill improvements

  • When a diff changes what a shared load, resolve, or normalization function fills into a config or struct — for example moving default-population out of a load/resolve path into a later runtime step — enumerate every consumer of the earlier path and check each pointer-field dereference. A field a consumer previously received filled may now be nil, turning a *field deref into a panic. Flag any consumer that dereferences a pointer field the function no longer populates, paying special attention to consumers outside the diff, because the failing deref and the changed fill often live in different files.
  • In cross-platform Go, flag os.Process.Signal (or proc.Signal) called with any signal other than os.Kill. On Windows only os.Kill is delivered; a Signal(0) liveness probe and SIGTERM/SIGINT return an error, so signal-based liveness checks and graceful-termination loops silently no-op there. Require a cross-platform kill/liveness helper for any process-management code that must run on Windows, and treat a swap away from such a helper toward raw syscall signals as a portability regression.

Repo context updates

  • [repo] Driver-specific config defaults (MountType, and other fields the driver selects) are filled only inside Driver.Configure (formerly FillConfig). LoadYAMLByFilePath / store.Inspect fill general defaults via limayaml.FillDefault but not driver-specific ones, and the built-in default (pkg/limayaml/default.yaml) sets mountType: null. Any consumer of a store.Inspect config that dereferences MountType — or another driver-defaulted pointer field — must nil-guard it or run Configure first. When reviewing a change that moves or removes driver default-filling, check cidata.GenerateCloudConfig callers and other store.Inspect consumers for unguarded derefs.
