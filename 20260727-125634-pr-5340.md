## Review Process Notes

### Skill improvements

- **Re-verify a decline whose reason is a claim about code nobody opened.** When a
  prior round declined a finding on the grounds that some helper, library, or
  subsystem "would never" produce the triggering value, open that code and confirm
  the guarantee exists. A decline resting on an assumed invariant is weaker than one
  resting on a measured one, and the assumption survives every later round unchecked
  because it sits in the resolution table rather than in the findings list.
- **Distrust an agent's citation of a CI log for a run still in progress.** Hosted CI
  APIs commonly refuse whole-run logs until every job finishes, so a claim to have
  read a specific job's output can be unreproducible even when the job itself has
  passed. Verify the underlying fact from the workflow definition and the job's
  status instead, and report it by that route.
- **Treat an agent whose limitations section mirrors the prompt's own decline list as
  unverified.** When a review restates injected context item for item and adds no
  measurement, its clean verdict carries no evidence. Say so in the retro rather than
  recording it as agreement, because several such agreements can otherwise look like
  convergence.

### Repo context updates

- **[repo] ADD**: `pkg/fsutil.WindowsSubsystemPathWithCygpath` returns
  `strings.TrimSpace(string(out)), nil` whenever `cygpath` exits 0, with no check
  that the output is non-empty and no separation of stdout from stderr
  (`CombinedOutput`). Any caller that treats a nil error as a guarantee of a usable
  path is relying on the subprocess behaving. Flag call sites that feed the result to
  a destructive operation without validating it.
- **[repo] ADD**: Lima's wsl2 driver never writes `/etc/wsl.conf`, so a wsl2 guest
  sees the host drives through WSL's default `/mnt/c` automount, and
  `cmd/limactl/shell.go` relies on that when it cd-s a wsl2 guest straight into the
  converted host path. Features that exist to isolate the guest from host files
  cannot work on wsl2 regardless of path handling.
- **[repo] UPDATE**: the Windows WSL2 CI job runs `go test -v ./...` on
  `windows-2025` before its integration step, so a `_test.go` file's table really
  executes on Windows. But `hack/test-templates.sh` never invokes `limactl shell
  --sync`, so no Windows job exercises that feature end to end.
