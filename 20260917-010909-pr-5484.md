## Executive Summary

This PR generalizes `pkg/networks` over the daemon name and adds the Linux
helper's command rendering, tap naming and sudoers wildcard. Argument injection
comes out clean: every interpolated value is either a `net.IP` or an identifier.
The helper path itself is the exception. It reaches a root command line with none
of the checks `validatePath` applies to every other path, and its "not installed"
case returns success. The maintainer already asked for that second fix twice.

I1. **`limaPrivilegedNetPath()` reports "not installed" as success, so `TapCmd` renders an empty program path** — `pkg/networks/config.go:195` [Claude Opus 5, Codex GPT 5.6 Sol, Gemini 3.1 Pro, Gemini 3.5 Flash]


`usrlocal.LibexecLima()` has a single return statement, `return candidates, nil`
(`pkg/usrlocal/usrlocal.go:216`), so `err` is never non-nil. The `err != nil` arm

I3. **`TapNamePattern`'s character ranges are locale-sensitive, and its comment claims an exactness it does not have** — `pkg/networks/commands.go:251` [Codex GPT 5.6 Sol, Claude Opus 5]

```go
// TapNamePattern is the sudoers wildcard matching exactly the names generated by
// TapName. Character classes are used instead of "*" because "*" would also
// match whitespace, which would allow smuggling extra arguments into the command.
func TapNamePattern() string {
	return tapPrefix + strings.Repeat("[0-9a-f]", tapDigits)
}
```

The second sentence is right and well founded. The first is wrong twice over. The
pattern authorises all 2³² names rather than the one `TapName` derives (see I7),
and `fnmatch` range expressions follow `LC_COLLATE`, so outside the C locale the
range also matches `A` and `é`. Two independent guards keep this closed:
`sudoers_locale` "Defaults to 'C'" (sudoers(5)), and `IsTapName` is case-
sensitive. So the security impact is nil and the comment is the defect.

I7. **Any sudoers-group member can pre-create another user's tap device** — `pkg/networks/commands.go:238` [Gemini 3.1 Pro, Codex GPT 5.6 Sol, Claude Opus 5]

```go
// of the hash because the bridges are shared between all users of the sudoers
// group, and a tap device may only ever be used by its owner.
func TapName(instName, netName string) string {
	sum := sha256.Sum256(fmt.Appendf(nil, "%d/%s/%s", os.Getuid(), instName, netName))
	return fmt.Sprintf("%s%x", tapPrefix, sum)[:len(tapPrefix)+tapDigits]
}
```

The comment presents the uid as a security property. It is namespace separation.
`TapName` is a pure public function of three guessable values, and
`TapNamePattern` authorises every result for the whole group, so a member can
compute a victim's name and create it first. `tapUp` then refuses the device to
its owner (`cmd/lima-privileged-net/network_linux.go:426`), blocking that
instance from starting. Ownership holds, availability does not.

## Suggestions

S1. **`limaPrivilegedNetPath` takes `dirs[0]` without checking the helper is in it** — `pkg/networks/config.go:198` [Claude Opus 5, Codex GPT 5.6 Sol]

Every other consumer of these directories iterates the whole list and picks the
one that contains the file: see `pkg/plugins/plugins.go:61`,
`pkg/registry/registry.go:122`, and `usrlocal.GuestAgentBinary` itself
(`pkg/usrlocal/usrlocal.go:141`). Taking the first entry means a prefix whose
`libexec/lima` exists but has no `privileged/` shadows a later prefix that does
have the helper.

Fix: iterate `dirs` and return the first that contains an executable helper,
folding the I1 error into the same "none found" branch.

S2. **`StartCmd` and `TapCmd` re-resolve the path instead of calling `c.DaemonPath`** — `pkg/networks/commands.go:184` [Claude Opus 5]

`DaemonPath` already maps `LimaPrivilegedNet` to `limaPrivilegedNetPath()` at
line 82, and both call sites have `daemon` in hand. Going straight to the
package-level helper duplicates the mapping.

Fix: use `c.DaemonPath(daemon)` in both. The I1 fix then lands in one place.

S3. **Address arguments render for every non-bridged mode, unlike the socket_vmnet arm** — `pkg/networks/commands.go:189` [Claude Opus 5]

```go
		if nw.Mode != ModeBridged {
			cmd += fmt.Sprintf(" --gateway=%s --dhcp-end=%s --netmask=%s",
				nw.Gateway, nw.DHCPEnd, nw.NetMask)
		}
```

The socket_vmnet arm eleven lines above switches on `ModeHost, ModeShared`, so an
unrecognised mode renders no address arguments there. `Validate()` only checks

## Design Observations

### Concerns

- **`Config.Validate()` cannot succeed on Linux yet (in-scope for the series).**
  Every value this PR interpolates into a root command line is safe *because*
  `identifiers.Validate` constrains it to `[A-Za-z0-9]+([._-][A-Za-z0-9]+)*`,
  which admits no whitespace and no sudoers or `fnmatch` metacharacter. But
  `validatePath` returns `errors.New("vmnet code must not be called on
  non-Darwin")` at `validate.go:174` for any non-empty `Paths` entry, and the
  shared template always sets `socketVMNet` and `varRun`. So `Validate()` errors
  out on every Linux host today, and the identifier checks plus the Linux
  bridge-length check at `validate.go:42` are unreachable on the platform they
  were written for. #5485 has to port that gate. [Claude Opus 5]
- **The digest invalidates the sudoers file on every lima upgrade (future).**
  Today only a socket_vmnet upgrade forces a regeneration, and `sudoers.go:117`
  already reports that as "out of sync and must be regenerated". Pinning the
  helper's own bytes extends that to every lima release. Worth deciding
  deliberately rather than discovering it in a bug report. [Gemini 3.1 Pro]
- **One string serves two grammars (in-scope).** `StartCmd` and `TapCmd` produce
  a single string that is both split into argv by `reconcile` and embedded in
  sudoers. A typed specification holding a path plus an argument slice, with
  separate renderers for the two consumers, would put validation in one place and
  remove the whitespace coupling behind I2. [Codex GPT 5.6 Sol]
- **The helper path varies with how limactl was invoked (in-scope for #5485).**
  `SelfDirs()` starts from `exec.LookPath(os.Args[0])`. Since `VerifySudoAccess`
  compares the whole generated text against the installed file, a user whose
  limactl resolves through a different prefix gets "out of sync" rather than a
  working network. [Claude Opus 5]

### Strengths

- Character classes instead of `*` is the right call, and the comment's reasoning
  matches sudoers(5): command arguments are matched as one concatenated string,
  so `*` crosses word boundaries. [Claude Opus 5, Codex GPT 5.6 Sol, Gemini 3.1 Pro, Gemini 3.5 Flash]
- `tapPrefix`, `tapDigits` and `IsTapName` are shared between the rendering side
  and the root-side helper, so the name the sudoers rule permits and the name the
  helper accepts cannot drift. [Claude Opus 5]
- `tapUp` checks the existing device's owner before reusing it, so a collision,
  deliberate or accidental, fails closed instead of transferring a tap.
  [Codex GPT 5.6 Sol, Gemini 3.5 Flash]
- Adding a `Digest_Spec` at all is real hardening over the ownership-check-only
  model, I4's comment notwithstanding. [Claude Opus 5]

## Review Process Notes

### Skill improvements

- When a finding's severity depends on a mechanism that a companion PR
  introduces, state which of the two outcomes the mechanism produces before
  assigning the severity. A defect that renders an invalid privileged command and
  one that renders a valid but wrong one read identically in a diff, and they
  differ by an order of magnitude in consequence.
- Before crediting a wildcard, glob, or character class in a generated
  configuration file as a safety property, identify which library evaluates it at
  runtime and whether its behaviour depends on locale, case folding, or path
  separators. A pattern that is exact under the C locale is not exact under every
  locale, and the tool's own default is what settles it.
- When a test guards itself with a runtime capability check, run the suite and
  confirm the guarded body executes before crediting it as coverage. A test that
  skips on every platform reads as coverage in a diff and in a coverage summary.

### Repo context updates

- [repo] `usrlocal.LibexecLima()` never returns a non-nil error; its only return
  statement is `return candidates, nil`. A caller that writes `if err != nil ||
  len(dirs) == 0 { return "", err }` therefore reports "not found" as success.
  Flag that shape wherever it appears.
- [repo] `pkg/networks/validate.go` applies its path safety checks (absolute, no
  whitespace, no symlink, root-owned, not group-writable) only to fields of the
  `Paths` struct. Any other path that reaches a sudoers file or a `sudo` command
  line gets none of them. The file-level comment in `commands.go` states the
  no-whitespace invariant as though it were global.
- [repo] `pkg/networks/reconcile/reconcile.go` splits the rendered command string
  on a single space before handing it to `sudo`, so whitespace anywhere in an
  interpolated value shifts every later argument.
- [repo] REMOVE nothing from `deep-review-context.md` this round; no entry was
  contradicted by the code under review.

- I6 cites commit `2db0e593` rather than a file, because the finding is about the
  commit message. The citation lint accepts it, counting it among the six
  findings with no leading block; inventing a file reference would point the
