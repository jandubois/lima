Executive Summary ¶

PR #5405 sends the output of the three WSL2 guest-address probes in getSSHAddress through a validating helper, routableGuestIP, so a compromised guest can no longer hand ssh an option such as -oProxyCommand=…. The change is correct and CI is green, including the Windows WSL2 job. One Important finding survives: the helper promises a routable address but rejects only loopback, and a one-token switch to IsGlobalUnicast fixes it. Four suggestions cover the error message, test reach and stderr parsing.

Claude and Codex reached I1 independently, and three reviewers reported the error-message defect behind S1. The Design Observations put the PR's security claim in context. Lima leaves WSL's default interop on, so a compromised WSL2 guest can already start Windows programs as the user, and I'd read the PR as hardening plus a fix for a functional bug in the first two probes.

I1. routableGuestIP promises a routable address but rejects only loopback Claude Opus 5 Codex GPT 5.6 Sol¶
pkg/driver/wsl2/sshaddress.go
import (
	"net"
	"strings"
)

// routableGuestIP returns the trimmed output when it is a routable IP address,
// or "" otherwise. The output comes from a command run inside the WSL2 guest
// and becomes inst.SSHAddress, which is passed to ssh/scp/rsync as the
// destination argument; a non-address value such as "-oProxyCommand=..." would
// be interpreted by ssh as an option, so it is validated here. Loopback is
// rejected because some distributions report 127.0.1.1, which is not routable.
func routableGuestIP(out []byte) string {
	s := strings.TrimSpace(string(out))
	if ip := net.ParseIP(s); ip == nil || ip.IsLoopback() {
		return ""
	}
	return s
}

The comment and the name promise "" for anything but a routable address. Line 19 rejects only unparseable and loopback input, so 0.0.0.0, ::, link-local, multicast and broadcast addresses pass unchanged. The option-injection defense holds either way, since no parsed IP starts with -.

But each probe in getSSHAddress returns the first value the helper accepts (pkg/driver/wsl2/vm_windows.go:271), so a probe that reports one of these ends the search before a later probe can offer a reachable address.

Design Observations ¶

Concerns ¶

  • The security claim is narrower than the description suggests (in-scope) [Consolidator]. Microsoft's wsl.conf reference lists [interop] enabled and [automount] enabled as defaulting to true, the first deciding "whether WSL will support launching Windows processes". Lima writes no wsl.conf; a search for wsl.conf and interop under pkg/driver/wsl2, pkg/cidata, templates and hack finds nothing. So a compromised WSL2 guest can already start Windows programs and write under /mnt/c as the user. The injection also depends on the ssh client. OpenSSH 10.3 refused limactl shell's real script as a hostname ("hostname contains invalid characters") and ran an injected ProxyCommand only when the trailing argument had no spaces. I'd read the PR as hardening plus the functional fix listed under Strengths. I did not check whether the Finch rootfs that templates/experimental/wsl2.yaml downloads ships its own wsl.conf.
  • Put -- before the destination at every ssh call site (future) Claude Opus 5 Gemini 3.1 Pro. cmd/limactl/shell.go:483 and pkg/hostagent/requirements.go:192 place the address before --, and cmd/limactl/tunnel.go:112 and executeSSHForRsync (cmd/limactl/shell.go:761) pass none. Given ssh -p 22 -- "-oProxyCommand=…" true, OpenSSH 10.3 read the value as a hostname and refused it, while the same argv with the address before -- ran the ProxyCommand. That form protects every address source. Gemini's external-driver example overstates the need, since an external driver is already a host process.
  • The wsl2 driver reports two SSH addresses (future) Claude Opus 5. SSHAddress() returns a constant "127.0.0.1" (pkg/driver/wsl2/wsl_driver_windows.go:347-349) that the hostagent adopts after its dynamic re-query (pkg/hostagent/hostagent.go:437-443), while InspectStatus (pkg/driver/wsl2/wsl_driver_windows.go:215-218) stores the guest-reported address in inst.SSHAddress for limactl shell, copy and tunnel. Only that CLI path reads the value this PR validates. Commit 2bee694d ("Restore DynamicSSHAddress functionality for WSL2") switched InspectStatus from l.SSHAddress to getSSHAddress on purpose, and the hostagent comment "WSL instance SSH address isn't known until after VM start" no longer matches the constant. Find out why 2bee694d wanted the guest address before proposing loopback for the CLI.
  • IPv6 addresses break the scp and rsync destinations (future) Gemini 3.1 Pro Codex GPT 5.6 Sol. The helper accepts fd00::1, and its test says so, but pkg/copytool/scp.go:80, :82 and pkg/copytool/rsync.go:77, :177 build user@addr:path and scp://user@addr:port/path with no brackets. scp read user@fd00::1:/tmp/x as host fd00; only user@[fd00::1]:/tmp/x reached fd00::1. This predates the PR, and the fix belongs in the consumers.

Review Process Notes ¶

Skill improvements ¶

  • When a change justifies itself by closing a security or failure mechanism, test that mechanism at each call site the description names, and check whether the platform or its default configuration already gives the attacker the capability the change removes. An overstated motivation sets how urgently maintainers treat the change, and reviewers who take it on trust carry the overstatement into their severities. Report the gap in Commit Structure or Design Observations.

Repo context updates ¶

  • [repo] UPDATE "SSHAddress convention: in-tree drivers return loopback": the wsl2 driver's SSHAddress() returns "127.0.0.1", and the hostagent adopts it, but InspectStatus stores the guest-reported address in inst.SSHAddress, which limactl shell, limactl copy and limactl tunnel pass to ssh, scp and rsync. The loopback equivalence holds for the hostagent's own address only; treat wsl2's CLI-side inst.SSHAddress as guest-controlled input.
  • [repo] A WSL2 guest shares the Windows user's trust domain unless its wsl.conf says otherwise. Lima's wsl2 driver writes no wsl.conf, and WSL defaults [interop] enabled and [automount] enabled to true, so the guest can start Windows programs and write the host's drives under /mnt/c. Weigh any "compromised wsl2 guest reaches the host" finding against that before rating it, and check the template's rootfs for its own wsl.conf when the severity turns on it.
  • [repo] Judge an ssh option-injection claim by the shape of each call's argv. An injected -o… value runs only when a destination still follows it; passed as ssh's last argument, it leaves no destination and ssh prints its usage. OpenSSH 10.3 also refuses a command-line hostname containing spaces or shell metacharacters before connecting, so a leftover remote command becomes the destination only when it is a single word; older clients may not check. Placing -- before the destination makes the value a hostname in every case.
