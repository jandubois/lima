Executive Summary ¶

The PR moves tap-device naming into lima-privileged-net, which derives the name from SUDO_UID. It also validates the helper path and makes the command renderers testable on every host. But the new sudoers entry ends in a bare *, so a group member can put --bridge=docker0 ahead of the instance name and attach a tap they own to any host bridge. And the 32-bit name hash still lets one member block another's device after a one-minute search.

func sudoMatches(pattern, args string) bool {
	p, a := C.CString(pattern), C.CString(args)
	defer C.free(unsafe.Pointer(p))
	defer C.free(unsafe.Pointer(a))
	return C.fnmatch(p, a, 0) == 0
}

Review Process Notes ¶

Skill improvements ¶

  • Truncated hash as an ownership key: when a change relies on a hash to keep one principal from producing another principal's identifier (a device, socket, lock or cache name), count the bits left after truncation and estimate a preimage search at commodity hashing speed. An identifier squeezed into a short name limit rarely keeps enough, and putting the principal's own id in clear closes the gap by construction.

Repo context updates ¶

  • [repo] Generated sudoers command lines and the helper's parser form one contract: sudo matches a rule's arguments as one space-joined string with fnmatch, so * spans whitespace and matches flags. Every wildcard argument in a rule pkg/networks renders must follow a pinned --, or be a character class that excludes whitespace, and the privileged helper must reject surplus positional arguments. Flag a wildcard that cobra could parse as a flag, and check the renderer and the helper's flag setup together, since a diff often shows only one side.
