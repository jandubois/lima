## Important Issues

I1. **A symlinked `--sync` target clears the depth guard, and the sync-back deletes through it** — `cmd/limactl/shell.go:226` [Codex GPT 5.6 Sol]

```go
		hostCurrentDirNative, err = filepath.Abs(syncDirVal)
```

`filepath.Abs` resolves no symlinks, so line 252 scores the spelling the user
typed rather than the directory rsync acts on. A deep path that links to a
shallow one clears the threshold, and the copy tool appends a trailing slash
(`pkg/copytool/rsync.go:165-166`), which makes rsync follow the link.

I reproduced the deletion with openrsync on darwin: `rsync -a -r --delete --
guest/ link/`, where `link` points at a directory holding a host-only file,
exited 0 and removed that file. `askUserForRsyncBack` runs the same
`--delete` back onto `hostCurrentDir` without a prompt when stdout is not a
terminal (`shell.go:556-557`).

The merge-base measured the same unresolved string
(`acdea753:cmd/limactl/shell.go`), so this is pre-existing and belongs in its own
PR.

Fix: resolve the native path before measuring it. Codex proposed
`filepath.EvalSymlinks` at line 226, which also changes what gets synced and
fails on a missing path, so weigh both in the follow-up.

**Resolved:** Declined for this PR — pre-existing bug in untouched code, so it
belongs in its own PR under the one-commit-per-PR convention.

I2. **`--sync` on a WSL2 instance passes a path the host's rsync cannot resolve, after creating the guest directory** — `cmd/limactl/shell.go:432` [Claude Opus 5]

```go
		paths := []string{
			hostCurrentDir,
```

For a WSL2 instance `mountDirFromWindowsDir` returns `wslpath` output such as
`/mnt/c/Users/jan/proj` (`shell.go:790-793`). `parseCopyPaths` leaves that
string alone, because `filepath.IsAbs` is false for it on Windows
(`pkg/copytool/copytool.go:123-133`), and the rsync that receives it is the
host's (`pkg/copytool/rsync.go:24-27`), which resolves `/mnt/c` against the
MSYS2 root.

The guard now passes because it measures `C:\Users\jan\proj`, so the run reaches
rsync instead of stopping. By then `mkdir -p` has already created the destination
in the guest (`shell.go:417`), which the failure leaves behind.

WSL2 is experimental (`templates/experimental/wsl2.yaml`) and the failure is
loud, but `--sync` requires `--mount-none`, which is exactly what the error at
line 214 tells users to do. Reasoned from the code, not executed: no Windows
host was available.

Fix: refuse the combination beside the mounts check at line 213, or convert with
`cygpath` for the rsync argument regardless of VM type.

**Resolved:** Fixed by refusing the combination. Subagent verification then
caught that `website/content/en/docs/examples/ai.md` lists the `--sync`
preconditions and would have left a user hitting an undocumented fourth one, so
that list gained the matching entry.

## Suggestions

S1. **`pathDepth` counts a repeated separator as an extra component, so `\\server\\share` scores 4** — `cmd/limactl/shell.go:774-776` [Claude Opus 5, Codex GPT 5.6 Sol]

```go
	if strings.HasPrefix(slashed, "//") {
		slashed = slashed[1:]
	}
```

This answers the item round 1 left open. I measured 4 for `\\server\\share`
against 3 for `\\server\share`, and 4 for `\\\server\share`, so either spelling
of a share root would clear the minimum of 4.

Reachability rests entirely on `GetFullPathNameW`. Go's `Clean` does not collapse
the run: the stdlib's own Windows table asserts ``Clean("//abc//") == `\\abc\\` ``
(`path/filepath/path_test.go:110`), because `volumeNameLen` absorbs the second
separator into the volume. Microsoft documents normalization as collapsing
separator runs after the first two, so the string should never survive, but
nothing in the repo pins that and neither I nor any agent could execute it.

Collapsing inside the helper drops the dependency. Claude verified the collapse
keeps all 15 existing rows green.

```diff
 	if strings.HasPrefix(slashed, "//") {
 		slashed = slashed[1:]
 	}
+	for strings.Contains(slashed, "//") {
+		slashed = strings.ReplaceAll(slashed, "//", "/")
+	}
```

**Resolved:** Fixed, and generalised: the one collapse loop replaced both the
leading-separator strip and the inert `UNC/` rewrite (S4). Verification compared
the new helper against the old over 960,800 generated inputs and found the new
one never counts higher, so it cannot admit a path the old guard refused.

S2. **The `pathDepth` docstring miscounts a bare root and omits its input precondition** — `cmd/limactl/shell.go:759-761` [Claude Opus 5, Codex GPT 5.6 Sol, Gemini 3.5 Flash]

```go
// pathDepth counts the components of an absolute path, including the root. It
// accepts either separator, so a Windows path counts the same wherever this
// runs.
```

Counting components including the root gives `/` a depth of 1, but the function
returns 2, and `shell_test.go:26-27` pins that for both `/` and `C:\`. The
formula counts separator-delimited fields, which is why the root and a
first-level directory tie. Every value involved sits far below the threshold, so
nothing misbehaves; the sentence just describes a different function.

The docstring also carries no precondition, and S1 shows the count depends on
one: the caller passes `filepath.Abs` output, and a hand-built path with a
repeated separator counts differently.

Fix: say it counts separator-delimited fields of a normalized absolute path.

**Resolved:** Fixed, with one change from the proposal. Naming `filepath.Abs` as
the precondition would have contradicted the S1 collapse loop and read as licence
to delete it, so the docstring states the collapse as part of the contract
instead. Subagent verification raised that contradiction.

S3. **The commit body omits the Linux and macOS behaviour change that round 1's decline cited** — commit `3fac6f96` [Claude Opus 5]

Round 1 declined the Unix backslash finding because "the commit message discloses

The paragraph exists in the PR description alone. Since this repo squashes to one

Fix: move that paragraph into the commit body.

**Resolved:** Fixed. The commit body gained the disclosure paragraph plus one

S4. **The `UNC/` branch in `pathDepth` cannot change the result** — `cmd/limactl/shell.go:768-770` [Consolidator]

```go
		if rest, found := strings.CutPrefix(slashed, "UNC/"); found {
			slashed = "//" + rest
		}
```

The rewrite swaps the three characters `UNC` for nothing and `//` for `/` once
the next branch runs, so the slash count comes out identical either way. I
confirmed it over 10 inputs, including `\\?\UNC\server\share\proj`, the trailing
form, lowercase `unc`, and `\\.\UNC\`: every one scores the same with the branch
removed.

The comment above it and the test comment at `shell_test.go:35-36` both present
the branch as load-bearing, so a reader has to derive the equivalence to trust
the code. Keep it only as documentation of intent, and say that is what it is.

**Resolved:** Fixed by removing the branch, folded into the S1 collapse loop. An
exhaustive probe over 960,800 strings found zero inputs where its removal changes
the result, confirming the claim independently.

## Review Process Notes

### Skill improvements

- **Answer a prior round's open item with a measurement or say why you could not.**
  When an earlier round recorded an item as open because a fact could not be
  measured in that environment, treat re-establishing that fact as the round's
  first task, and prefer a language or library source that pins the behaviour over
  reasoning from documentation. Report the item as still open when neither is
  available, rather than promoting an expectation to a conclusion.
- **Check a decline's stated reason, not only its subject.** When a prior round
  declined a finding because some artifact documents the behaviour, open that
  artifact and confirm the documentation is there. A reason that was never true,
  or that a later edit removed, silently converts a reasoned decline into an
  undisclosed change.
- **Distrust a helper branch that normalizes one spelling into another.** When a
  function rewrites a prefix before measuring, check whether the rewrite can
  change the measurement at all. Prefix normalization that preserves the quantity
  being counted is a no-op the reader must still verify, and a comment asserting
  it matters makes the verification harder to skip.

### Repo context updates

- **[repo] ADD**: `limactl shell --sync` measures its depth guard on the path
  `filepath.Abs` returns, which resolves no symlinks, while rsync follows the link
  because the copy tool appends a trailing slash. Any guard that validates a host
  path before a recursive `--delete` must resolve symlinks first, or the string
  checked and the directory acted on differ.
- **[repo] ADD**: on Windows, path conversion for a WSL2 instance goes through
  `wslpath` and yields `/mnt/c/...`, while every other VM type goes through
  `cygpath` and yields the MSYS `/c/...` form. The host's rsync understands only
  the second. Flag any code path that hands a converted path to a host-side tool
  without branching on VM type.
