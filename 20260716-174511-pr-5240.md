## Important Issues

I1. **`validateGitHubRedirect` org containment falls to the same `../` traversal this PR closes** — `pkg/limatmpl/github.go:214` [Claude Opus 4.8]

```go
	if !strings.HasPrefix(redirect, "github:"+org+"/") {
		return "", fmt.Errorf("redirect %#q is not a `github:%s` URL (from %#q)", redirect, org, url)
	}
```

The check is prefix-only, so a redirect body `github:ORG/../../otherorg/otherrepo/master/evil.yaml` satisfies it and the `@` check below it. `TransformCustomURL` re-feeds the returned locator to `transformGitHubURL` (`locator.go:401`), where `repo` becomes `..` and `filePath` keeps its leading `../`. The rebuilt URL then cancels the org segment server-side.

Verified against live GitHub: `https://raw.githubusercontent.com/lima-vm/../main/../torvalds/linux/master/README` returns **307** to `torvalds/linux/master/README`. Reaching it needs `repo == org` and an explicit `@branch` — without one, the default-branch lookup for `repo=".."` 404s and fails closed. This is pre-existing, not a regression, but it is the same bug class in the path the PR description credits as safe, and it escapes the org entirely rather than just the repo.

Fix: hoist the predicate to the parse boundary where `filePath` is derived, covering user input, redirect re-entry, and symlink resolution at once. Reject `..` in `repo` too, since it is interpolated into the URL unvalidated.

```go
func escapesRepo(p string) bool {
	p = path.Clean(p)
	return p == ".." || strings.HasPrefix(p, "../")
}
```

## Design Observations

**Concerns**

- **Containment guards one of the three places `filePath` is set** *(in-scope)* [Claude Opus 4.8]. `filePath` reaches `githubUserContentURL` from user input (`github.go:42`), redirect re-entry through the `TransformCustomURL` loop (`locator.go:401`), and symlink resolution (`github.go:172`). Only the third is guarded, which is exactly how I1 survives. Asserting the invariant once at the parse boundary covers all three and forecloses the class rather than this instance.
- **The URL builder trusts every component it interpolates** *(future)* [Codex GPT 5.5]. `githubUserContentURL` formats `org`, `repo`, `branch`, and `filePath` straight into a URL with no escaping or segment validation. Today the server's own normalization contains the encoded variants, so this is latent rather than live — but it is why a single unguarded producer becomes an escape.

**Strengths**

- **The check sits after `path.Join`, not before** *(in-scope)* [Claude Opus 4.8]. Testing the cleaned result rather than pattern-matching `..` in the raw target avoids both classic errors: rejecting a legitimate `..foo.yaml` and missing `a/../../b`. Because `path.Clean` leaves surviving `..` only at the front, the `..`-or-`../`-prefix test is complete.
- **`path`, not `filepath`** *(in-scope)* [Claude Opus 4.8]. These are URL paths. `filepath` would treat `\` as a separator on Windows and make containment host-OS-dependent.
- **Encoded traversal is genuinely covered, not merely missed** *(in-scope)* [Claude Opus 4.8]. `path.Clean` does not decode percent-escapes and Go preserves them on the wire, which reads as a bypass on paper. It is not one — see the Reconciliation note.

## Review Process Notes

### Skill improvements

- When a finding's evidence is an observed behavior — an HTTP status, an exit
  code, a log line — confirm the observation demonstrates the consequence you
  claim rather than a precondition of it. A probe showing that a system decodes,
  parses, or accepts hostile input proves only that much; it does not prove the
  input crosses a trust boundary. Name the boundary in the finding and test an
  input that crosses it. If the crossing test does not reproduce, there is no
  finding. Systems routinely contain hostile input at a layer the probe never
  reached, so the gap between "it parsed my input" and "it acted on my input"
  is where false positives live.

- When a change adds a containment or validation check and its rationale credits
  an adjacent code path with already enforcing the same property, test that
  credit against the adjacent path before accepting it. A reviewer inherits the
  author's framing, and an unexamined premise in the rationale is where the
  remaining instance of the bug class usually survives. Where sibling paths
  enforce one property by different mechanisms — a prefix or substring test in
  one, a canonicalizing check in the other — treat the weaker mechanism as the
  finding.

### Repo context updates

- [repo] `github:` template locators build raw.githubusercontent.com URLs by
  interpolating org, repo, branch, and path into a format string with no
  escaping. raw.githubusercontent.com normalizes literal `../` before routing
  and answers with a 307 to the collapsed path, so a `../` climbing above the
  repo root reaches an unrelated repository. It does not treat percent-encoded
  traversal (`%2e%2e`, `..%2f`) as a routing separator: those requests reach the
  original repo and 404. Containment checks on these paths need only reject
  literal `..` segments. Treat a claim that percent-encoding defeats such a check
  as a false positive unless it comes with a request that demonstrably leaves the
  repository.

- [repo] `TransformCustomURL` re-feeds each transformed locator through the
  transform loop until it stops changing, so any `github:` URL a resolver returns
  is re-parsed from scratch. Validation applied to one producer of the path does
  not bind the others, and the loop's re-entry point is the choke point that does.
