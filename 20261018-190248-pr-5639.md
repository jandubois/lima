## Important Issues

I1. **An `ssh` wrapper on PATH that does not `exec` leaves the master never ready and `terminate` blocked forever** — `pkg/hostagent/sshmaster.go:236-240` [Claude Opus 5.5]

```go
			if pid != cmd.Process.Pid {
				// Our ssh found the socket taken and runs as a plain connection.
				logrus.Warnf("The SSH control socket is held by a master (pid %d) that the host agent did not start; replacing it", pid)
				_ = cmd.Process.Kill()

```

The master is the first `ssh` on PATH, since sshocker's `SSHConfig.Binary()` returns the bare name. For a wrapper script that runs the real ssh as a child, `ssh -O check` reports the child's pid, so this check kills only the wrapper, twice a second. The orphaned ssh holds the stderr pipe open, so `cmd.Wait` (line 212) and `markReady` never run. No forward is replayed, and the essential requirement fails after 10 minutes.

`terminate`'s fallback kill (line 372) also reaches only the wrapper, so `<-m.done` (line 375) blocks forever. `close()` never reaches `driver.Stop`, and `limactl stop` gives up after 3 min 10 s with the VM still running. At the merge-base, ControlPersist detached the master with `daemon(1, 1)` (`ssh.c:1889`), out of the wrapper's way.

+func setOwnProcessGroup(cmd *exec.Cmd) {
+	cmd.SysProcAttr = &syscall.SysProcAttr{Setpgid: true}
+}
+
+// signalProcessGroup sends sig to the process group that cmd leads.
+func signalProcessGroup(cmd *exec.Cmd, sig syscall.Signal) error {
+	if err := syscall.Kill(-cmd.Process.Pid, sig); err != nil && !errors.Is(err, syscall.ESRCH) {
+		return err
+	}
+	return nil

+func inProcessGroup(cmd *exec.Cmd, pid int) bool {
+	pgid, err := syscall.Getpgid(pid)
+	return err == nil && pgid == cmd.Process.Pid
+}

S10's fix dropped the `isReady()` guard on each tick and stopped the ticker instead, so correctness now depends on this line. Without it, every 500 ms tick calls `markReady`, which starts a new generation and replays every forward. The suite stays green with it deleted.

If `control` loses its timeout, `exitForeignMaster` waits on a hung foreign master with no limit. If the 60 s readiness kill goes (S4), a master hung in authentication polls forever. Each fails by hanging or flapping with timing, so the tests are required.

## Review Process Notes

### Skill improvements

- When code starts a program by its bare name from PATH and then identifies, signals or waits on it by pid, picture a wrapper script that runs the real program as a child. The pid that the program reports then differs, a kill reaches only the wrapper, and a pipe that the child inherited keeps `Wait` from returning.
- When a fix removes a guard because another change made it unreachable, correctness now depends on that other change; ask for the test that fails when it is deleted.

### Repo context updates

- The host agent runs every ssh that it starts (the master, `-O` requests, requirement scripts, forwards) by the bare name `ssh` through PATH, because sshocker's `SSHConfig.Binary()` returns `"ssh"`. The `SSH` environment variable reaches only limactl's own commands. Judge any claim about which ssh the host agent runs from that.
- Correct the pending entry on `O_NONBLOCK`: SIGTERM clears the flag as `-O exit` does, because `client_loop` frees every channel before it exits. A keepalive timeout or SIGKILL leaves it set.
