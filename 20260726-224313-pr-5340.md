## Executive Summary

The depth computation and its unit test are correct, and measuring the native
path is the right fix. But the old guard was also the only thing that aborted
`--sync` when the Windows path conversion failed. Reading a different variable
removes that abort, and the empty path left behind becomes `/` in the rsync
argv. Three pre-existing Windows path bugs become reachable once `--sync` works
on Windows at all.

All four reviewers converged on the conversion-failure regression. Codex and
Claude independently traced it into `pkg/copytool`, and I confirmed the
mechanism plus a missing confirmation prompt neither of them mentioned. The
remaining Important findings are pre-existing gaps, so each belongs in its own
follow-up PR.

## Critical Issues

C1. **`--sync` continues after a failed Windows path conversion, and rsync receives `/`** — `cmd/limactl/shell.go:237-240` [Claude Opus 5, Codex GPT 5.6 Sol, Gemini 3.5 Flash]

```go
	if err != nil {
		changeDirCmd = "false"
		logrus.WithError(err).Warn("failed to get the current directory")
	}
```

`mountDirFromWindowsDir` returns `("", err)` on every failure path, and this
block only warns. The depth guard used to catch the empty value, because it
read `hostCurrentDir`, scored 1, and returned at line 250. Line 249 now reads
`hostCurrentDirNative`, a valid deep path, so execution continues.

The trailing-slash loop at `pkg/copytool/rsync.go:166` then appends `/` to the
empty local path, and `parseCopyPaths` returns `[]*Path`, so the mutation
sticks. With `--delete` from line 436 and `-q` from `rsync.go:101`, the upload
becomes `rsync -a -q -r --delete -- / user@…:/home/<user>/`.

`--tty` defaults to whether stdout is a terminal (`cmd/limactl/main.go:127`),
so under automation `askUserForRsyncBack` calls `rsyncBack()` with no prompt
and `--delete` pointed at the host root. Only a failure of the upload stops it.

Fix: make the error fatal when the user asked for `--sync`.

```diff
 	if err != nil {
+		if syncHostWorkdir {
+			return fmt.Errorf("failed to determine the host directory to sync: %w", err)
+		}
 		changeDirCmd = "false"
 		logrus.WithError(err).Warn("failed to get the current directory")
 	}
```

**Resolved:** Fixed as proposed. `--sync` now returns the error instead of
warning and continuing. Declined a further guard on `hostCurrentDir == ""` with
`err == nil`: no reachable case exists, since a conversion helper returning
success with an empty path would be a bug in that helper.

## Important Issues

I1. **`pathDepth` treats `\` as a separator everywhere, so a UNC share root clears the guard** — `cmd/limactl/shell.go:759` [Codex GPT 5.6 Sol, Claude Opus 5]

```go
func pathDepth(path string) int {
	return strings.Count(strings.ReplaceAll(path, `\`, "/"), "/") + 1
}
```

A UNC volume root reaches 4 here: `\\server\share` becomes `//server/share`,
which holds three separators. `rsyncMinimumSrcDirDepth` is 4 (line 82), so the
root of a network share clears a guard meant to refuse near-root directories,
while the local `C:\` scores 2 and is refused.

On Linux and macOS a backslash is a legal filename character, so `/tmp/a\b`
counts 4 where the old formula counted 3. The commit message scopes its
no-change claim to paths without a backslash, so that half is disclosed, and it
only loosens the guard.

Codex proposed keying the fix on `filepath.VolumeName` and `os.PathSeparator`,
which would make the helper platform-dependent and stop the Windows cases from
running on the Linux and macOS unit-test jobs. Collapsing the leading separator
run keeps the helper portable.

Fix:

```diff
 func pathDepth(path string) int {
-	return strings.Count(strings.ReplaceAll(path, `\`, "/"), "/") + 1
+	// A UNC prefix (\\server\share) is one root, not two components.
+	slashed := "/" + strings.TrimLeft(strings.ReplaceAll(path, `\`, "/"), "/")
+	return strings.Count(slashed, "/") + 1
 }
```

**Resolved:** Fixed, and widened during verification. Beyond the leading
separator run, `pathDepth` now strips extended-length and device prefixes
(`\\?\C:\`, `\\.\C:\`, `\\?\UNC\server\share`) and normalises a root's trailing
separator, without which `\\server\share\` still counted 4 while
`\\server\share` counted 3. Eight rows were added to `TestPathDepth`, which
closes Testing Gap #3. The Unix backslash-in-filename half was declined: it only
loosens a foot-gun guard and the commit message discloses it. `\??\` and
`\\?\GLOBALROOT\` prefixes remain unstripped, since a conversion error catches
them downstream.

I2. **`askUserForRsyncBack` applies host `filepath` semantics to the converted guest path** — `cmd/limactl/shell.go:525-526` [Gemini 3.5 Flash, Claude Opus 5]

```go
	clean := filepath.Clean(hostCurrentDir)
	dirForCleanup := shellescape.Quote(filepath.Join(*inst.Config.User.Home, clean))
```

On Windows `hostCurrentDir` carries the `/c/...` form, and `filepath.Clean`
rewrites it to `\c\Users\jan\proj`. The `filepath.Join` then builds
`\home\<user>\c\Users\jan\proj`, which the `rm -rf` at line 548 cannot match, so
the guest workdir leaks after every sync-back. Line 265 already computes the
right guest path by plain concatenation.

`filepath.Dir(hostCurrentDir)` at line 557 shares the problem. It hands
`\c\Users\jan` to `getRsyncStats` as a local rsync destination, so the change
counts in the confirmation prompt describe a directory that does not exist.

This code is pre-existing and untouched by the PR. But `--sync` never ran on
Windows before, so this is the first release where anyone can reach it.

Fix: use the `path` package for guest paths and `hostCurrentDirNative` for
host-filesystem calls.

**Resolved:** Declined for this PR — pre-existing bug in untouched code, so it
belongs in its own PR under the one-commit-per-PR convention. Verification
confirmed the mechanism and found that `filepath.Dir(hostCurrentDir)` at
`shell.go:557` degrades the change preview on Windows the same way. Both should
land together in the follow-up.

I3. **`mountsContainPath` receives the converted path and never matches on Windows** — `cmd/limactl/shell.go:279` [Gemini 3.1 Pro]

```go
	case mountsContainPath(inst.Config.Mounts, hostCurrentDir) || inst.VMType == limatype.WSL2:
```

`mount.Location` keeps the native host form on Windows
(`pkg/limayaml/defaults.go:716`); only `MountPoint` gets converted to the
`/c/...` form (lines 730-737). So this compares `/c/Users/jan` against
`C:\Users\jan` and always fails, and `hostHomeDir` at line 286 fails the same

This PR creates the variable the fix needs. Passing `hostCurrentDirNative` to
`mountsContainPath` while keeping `hostCurrentDir` for the guest `cd` restores
the match, because the defaulted `MountPoint` is the `/c/...` form. An explicit
`mountPoint:` in the YAML still breaks the `cd`, which is a separate bug.

Fix: pass the native paths to `mountsContainPath`, in a follow-up PR.

**Resolved:** Declined for this PR — pre-existing bug on a different code path
than `--sync`, so it belongs in its own PR.

## Review Process Notes

### Skill improvements

- **Verify a proposed fix, not only the finding.** Before repeating an agent's
  patch in the consolidated report, check it against properties the current
  implementation deliberately holds: platform independence, an invariant a test
  depends on, an ordering another caller assumes. A correct diagnosis often
  arrives with a patch that trades one defect for another, and a patch quoted in
  a review carries the report's authority.
- **Ask whether a test pins the fix, not only the computation.** When a change
  fixes a bug by applying an existing computation to a different input, check
  whether any test would fail if the input were swapped back. A table-driven
  test of the computation proves the formula and pins nothing about where it is
  applied. Report that as a coverage gap even when the added test is otherwise
  well built.

### Repo context updates

- **[repo] UPDATE** the "Native vs converted host paths on Windows" entry: it
  names `pkg/ioutilx.WindowsSubsystemPath`, but the symbol lives in
  `pkg/fsutil`. `pkg/ioutilx` still exists and holds unrelated helpers, so the
  stale name resolves to a real package and reads as correct.
- **[repo] REMOVE** the "GitHub Actions PATH on Windows runners" entry. It
  describes a composite action that is not on master, and repo context should
  state the merged default-branch reality.
- **[repo] ADD**: `--tty` is a persistent root flag defaulting to whether stdout
  is a terminal, and `--yes` forces it false. Any confirmation prompt is
  therefore skipped under automation. When a destructive operation is gated only
  on a prompt, treat it as ungated and judge severity on the unattended path.
- **[repo] ADD**: guest-side paths in `cmd/limactl` must be built with the `path`
  package, never `path/filepath`. On a Windows host `filepath.Clean`, `Join`,
  and `Dir` emit backslashes, and a guest command receives a path the Linux side
  cannot resolve. Flag any `filepath` call whose result crosses into a guest
  command or an rsync remote path.
