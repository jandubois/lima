## Executive Summary

The PR wires the merged `lima-privileged-net` helper into reconcile, the QEMU driver and validation, adds a Linux CI job, and documents the Linux networks. The CI job passes without running its network checks, because `test-templates.sh` reads the network from the template, not from `LIMACTL_CREATE_ARGS`. A stop followed at once by a start can race the old helper's teardown. And the new page misstates what the firewall zones expose, when `ip_forward` is restored, and how long the helper runs as root.

I2. **`limactl stop` returns before the helper has torn the network down** — `cmd/lima-privileged-net/network_linux.go:124` [Codex GPT 6 Astra, Claude Opus 5.5, Gemini 3.5 Flash]

```go
	<-sig
	logrus.Infof("Shutting down the network on bridge %#q", c.bridge)
	return errors.Join(os.Remove(c.pidFile), stopDnsmasq(dnsmasq), c.down(downCtx))
```

Go evaluates the arguments of `errors.Join` from left to right, so the helper removes its PID file before it stops dnsmasq and runs `down()`. `stopNetwork` stops waiting once the PID file is gone (`reconcile.go:473-485`), so a `limactl start` right after `limactl stop` starts a second helper while the first is still tearing down. The new helper's `up()` finds the bridge and rules still present and skips them (`iptablesRules` checks with `-C`); the old one then deletes them, and the guest loses its bridge. `limactl restart` keeps the network up (`pkg/instance/restart.go:31`). The ordering came with #5483; this PR puts the helper behind `stopNetwork`. The probe blocks a stub `down()`; no Linux host ran the race.

## Design Observations

### Concerns

- **Concurrent starts can launch two helpers for one network** (future) [Claude Opus 5.5]: nothing serializes `Reconcile`, so two `limactl start` runs can both miss the PID file and both start the helper. The second overwrites the PID file, and `pkill -F` then reaches only one of them, leaving the other running as root. A per-network lock in `_networks` around `startNetwork` and `stopNetwork` would close this.
- **Every `LIMA_HOME` and every user shares one helper per network** (future): the PID file is in the global `/run/lima`, but `Reconcile` counts only its own `LIMA_HOME`'s instances. When the last instance of one `LIMA_HOME` stops, it kills the helper, and `down()` deletes every Lima tap on the bridge, including those of instances still running under another `LIMA_HOME` or user. socket_vmnet shares its daemon the same way on macOS, where those instances lose their socket instead.

### Strengths

- **Tap names agree everywhere** (in-scope) [Codex GPT 6 Astra, Claude Opus 5.5]: `qemu.go:929`, `reconcile.go:256` and the helper's `network_linux.go:423` all call `TapName(uid, instance, network)`, and `ensureTaps` passes `TapCmd` its arguments in the declared order.
- **`startNetwork` and `stopNetwork` loop over `RequiredDaemons()`** (in-scope) [Claude Opus 5.5, Gemini 3.5 Flash]: the hard-coded socket_vmnet list and its install check moved into that loop.
- **QEMU opens its tap without privileges** (in-scope) [Codex GPT 6 Astra]: `script=no` with a tap that the user owns does not add a privileged path to the driver.
