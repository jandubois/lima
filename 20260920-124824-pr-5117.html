Concerns ¶

pkg/limayaml now links the privileged helper implementation (in-scope) Claude Opus 5. pkg/limayaml/validate.go imports pkg/blockdevice for two pure-string helpers, but on darwin that package also carries the sudo invocation, the SCM_RIGHTS protocol and the getattrlist ACL probe. I measured it: go list -deps ./pkg/limayaml on darwin now includes github.com/balajiv113/fd, the merge-base validate.go had no blockdevice import at all, and the edge is absent under GOOS=linux. Every darwin binary that validates a lima.yaml, including lima-driver-qemu and limactl-mcp, now links that code. Moving path.go into a leaf package would answer this and the dependency half of round-5 S13, which the decline did not address.

Nothing refuses the host's boot disk (future) Claude Opus 5. disk.md:148 warns against granting it, and that sentence is the only guard. A first cut would compare the requested whole-disk name against the device behind statfs("/"), refusing rather than allowing when APFS synthesis makes the comparison ambiguous.

--block-device can only add, never remove (future) Claude Opus 5. cmd/limactl/editflags/editflags.go:379 emits .blockDevices += [...] | .blockDevices |= unique, and cmd/limactl/start.go:301 applies edit flags to existing instances. So limactl start foo --block-device=/dev/disk4 followed by --block-device=/dev/rdisk4 now fails the new overlap check with no CLI way to drop the first entry. Block-device grants stay per-user inside a file every user rewrites (in-scope) [carried from round 5]. Round 6 answered the documentation half (S3 of round 5), and disk.md:131-134 now states the limit plainly. The model itself is unchanged and remains the author's decision.

Strengths ¶

  • The fd handoff authenticates in both directions at the right moments Claude Opus 5. The helper checks the listener's uid before sending the caller-supplied nonce (block_device_darwin.go:108-113), and the receiver checks peer uid, nonce, device type and Rdev before accepting the descriptor (:633-668).
  • retainedFileDescriptors.CloseAll is idempotent and every failure path calls it Claude Opus 5. That is what releases the whole-disk flock even when the sendErrCh send blocks forever.
  • The ACL check is neither vacuous nor a false-positive trap Claude Opus 5. Replicating pathHasExtendedSecurityACL over /, /usr, /usr/local, /opt, /private, /System and /Applications reports no ACL, while ~/Desktop, which carries a stock ACL, reports one.
  • TestContainsActiveFragmentLineContinuations checks the sudoers logic against real visudo Claude Opus 5, an oracle independent of the code under test. It is the strongest test in the PR.
  • Whole-disk locking normalizes raw/block aliases and partitions correctly Codex GPT 5.6 Sol Gemini 3.1 Pro Gemini 3.5 Flash.
  • Both round-6 regression tests fail when their fix is reverted (verified during consolidation; see Testing Assessment).

Review Process Notes ¶

S14 is about the commit message, so it cites the short SHA and quotes the body rather than a file. The citation lint counts that as a finding without a leading block; the warning is expected and inventing a file reference would point the reader at code the finding is not about.

Skill improvements ¶

  • When a review adds or changes test fixtures, run the suite under a hardened process umask as well as the default. os.Mkdir, os.WriteFile, os.OpenFile and their equivalents in other languages mask the mode argument with the umask, so a fixture that creates a deliberately permissive file or directory silently creates a restrictive one for any contributor whose umask differs from CI's. The test then asserts against behavior it never produced. One extra run of the suite settles it.
  • When a fix removes a dead symbol, grep for its siblings before accepting the fix as complete. Dead code is usually found one symbol at a time, and a helper that had no callers often has an exported neighbour in the same file with the same problem. Enumerate the callers of every nearby symbol with a related name, not only the one the previous round named.
  • A test whose child process or subcommand carries the assertion needs a positive signal that the child ran. A process that silently does nothing usually exits 0, so a parent asserting only on the exit status passes when the child was never invoked, when a filter excluded it, or when it was renamed. Require the parent to observe something the child could only have produced by running.
