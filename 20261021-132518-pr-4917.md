The self-exclusion covers only a host file that exists at session start under exactly that name. The guest can still write the filter four ways.

- When the host has none, the file that the guest creates syncs back.
- On a case-insensitive host (macOS's default APFS), `.LIMASYNCIGNORE` or `.limaſyncignore` overwrites the host's file.
- A `+ .*` line in the user's own file matches first, because the self-exclusion comes last.
- When `.limasyncignore` links to a file in the synced tree, such as `.gitignore`, the guest edits that file.

A filter holding only `!` clears every earlier rule, `--sync-exclude` flags included, so the next session pushes what the user excluded.

## Design Observations

### Concerns

- **A filter inside the synced tree gives the guest a way to change it** (in-scope) [Codex GPT 6 Astra] [Claude Opus 5.5]. Round 3 found the rewrite, and this round found four more paths, one of which no name pattern can block. A filter outside the synced tree never reaches the guest. The author offered `--sync-exclude-from FILE` (r3174888608), and with FILE outside the synced tree it would make I1's patch unnecessary.
- **openrsync's dry run omits symlink retargets, so "No changes detected" can discard one** (future) [Claude Opus 5.5]. On the review host, openrsync's dry run printed nothing for a symlink retargeted from `b` to `a`, and the real run retargeted it. ###### Design Observations

###### Concerns

- **Interactive TUI diff logic is coupled with shell lifecycle** `(future)`:
  `askUserForRsyncBack` manages TUI selection, dry-run itemize output, pager execution, temporary guest copying, and host tree filtering in a single 250-line function. Decoupling the diff preparation and inspection logic into a testable abstraction would eliminate untestable branches like I1.

###### Strengths

- **Symmetric exclusion across all synchronization phases**: By passing `excludeArgs` consistently to initial sync (`shellAction`), dry-run diff (`getRsyncStats`), final sync-back (`rsyncBack`), and diff viewing (`hostTmpDest` / `diffSource`), the implementation ensures that file filters remain consistent throughout the round trip.
- **Robust flag isolation**: `validateSyncFlagValue` prevents `pflag` consumption bugs when `--sync` is passed without a directory, and `StringArray` preserves comma-containing patterns.

###### Acknowledged Limitations

- **Dangling `.limasyncignore` symlink skipped silently vs mode-000 failure** (`cmd/limactl/shell.go:995`): Confirmed. `os.Stat` follows symlinks and returns `os.ErrNotExist` on dangling targets, causing the ignore file to be skipped without warning. Mode-000 files return `nil` error from `os.Stat`, causing rsync to receive `--exclude-from` and fail loudly on unreadable file permissions. Verified with probe: `os.Stat` on dangling symlink returned `no such file or directory` (`isNotExist: true`); mode-000 returned `<nil>`.
- **Documentation describes excludes inaccurately** (`website/content/en/docs/examples/ai.md:193-203`): Confirmed. The documentation refers to "directories" rather than patterns and describes the host directory as the "target directory".
- **No test covers `--sync-exclude` without `--sync`** (`cmd/limactl/shell.go:234-236`): Confirmed. Grep for `cannot use '--sync-exclude' without '--sync'` in `cmd/limactl/shell_test.go` and `hack/bats/tests/` yields zero occurrences.
- **Edits to `.limasyncignore` during session**: Confirmed. Self-exclusion `--exclude /.limasyncignore` added in round 4 prevents the guest from creating or modifying `.limasyncignore` on the host during sync-back. However, host-side modifications to `.limasyncignore` while the shell session is active will still affect `rsyncBack` because `--exclude-from` points to the host file path.
