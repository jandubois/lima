## Suggestions

S1. **Without `findmnt`, a path with a space loses its read-only parent, and self-binds stack on reruns** — `pkg/driver/wsl2/boot.Linux/03-wsl-mounts.sh:24` [Gemini 3.1 Pro, Gemini 3.5 Flash, Codex GPT 6 Astra, Claude Opus 5.5]

```sh
	for ro_entry in $ro_mounts; do
```

`ro_mounts` is a space-separated list, so `/mnt/c/Users/John Doe` splits into two words that match nothing. `findmnt -T` at line 30 covers for that, and `is_exact_ro_mount` relies on `findmnt` alone. On a guest without it, the writable child of such a home stays read-only, and each rerun without a distro restart stacks another read-only self-bind. That is the open part of round-1 S3. The guests that this driver supports today probably have `findmnt`, since `02-no-cloud-init-setup.sh:12` creates the user with `useradd`, which BusyBox lacks.

Fix: require `findmnt` and drop `ro_mounts`, or keep the list newline-separated and loop over it with `IFS` set to a newline.

S2. **A failed self-bind still unmounts the path** — `pkg/driver/wsl2/boot.Linux/03-wsl-mounts.sh:92` [Codex GPT 6 Astra, Gemini 3.5 Flash]

```sh
				if mount --bind "$mountpoint" "$mountpoint" 2>/dev/null && mount -o remount,ro,bind "$mountpoint" 2>/dev/null; then
					ro_mounts="$ro_mounts $mountpoint"
				else
					WARNING "Path $location is natively read-write; cannot enforce writable:false on $mountpoint"
					umount "$mountpoint" 2>/dev/null || true
				fi
```

Line 88 joins the bind and the remount with `&&`, so line 92 also runs when the bind itself failed and this iteration did not make a mount. When the path is already a mount point, such as a drive root, `umount` would then remove the existing mount. A bind of an existing directory onto itself rarely fails, and on a missing directory `umount` fails harmlessly, so this stays a Suggestion. Lines 98-100 repeat the pattern.

Fix: undo only a bind that this iteration made.

S3. **The symlink fallback logs success when `ln` fails, and its link redirects the next boot's bind** — `pkg/driver/wsl2/boot.Linux/03-wsl-mounts.sh:136` [Codex GPT 6 Astra, Claude Opus 5.5, Gemini 3.1 Pro]

```sh
			if [ ! -e "$mountpoint" ]; then
				ln -sfn "$wsl_path" "$mountpoint"
				if [ "$writable" = "0" ]; then
					WARNING "Fell back to symlink for $mountpoint, but note that symlinks CANNOT enforce read-only status. Target is writable!"
				fi
				INFO "Successfully symlinked $wsl_path to $mountpoint"
```

Line 140 logs success whatever `ln` returned, and the `mkdir -p` at line 113 is unchecked too. The likeliest trigger is a host directory that does not exist yet; the reverse-sshfs hostagent creates it (`pkg/hostagent/mount.go:62`), but nothing does for wsl2. The link is still there after a restart. Once the directory exists, line 110 follows the link and does not find a mount, and the bind at line 115 follows it too, binding the source onto itself. With `writable: false`, line 117 then makes the `/mnt/<drive>` path read-only as well. That step rests on mount(2) following a symlink in its target, which nobody ran on Linux.

Fix: create the host directory before the bind, as the hostagent does, or warn and `continue` instead of linking.

S4. **A rerun keeps an existing custom mount's old flags** — `pkg/driver/wsl2/boot.Linux/03-wsl-mounts.sh:110-111` [Gemini 3.5 Flash, Codex GPT 6 Astra]

```sh
	if mountpoint -q "$mountpoint"; then
		INFO "$mountpoint is already mounted, skipping"
```

`mountpoint -q` says only that something is mounted there. A rerun after a failed read-only remount at line 117, or after a change to `writable`, keeps the old flags. A rerun without a distro restart happens after `limactl stop --force`, which round 1 found kills only Lima's own processes.

Fix: compare the existing mount's flags with `writable`, and remount when they differ.

S5. **`echo` mangles Windows paths in the log on dash guests** — `pkg/driver/wsl2/boot.Linux/03-wsl-mounts.sh:10` [Claude Opus 5.5]

```sh
INFO() {
	echo "LIMA $(date -Iseconds)| mounts: $*"
}
```

dash, the `/bin/sh` on Debian and Ubuntu, interprets backslash escapes in `echo`. Under `/bin/dash`, `C:\Users\alice\cache` printed a BEL for `\a`, and `\c` ended the output there, dropping the rest of the message and its newline. Four messages (lines 73, 91, 99 and 103) quote `$location`; the rest print guest paths, which have no backslashes.

Fix: use `printf '%s\n' "LIMA $(date -Iseconds)| mounts: $*"`, and the same in `WARNING`.

S6. **The new `mountPoint` check hides the `location` error** — `pkg/limayaml/validate.go:159-162` [Claude Opus 5.5]

```go
		if f.MountPoint == nil {
			errs = errors.Join(errs, fmt.Errorf("field `mounts[%d].mountPoint` must be specified explicitly (failed to automatically determine default mount point)", i))
			continue
		}
```

For a relative location such as `relative\path`, the `continue` skips the absolute-path check at line 163. So the user is told to set `mountPoint`, and learns that the location itself is invalid only after doing so. Lines 163-183 never dereference `MountPoint`.

Fix: move the block to just before `switch *f.MountPoint` at line 184.

## Design Observations

### Concerns

- **What `writable: false` means on wsl2 is still open** (in-scope) [Claude Opus 5.5, Codex GPT 6 Astra, Gemini 3.5 Flash]. Round 1 left this to the maintainers, and the PR comments do not record a ruling. This revision documents read-only in `mount.md`, and its example makes `~` read-only and `~/projects` writable. The source stays writable under `/mnt/<drive>`, the user has passwordless sudo, and interop runs Windows programs, so the bind guards against mistakes only. An existing wsl2 instance that declares mounts gets read-only binds at its first start after an upgrade, including the directory `limactl shell` starts in.
- **The translator still hard-codes `/mnt`** (future) [Claude Opus 5.5, Codex GPT 6 Astra, Gemini 3.5 Flash, Gemini 3.1 Pro]. With a custom `[automount] root`, `wslpath` and the default mount point disagree. The script then binds the `wslpath` path onto the `/mnt/<drive>` path, so listed mounts still work. Paths outside the listed mounts do not get a `/mnt` alias.
- **A mount whose mount point cannot be defaulted now fails validation** (in-scope) [Claude Opus 5.5]. At the merge-base such a mount got an empty mount point and the instance loaded. Now `Validate` refuses the instance, and not only for wsl2: a qemu instance on a Windows host without cygpath fails too when it has a UNC location. A wsl2 instance created before this PR with a UNC mount becomes Broken. `limactl delete --force` then skips `unregister` (`pkg/instance/delete.go:27-31`) and leaves the WSL distro registered. The error message names the remedy, but the commit message does not mention the change.

### Strengths

- Keeping an entry whose mount point could not be defaulted, so that `Validate` reports it, avoids both the panic and a silent drop. [Claude Opus 5.5]
- Gating `_LOCATION` and `_WRITABLE` on wsl2 leaves every other guest's `lima.env` unchanged. [Claude Opus 5.5, Codex GPT 6 Astra, Gemini 3.5 Flash]
- Host-side translation stays a pure string function, so `FillDefault` does not start a WSL distro. [Codex GPT 6 Astra] (raised in round 1 by Codex GPT 6 Astra and Claude Opus 5.5)

## Review Process Notes

### Skill improvements

- Extend "Entries over nested paths" in the dimensions: check each nesting pair in both list orders, and find the order that the project's config merging (base templates, default and override files) produces. A user rarely writes the order that breaks, but merging can produce it.

### Repo context updates

- [repo] `limatmpl` embedding appends a base template's list entries (mounts, networks, disks and the rest) after the template's own; only `base`, `provision` and `probes` are prepended. `FillDefault` then concatenates `_config/default.yaml`, the template and `_config/override.yaml` in that order without sorting. Guest-side code that walks `LIMA_CIDATA_MOUNTS_*` in index order therefore sees an inherited `~` after a template's own `~/projects`, and must not assume parents come first.
- [repo] Boot scripts run under `/bin/sh`, which is dash on Debian and Ubuntu guests. dash's `echo` interprets backslash escapes, so a script that logs a Windows path must use `printf '%s\n'`.

##### Design Observations

###### Concerns

1. **WSL2 `writable: false` protection boundary** `(in-scope)`:
   Remounting `/mnt/c/Users/...` as read-only inside WSL2 prevents guest processes from modifying host files at that specific path. However, files remain directly accessible through `/mnt/c` unless unmounted, the guest user has passwordless sudo, and Windows interop binaries can still be executed. This is documented in `website/content/en/docs/config/mount.md`, but users should be reminded that this is an accidental-edit guard, not an isolation boundary.

2. **Automount root disagreement between Go and WSL** `(future)`:
   `TranslateWindowsToWSLPath` hardcodes `/mnt/<drive>`, while the guest's `wslpath` respects custom `[automount] root` settings from `/etc/wsl.conf`. If a user customizes `root = /`, the default mount point will differ from the automount path, causing the script to create bind mounts rather than using automount paths directly.

###### Strengths

- Removing the invasive `/etc/wsl.conf` edit (Step 3) preserves user configuration and avoids unexpected system-wide permission changes across reboots.
- Pre-filtering `LIMA_CIDATA_MOUNTS_*_LOCATION` and `_WRITABLE` to `wsl2` instances avoids cluttering environment configurations on macOS and Linux guests.
