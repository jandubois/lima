Executive Summary ¶

The PR stops the WSL2 host agent from pinning another SSH server's host key. It pins only a key that wsl.exe finds in the guest's /etc/ssh. The WSL2 CI job at this head hit the race and recovered. The design is close to minimal, though parseAuthorizedKeys can shrink and three table rows repeat what TestPinHostKey covers. The one Important finding asks for a test that checks that the host agent finds the reader behind ConfiguredDriver.

S1. parseAuthorizedKeys repeats the loop inside ssh.ParseAuthorizedKey Codex GPT 6 Astra Gemini 3.1 Pro Gemini 3.5 Flash Claude Opus 5.5¶
pkg/sshutil/hostkey.go

// parseAuthorizedKeys returns the public keys in b, which is in the authorized_keys format.
// Blank lines, comments and lines that fail to parse are skipped, so that one bad line does not hide the other keys.
func parseAuthorizedKeys(b []byte) []ssh.PublicKey {
	var keys []ssh.PublicKey
	for line := range bytes.Lines(b) {
		if trimmed := bytes.TrimSpace(line); len(trimmed) == 0 || trimmed[0] == '#' {
			continue
		}
		key, _, _, _, err := ssh.ParseAuthorizedKey(line)
		if err != nil {
			logrus.WithError(err).Debugf("Ignoring the line %q in the SSH host keys of the guest", line)
			continue
		}
		keys = append(keys, key)
	}
	return keys
}

In x/crypto v0.58.0, ssh.ParseAuthorizedKey (ssh/keys.go:234) already walks its input line by line. It skips blank lines, # comments and lines it cannot parse, drops a trailing CR, and returns the rest of the input. So an 8-line loop over that rest replaces the 11-line one, and the blank and comment check goes. Both versions returned the same keys for six inputs: the test's own, an empty one, CRLF, no final newline, and a bad line in the middle or at the end. The only loss is the Debug line that names a bad line. A containsKey(b, key) helper that returns at the first match would also drop the slices import.

Fix:

	for len(b) > 0 {
		key, _, _, rest, err := ssh.ParseAuthorizedKey(b)
		if err != nil {
			break // b holds no further key
		}
		keys = append(keys, key)
		b = rest
	}

Design Observations ¶

Concerns ¶

  • Instances that Lima 2.3.0 pinned to another server's key stay broken (future) Claude Opus 5.5: this PR leaves them as they were at the merge-base. Each fails until the user removes ssh.known_hosts. The mismatch warning names that file when the guest answers first. A release note that points at the file would reach the users who hit #5801 on 2.3.0.

Strengths ¶

  • The design is close to the smallest that fixes #5801 (in-scope) Claude Opus 5.5 Codex GPT 6 Astra Gemini 3.5 Flash. This answers the author's first question. What each piece is for:
  • GuestSSHHostKeysReader is optional, like Screenshotter, so the external drivers' gRPC API stays as it is. The assertion at pkg/driver/wsl2/wsl_driver_windows.go:63 breaks the build if the method is renamed, and an anonymous interface at the call site would not.
  • concreteDriver serves both Screenshot and pinSSHHostKey, and it replaces the unwrap that Screenshot had inline.
  • ErrHostKeyNotGuest and its flag give the user the one early Info line. The requirement loop does not log retry errors (pkg/hostagent/requirements.go:71-104), so without them the user would not see anything for up to 10 minutes.
  • The fast path at pkg/sshutil/hostkey.go:122-124 keeps wsl.exe out of every boot after the first, and it keeps instances pinned before this change clear of S3's limit.
  • The rejected alternative, waiting in the WSL2 driver's AdditionalSetupForSSH until the guest's sshd listens, would drop the interface, the error and the parser. But it assumes WSL's relay takes over 127.0.0.1:22 as soon as sshd listens, which nobody has measured, and it would not check any key.
  • CI exercised the fix (in-scope): Windows tests (WSL2) at this head saw the runner's Windows OpenSSH Server answer first (SHA256:t69vws…). The host agent logged that key as not the guest's, pinned the guest's key 3 seconds later, and the job passed.

Acknowledged Limitations ¶

  • Only the built-in WSL2 driver reads the guest's keys (PR body). WSL2 built as an external driver pins as before, because the gRPC client wrapped at pkg/driver/external/client/methods.go:330 does not implement the interface.
  • Only /etc/ssh/ssh_host_*_key.pub is read (PR body). S3 asks to document it.
  • A guest key that differs from the pin stays a mismatch. Do not re-suggest re-pinning any key the guest holds, because that would undo the guarantee #5687 added.
  • A distro re-imported after a manual wsl --unregister fails the pin. Lima does not support unregistering a distro outside limactl delete. Do not re-suggest healing it.
  • readGuestSSHHostKeys has no timeout of its own, like every other wsl.exe -d call in the driver. Do not re-suggest one without an observed hang. The host agent's requirement context has no deadline, and the host agent does not log the reader's error on a retry. Its 200 retries outlast the 10 minutes that limactl start waits (pkg/instance/start.go:46). So with or without a timeout, a hung wsl.exe shows the user the same 10-minute timeout of limactl start.
  • ScanHostKey prefers ed25519 whatever type is pinned, as the second review of #5687 found. This PR does not change it.
  • From the reviews of #5687: the first boot trusts the guest, and a mismatch is retried by design.

Review Process Notes ¶

Skill improvements ¶

  • Before the prompt cites a log as proof that new code ran, find a line that only the new code can print. A success line that the old code prints too does not show that the new code ran, and agents repeat the claim as verified.

Repo context updates ¶

  • [repo] Configure returns every driver, external ones included, wrapped in *driver.ConfiguredDriver, which embeds the Driver interface and so does not expose an optional driver interface such as Screenshotter or GuestSSHHostKeysReader. Host agent code reaches them through concreteDriver(). Flag a type assertion for an optional interface on the wrapped driver, and a test that hands the host agent an unwrapped fake driver, because that test passes whether or not the code unwraps.
  • [repo] GitHub's Windows runner image runs the Windows OpenSSH Server on 0.0.0.0:22, with one host key on every runner (SHA256:t69vws…). Lima reaches a WSL2 guest's sshd at 127.0.0.1:22, so the runner's server answers until WSL's relay binds that address. Treat WSL2 code that trusts the first SSH answer on port 22 as racing the runner's server.
