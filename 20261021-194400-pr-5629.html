Executive Summary ¶

This PR adds a form to limactl-menu for creating an instance, builds its fields from the limactl create flags, and offers an Edit button that opens the template YAML first. Two defects need fixing before merge. One mouse click on the column header or footer disables every list shortcut, which the merge-base did not do. And when limactl rejects YAML edited through the Edit button, the edits are lost, because neither limactl nor the menu saves them.

// quitsOnQ builds the menu the way run() does, on an 80x25 simulation screen,
// optionally clicks row y, presses 'q', and reports whether the menu quit.
func quitsOnQ(click bool, y int) bool {
	sim := tcell.NewSimulationScreen("UTF-8")
	s := &State{insts: []*limatype.Instance{{Name: "foo", Status: "Stopped"}}, limactl: "/nonexistent", ctx: context.Background()}
	s.app = tview.NewApplication().EnableMouse(true)
	s.app.SetScreen(sim)
	s.setupStyles()
	s.buildUI()
	footer := tview.NewTextView().SetText(" F1 Help ... F10 Quit")
	s.flex = tview.NewFlex().SetDirection(tview.FlexRow).AddItem(s.panel, 0, 1, true).AddItem(footer, 1, 1, false)
	s.app.SetRoot(s.flex, true).SetFocus(s.list)
	s.app.SetInputCapture(s.handleGlobalKey)
	done := make(chan struct{})
	go func() { _ = s.app.Run(); close(done) }()
	time.Sleep(200 * time.Millisecond)
	if click {
		sim.InjectMouse(10, y, tcell.Button1, tcell.ModNone)
		time.Sleep(50 * time.Millisecond)
		sim.InjectMouse(10, y, tcell.ButtonNone, tcell.ModNone)
		time.Sleep(100 * time.Millisecond)
	}
	sim.InjectKey(tcell.KeyRune, 'q', tcell.ModNone)
	select {
	case <-done:
		return true
	case <-time.After(time.Second):
		s.app.Stop()
		<-done
		return false
	}
}

Design Observations ¶

Concerns ¶

  • The menu binary grew 4.6 times (future) Claude Opus 5.5: a default go build on macOS arm64 gave 6,592,754 bytes at the merge-base and 30,123,586 at the head, and go list -deps grew from 189 to 527 packages (both measured for this review). The new imports of editflags, limatmpl, limayaml and yqutil pull in much of limactl, and the release archive ships the menu as a plugin (Makefile:326). Reading the flags and the template from limactl at run time would avoid that, at the cost of a larger change.
  • The help screen says h opens the actions menu (in-scope) Claude Opus 5.5 Gemini 3.5 Flash: main.go:291 says Enter / h opens the actions menu, but h opens the help (main.go:221), as it already did at the merge-base. The PR edits both places, so the one-line fix fits here.

Strengths ¶

  • The fields follow limactl create (in-scope) Claude Opus 5.5 Codex GPT 6 Astra Gemini 3.5 Flash: the form builds its fields from editflags.RegisterCreate and its completion functions, and the Edit path applies them with editflags.YQExpressions, so a new limactl create flag appears in the form without menu changes.
  • The key guard fixes an older bug (in-scope) Claude Opus 5.5: at the merge-base, d, F2, F3 and F8 acted on the highlighted instance while the help view or the actions menu covered the list, and q quit the menu from the help view. The new guard stops that, and the I1 fix keeps it.

Testing Assessment ¶

  • I1 needs a test (required): every shortcut stops silently, and nothing tests handleGlobalKey. The patch adds TestListShortcutsWhileListViewIsShown, which fails at the head and passes with the fix.
  • I2 needs a test (required): the defect silently loses user input. The patch adds TestEditAndCreateSavesRejectedYAML, which fails at the head and passes with the fix. Its limactl and editor are shell scripts, so it skips on Windows, where the WSL2 job runs go test ./....
  • The PR's own tests exercise real logic (argument building, validation, YAML application, field kinds) without mocks.
  • I ran go test ./cmd/limactl-menu/ in the lead worktree. All 18 tests pass at the head, and all 20 pass with both patches applied in sequence. On the head, 37 CI checks pass and 2 are skipped.
  • Optional: a test for S2 would need updateTemplateChoices lifted out of showCreateForm.

Documentation Assessment ¶

The commit message says the single-key shortcuts now work only while the list has the focus. The guard covers F1 to F8 as well, and after the I1 fix it applies to the whole list view, so that paragraph should say both. The help screen's Enter / h line is wrong (see Design Observations). No website page covers limactl-menu.

Acknowledged Limitations ¶

  • Entering Other... as a custom value (create.go:186): typing the literal text Other... into an "Other..." dialog reopens the dialog, because the value then matches otherChoice. It does not loop. promptValue shows the dialog and returns, and Cancel restores the previous value. Do not re-raise it as a hang.
  • Reading the template on the UI goroutine (create.go:444): updateTemplateChoices runs limactl template copy --embed-all each time the template changes. Here it took 0.79 s for default (first run) and 0.06 to 0.07 s for k8s and docker, all local reads. No bundled template has a remote base:, so only a user template with one would fetch, and limactl create fetches the same base. Do not re-suggest an asynchronous read without a template that shows a visible stall.
  • context.Background() in editAndCreate: s.ctx comes from cobra's Execute, which nothing cancels, so the two contexts behave the same.

Review Process Notes ¶

Skill improvements ¶

  • When a change routes keys or other input by which widget has focus, list every event that moves the focus, including a mouse click on a passive widget such as a label, a header or a status bar, and check the routing after each one. A focus check written for keyboard navigation misses the paths that the mouse opens.

Repo context updates ¶

  • [repo] limactl-menu runs tview with the mouse enabled, and tview gives the focus to any TextView or Box the user clicks, the column header and the footer included. Key handling that tests app.GetFocus() against one widget breaks after such a click; test the view as a whole, for example with Flex.HasFocus.
  • [repo] limactl create and limactl start turn tty off when they read a template from stdin (-), and instance.Create saves lima.REJECTED.yaml only with tty on. A caller that pipes user-edited YAML to limactl must keep the buffer itself when limactl rejects it.
  • [repo] limactl template copy --embed-all leaves out the user's _config/base.yaml, which only --fill adds, while limactl create embeds it before checking --param. Code that edits or validates a template outside limactl must decide whether the global base applies.
