Executive Summary ¶

All ten round-1 findings are fixed, and the fixes hold. Real OpenSSH 10.3 refuses a key of another type under every option set, so dropping HostKeyAlgorithms did not open a downgrade. Two new failures remain. A guest pinned on RSA fails to start once it gains an ed25519 key, because the scan prefers ed25519 over the pinned type; a patch below fixes that. And a qemu snapshot taken before the upgrade fails its next start.

func startProbeServer(t *testing.T, hostKeys ...ssh.Signer) (string, int) {
	l, err := net.Listen("tcp", "127.0.0.1:0")
	assert.NilError(t, err)
	t.Cleanup(func() { _ = l.Close() })
	config := &ssh.ServerConfig{NoClientAuth: true}
	for _, k := range hostKeys {
		config.AddHostKey(k)
	}
	go func() {
		for {
			conn, err := l.Accept()
			if err != nil {
				return
			}
			go func() { defer conn.Close(); _, _, _, _ = ssh.NewServerConn(conn, config) }()
		}
	}()
	return "127.0.0.1", l.Addr().(*net.TCPAddr).Port
}

Acknowledged Limitations ¶

  • First boot trusts the guest. The author chose this after moving key generation into the guest, because the ISO is readable by non-root users in some guests.
  • Localhost is verified on purpose. A PR comment proposed checking only other hosts, and the author declined.
  • A mismatch retries by design. pkg/hostagent/requirements.go:173-174 states why, and the warning prints once.
  • A non-plain alpine-iso restart keeps its key. Do not re-suggest restarting sshd in the persistence script.
  • ssh.md's example does not need more options. Do not re-suggest HostKeyAlgorithms or StrictHostKeyChecking there.
  • /dev/null stays on Windows. Do not re-suggest NUL, a Win32 name that MSYS2 and Cygwin ssh may not share.
  • BatchMode=yes stays. Only a diff in a PR comment removes it.
  • HostKeyOpts does not need a HostKeyAlgorithms restriction. Do not re-suggest it. OpenSSH 10.3p1 treats a key of another type for a pinned host as a changed key, under accept-new too.
  • No CI job restarts a plain-mode alpine-iso (optional in rounds 1 and 2). No CI job passes --plain to hack/test-templates.sh, so the test needs a new CI step, and the failure is loud and happens on every second start.

Review Process Notes ¶

Skill improvements ¶

  • When a change makes the host keep a record of guest state (a pinned key, a cached digest, a recorded identifier), ask agents to walk every operation that rewinds or replaces that state from outside the guest: snapshot apply, clone, factory reset, disk replacement and downgrade. A diff review checks the record against the guest's normal lifecycle, and the operations that restore older guest state sit in files the diff never touches.

Repo context updates ¶

  • Lima changes the cloud-init instance-id on every boot (pkg/cidata/cidata.go), so cloud-init's per-instance modules run on every boot, and guest state they would regenerate survives only if the guest's own disk opts out before the boot starts. limactl snapshot apply (qemu and krunkit) restores the whole disk, opt-out files included. Check any host-side record of guest state against snapshot apply, clone and factory reset. Factory reset deletes every instance file except the YAML, lima-version, protected and the vz identifier, and clone copies everything except protected and the TPM state.
