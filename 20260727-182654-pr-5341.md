## Important Issues

I1. **`SSH` is offered as an alternative to fixing `PATH`, but reverse-sshfs mounts ignore it** — `website/content/en/docs/config/vmtype/wsl2.md:98` [Claude Opus 5]

```markdown
all of which Lima needs. Either set `SSH` to the full path of Git's
`ssh.exe`, or add `C:\Program Files\Git\usr\bin\` to your `PATH` ahead of
any other directory holding an `ssh.exe`. The Git installer's default
```

sshocker's `SSHConfig.Binary()` returns a hardcoded `"ssh"` (v0.3.11, `pkg/ssh/ssh.go:22-24`), so every reverse-sshfs mount runs whatever `ssh` the `PATH` resolves.

Meanwhile `identityFileEntry` converts the private-key path through the *selected* toolchain and the hostagent hands the resulting options to sshocker verbatim as `AdditionalArgs` (`pkg/sshutil/sshutil.go:487-496` and `pkg/hostagent/hostagent.go:226-228` on #5300). With `SSH` naming Git's `ssh.exe` while native OpenSSH leads `PATH`, native `ssh` receives `IdentityFile='/c/Users/…'` and cannot resolve it; `IdentitiesOnly=yes` leaves no fallback. Windows QEMU defaults to reverse-sshfs because 9p is unsupported (`pkg/driver/qemu/qemu_driver.go:239-247`), so this is the normal mount path.

`environment-variables.md:234` in this same commit says the two must agree, so the commit gives opposite advice on two pages.

Fix: drop the `SSH` alternative here and tell the reader to fix `PATH`; keep `SSH` documented as an override on the environment-variables page.

I2. **A Windows path in `SSH` loses its backslashes, and this page calls a bare path reliable** — `website/content/en/docs/config/environment-variables.md:223` [Codex GPT 5.6 Sol, orchestrator]

```markdown
- **Description**: Command to run in place of the `ssh` executable. The value is
  split into shell tokens, so it can carry arguments as well as a path. Lima
  sets its own `-F` on most invocations, and `limactl copy` drops the arguments
  on its scp backend, so a bare path is the reliable form.
```

`shellwords.Parse` treats `\` as an escape, so a bare Windows path is destroyed. I ran the pinned `mattn/go-shellwords` v1.0.14 against four forms:

| value | result |
|---|---|
| `C:\Program Files\Git\usr\bin\ssh.exe` | `["C:Program", "FilesGitusrbinssh.exe"]` |
| `"C:\Program Files\Git\usr\bin\ssh.exe"` | `["C:Program FilesGitusrbinssh.exe"]` |
| `'C:\Program Files\Git\usr\bin\ssh.exe'` | intact |
| `"C:/Program Files/Git/usr/bin/ssh.exe"` | intact |

The value must carry quotes or forward slashes; single quotes preserve backslashes, double quotes do not. `wsl2.md:98` tells Windows readers to set `SSH` to exactly the broken form, and the only example on this page (`export SSH=/opt/homebrew/bin/ssh`) is Unix.

Fix: say the value is shell-tokenised, so a Windows path needs quoting or forward slashes, and add `$env:SSH = '"C:/Program Files/Git/usr/bin/ssh.exe"'` as a PowerShell example.

I3. **The `fstab` note exempts default installs whose guest mount point does move** — `website/content/en/docs/config/vmtype/wsl2.md:134` [Claude Opus 5]

```markdown
disk. Lima re-derives the host path on every start, so on such a host do
not change ssh toolchains between starts of an existing QEMU instance
with a reverse-sshfs mount: the mount would afterwards point at a
different directory. Default installs without `fstab` overrides are
unaffected.
```

The claim about the host directory is right: without an `fstab` override, `/c/Users/USER` and `/cygdrive/c/Users/USER` name the same directory. But a mount with no explicit `mountPoint` derives its *guest* path from the PATH-global converter on every load (`pkg/limayaml/defaults.go:728-737`), and `pkg/instance/create.go` persists the pre-defaults YAML, so nothing pins it.

Switching between stock Cygwin and MSYS2 or native therefore moves an existing instance's mount inside the guest, between `/cygdrive/c/Users/USER` and `/c/Users/USER` — the two forms this page names at lines 116-117. A default install is not unaffected.

Fix: keep the `fstab` hazard, then replace the exemption with a note that a mount without an explicit `mountPoint` moves inside the guest when the toolchain changes.

## Review Process Notes

### Skill improvements

- In PR mode, compare the PR's head SHA against the local branch of the same name before launching agents. When the local branch is ahead, the hosting platform still reports the older head, and the round re-reviews code whose findings the author has already resolved. Report the divergence and settle which SHA to review before spending a round on it.

- When you propose a fix, apply to the fix the same verification you applied to the defect. A finding produced by running a program earns its confidence from that run; the patch beside it usually does not, and a patch that trades one broken form for another arrives with the finding's authority attached.

- Before citing a documentation table as authority, check that its columns distinguish the entities your claim distinguishes. A single row summarising a product that ships as separable components supports no claim about one component alone, and a reviewer reading such a table will produce a confident finding about the wrong half.

- When you build a probe, script, or scratch program to answer a question, report what it returned even when it confirms the code. An experiment that produced no finding is still evidence, and omitting it leaves a reader unable to tell a checked claim from an unchecked one.

### Repo context updates

- [repo] Building the website needs `make docsy` before `hugo`: `website/hugo.toml` imports `../_output` as a Hugo module, and that directory is generated by building `limactl` and running `generate-doc`. `npm --prefix website ci` installs the pinned `hugo-extended` but the build then fails with `module "../_output" not found`. Treat any claim that the site cannot be built locally as a missing prerequisite rather than a missing tool.

- [repo] Hugo's `{{< ref "page#fragment" >}}` resolves the page and fails the build on a bad path, but it never checks the fragment. An anchor in a cross-reference is verified only by rendering the site and matching the emitted `href` against the target heading's generated `id`.

- [repo] `pkg/sshutil.NewSSHExe` parses `SSH` with `shellwords.Parse`, which treats `\` as an escape character. A Windows path therefore loses its separators: `C:\Program Files\Git\usr\bin\ssh.exe` becomes two tokens with every backslash stripped, and wrapping it in double quotes preserves the space while still stripping them. Only single quotes or forward slashes survive. Flag any documentation or default that hands `SSH` an unquoted backslash path.

- [repo] A mount with no explicit `mountPoint` has its guest path derived in `FillDefault` from the PATH-global converter, and `pkg/instance/create.go` persists the pre-defaults YAML, so the value is recomputed on every load rather than pinned at create. Stock Cygwin yields `/cygdrive/c/...` where MSYS2 and Git for Windows yield `/c/...`, so changing the host toolchain moves an existing instance's mount inside the guest. Weigh any claim that toolchain changes are safe for default installs against this.
