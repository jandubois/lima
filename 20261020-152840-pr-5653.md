## Executive Summary

With the default gRPC forwarder, non-reverse `guestSocket` rules now go through the guest agent's tunnel, so on vz docker.sock no longer dies with the SSH ControlMaster. The routing and the per-dial client lookup are sound. Three things need fixing. The host socket's mode now follows the umask where SSH created it 0600, a template comment about guest socket access is now false because the guest agent connects as root, and no test pins the routing decision.

## Important Issues

I1. **The host socket's mode follows the umask; the SSH forward created it 0600** — `pkg/portfwd/listener.go:143` [Claude Opus 5.5]

```go
	unixLis, err := Listen(ctx, p.listenConfig, hostAddress)
```

At the merge-base, OpenSSH created this socket under its default `StreamLocalBindMask 0177`, so it was 0600 (`ssh_config(5)`). `forwardUnix` now creates it through `Listen`, whose Unix branch does not set a mode, so the socket gets `0777 &^ umask`. Under umask 002 that is `srwxrwxr-x`, and `connect(2)` checks the write bit, so the group (on macOS usually `staff`, every local user) can connect. With a `hostSocket` in a directory that others can traverse, such as Rancher Desktop's `~/.rd/docker.sock` (`~` and `~/.rd` are 0755 on the review host), another local user reaches docker.sock and so guest root. Under the default umask 022 nothing is exposed.

The Unix branch is `listener_darwin.go:23` and `listener_others.go:21`. TCP guest ports forwarded to a `hostSocket` take it too, so the fix covers them.

## Suggestions

S1. **`forwardUnix` copies `forwardTCP`'s accept loop but drops its pseudoloopback `continue`** — `pkg/portfwd/listener.go:158-159` [Codex GPT 6 Astra, Claude Opus 5.5, Gemini 3.1 Pro, Gemini 3.5 Flash]

```go
			logrus.Errorf("failed to accept unix connection: %v", err)
			return
```

A `guestSocket` rule may forward to a `hostPort` (`pkg/limayaml/validate.go:390`). On macOS, `127.0.0.1` with a port below 1024 goes through `pseudoLoopbackListener`, whose `Accept` returns an error for every non-loopback peer. `forwardTCP` continues past that error (line 124). `forwardUnix` returns, and its deferred `Remove` closes the listener, so one LAN connection ends the forward. SSH could not bind such a port unprivileged, so nothing regresses. Both loops also give up on any other `Accept` error, such as `EMFILE`, which leaves docker.sock gone until a restart. `handleUnixConnection` exists only because tcpproxy dials `"tcp"`, and a dialer that rewrites the network to `"unix"` fixes that. The PR's Unix tests and a client half-close probe pass with that change.

Fix: reuse `forwardTCP` and `HandleTCPConnection` with a protocol parameter for the key and a dialer that passes `"unix"`, so one loop gets any later fix to accept-error handling.

## Design Observations

### Concerns

- **Socket routing follows the TCP forwarder choice** (in-scope). With `LIMA_SSH_PORT_FORWARDER=true` every `guestSocket` stays on the ControlMaster. Rancher Desktop 1.x (`sshPortForwarder: true` in `pkg/rancher-desktop/config/settings.ts:167`) and colima (`portForwarder: ssh`, which sets the variable to `true`) both run that way by default, as their upstream sources read today, so the users of rancher-desktop#9839 and colima#1033 keep docker.sock on the master. The #5420 thread asked for every Linux socket on its own connection. The maintainers should decide whether the socket transport follows the TCP forwarder; a user who chose SSH to stay off the gRPC tunnel would see a change if it did not.
- **On QEMU, docker.sock still depends on the master** (in-scope) [Claude Opus 5.5]. QEMU on macOS and Linux leaves `virtioPort` empty (`pkg/driver/qemu/qemu_driver.go:70-73`), so the gRPC tunnel rides the SSH-forwarded `ga.sock`. A master death still breaks docker.sock there, but the socket now comes back once some ssh re-creates a master and the 10-second loop re-forwards `ga.sock` (`pkg/hostagent/hostagent.go:862-867`); an SSH-forwarded socket never came back. The PR description says the change applies "when `LIMA_SSH_PORT_FORWARDER=false`", but it applies when the variable is unset too, and it does not decouple the socket from the master on QEMU.
- **The guest-side identity changes from the lima user to root** (in-scope) [Claude Opus 5.5]. Under `user.passwordlessSudo: false` the threat model treats guest root as a boundary, and a `guestSocket` rule that used to fail on permissions now reaches root-owned sockets. Templates are trusted, so this is a behavior change for the release notes, not a vulnerability. I2 covers the template comment.

### Strengths

- **Each dial looks up the current client** (in-scope) [Claude Opus 5.5, Codex GPT 6 Astra, Gemini 3.5 Flash]. `DialContextToGRPCTunnel(a.getClient)` keeps the socket listeners working across guest agent reconnects. The original commit's per-dial `getOrCreateClient` would have added an `Info` RPC to every connection.
- **Unix listeners are keyed by host path** (in-scope) [Claude Opus 5.5]. A second rule for the same host path cannot unlink the live socket through `RemoveStaleSocket`, which removes any socket at the path.
- **Reverse rules and the SSH mode stay on SSH** (in-scope) [Claude Opus 5.5]. The cleanup cancels only the forwards that SSH owns.
- **A client half-close reaches the guest** (in-scope) [Codex GPT 6 Astra, Claude Opus 5.5]. A client that sends its request and calls `CloseWrite`, the `docker exec` pattern from #5420, gets the whole response through the Unix path.

## Review Process Notes

### Skill improvements

- When a change moves an existing function onto a different mechanism (an external tool's forward to an in-process listener, one transport to another), list what the old mechanism did without being asked, such as the file mode that it created, the identity that it acted as, what it logged, and how it cleaned up. Then check each property in the new path. A reviewer reading the diff compares the new code with itself and misses properties that the old code never spelled out.
- A Unix socket path must fit in 104 bytes on macOS, and a path under the worktree's `.scratch/` can exceed that. Tell agents to bind such a socket by a relative name from a process whose working directory is inside `.scratch/`, so a probe that needs one does not fall back to `/tmp`.

### Repo context updates

- [repo] SSH and gRPC forwards differ in two properties that the code does not state. OpenSSH creates a forwarded host socket with its default `StreamLocalBindMask 0177`, and connects to a guest socket as the lima user; the gRPC tunnel connects from the guest agent, which runs as root. When a change moves a forward between the forwarders, check the host socket's mode and the guest-side identity.
- [repo] Rancher Desktop 1.x (`sshPortForwarder: true`) and colima (`portForwarder: ssh`) run Lima with `LIMA_SSH_PORT_FORWARDER=true` by default, so a change that only takes effect under the gRPC forwarder does not reach their users.
