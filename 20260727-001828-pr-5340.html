Review Process Notes ¶

Skill improvements ¶

  • Answer a prior round's open item with a measurement or say why you could not. When an earlier round recorded an item as open because a fact could not be measured in that environment, treat re-establishing that fact as the round's first task, and prefer a language or library source that pins the behaviour over reasoning from documentation. Report the item as still open when neither is available, rather than promoting an expectation to a conclusion.
  • Check a decline's stated reason, not only its subject. When a prior round declined a finding because some artifact documents the behaviour, open that artifact and confirm the documentation is there. A reason that was never true, or that a later edit removed, silently converts a reasoned decline into an undisclosed change.
  • Distrust a helper branch that normalizes one spelling into another. When a function rewrites a prefix before measuring, check whether the rewrite can change the measurement at all. Prefix normalization that preserves the quantity being counted is a no-op the reader must still verify, and a comment asserting it matters makes the verification harder to skip.
