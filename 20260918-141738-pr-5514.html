Executive Summary ¶

The hcs driver now converts qcow2 and raw images to VHDX through go-qcow2reader instead of qemu-img. The writer itself is sound: a converted image round-trips byte-identically through qemu-img, and the disk finally honors the configured disk: size. But the switch narrows what hcs accepts. A zstd-compressed qcow2 that qemu-img read now fails outright, an ISO instance image produces an empty boot disk, and disk: is honored for a converted image while a .vhdx one keeps its own size.

Design Observations ¶

Concerns ¶

  • EnsureDisk assumes its caller attaches the ISO (in-scope) Codex GPT 5.6 Sol — the ISO branch splits the image into iso plus an empty disk for every caller, with nothing checking that the driver consumes filenames.ISO. Making ISO handling an explicit driver capability, or keeping it in the drivers whose VM config reads that file, forecloses I2 rather than patching it.
  • SupportedImageFormats carries two meanings (future) Claude Opus 5 Codex GPT 5.6 Sol — boot capability and download-normalization hint. Splitting them, or letting a driver declare the format it wants the image normalized to, removes the coupling behind both I1 and I5.
  • convertTo branches on destType in three places (future) Claude Opus 5 — temp-file creation, writer selection, and the resize skip, with nothing tying them together. A fourth format has to touch all three and nothing catches a missed one.
  • The disk.vhdx hard link is never refreshed (future) Claude Opus 5 Gemini 3.5 Flash — CreateDisk returns early when the link exists, and a hard link outlives the deletion of its peer, so a user who removes disk to force a re-conversion boots the old inode through disk.vhdx. These lines predate the PR and I found no code that removes disk while leaving the link, so this is latent.

Strengths ¶

  • The virtual size is set when the VHDX is created (in-scope) Claude Opus 5 Codex GPT 5.6 Sol — truncating a dynamic VHDX to its virtual size would corrupt the container, and the destType != vhdx.Type guard on the resize block is the smallest way to express that. It also gets hcs its configured disk: size for the first time.
  • srcF.Close() before the rename fixes in-place conversion on Windows (in-scope) Claude Opus 5 Gemini 3.5 Flash — an open handle turns the delete into a pending-delete and the rename into ERROR_ACCESS_DENIED. The new in place subtest runs under go test ./... on the Windows CI job, so it pins the fix where it matters.
  • Output is built in a temp file and the signature is written last (in-scope) Codex GPT 5.6 Sol — an interrupted conversion leaves a file no prober recognizes as VHDX, rather than a half-written disk that looks valid.
  • Declaring raw and qcow2 removes a whole raw copy of every image (in-scope) Claude Opus 5 — from the download cache and the instance directory both. That saves more disk than dropping qemu-img does.

Review Process Notes ¶

Skill improvements

  • When the prompt directs agents to read a dependency's source in the module cache or any path outside their worktree, state that a sandboxed agent may be refused there and tell it to say so rather than proceed without the source. An agent that silently loses its reference material reviews the calling code against an assumed API.
  • Before accepting a reviewer's reproducer, check that the assertion in its repro block and the failure in its repro-output block describe the same outcome. A block asserting the value the code actually produces, paired with output claiming that assertion failed, is fabricated output, and the mismatch is visible without running anything.
  • When a finding rests on a file permission, a mode bit, or a similar POSIX attribute, check what the attribute means on the platform the changed code runs on before assigning severity. Go's Windows layer maps only the owner-write bit, so a mode difference that matters on Linux can be inert in a Windows-only driver.

Repo context updates

  • [repo] pkg/driver.DriverFeatures.SupportedImageFormats has exactly one consumer: pkg/instance/start.go passes it to the downloader, which converts a downloaded image to raw in the cache when its format is absent from the list. A driver therefore lists a format both to declare it bootable and to suppress that conversion. When reviewing a change to this field, check which of the two the author intends.
  • [repo] proxyimgutil.Convert tries qemu-img first only for a raw target; every other target goes straight to the native converter with no fallback. A change that makes a driver request a non-raw format therefore removes qemu-img as a safety net for every image feature the native reader does not implement, such as zstd-compressed qcow2 and VMDK.
  • [repo] driverutil.EnsureDisk renames an ISO instance image to iso and creates an empty data disk. That split is correct only for a driver whose VM configuration attaches filenames.ISO. When a driver adopts EnsureDisk, check its VM config for that attachment.
  • [repo] go-qcow2reader exposes VHDX through a stub: qcow2reader.Open detects the type and Size() returns -1, so any code that reads a size or converts from a VHDX source fails with unimplemented type. Treat a VHDX disk as write-only from Lima's side.
