## Executive Summary

The PR adds a repeatable `--sync-exclude` flag and a top-level `.limasyncignore` file to `limactl shell --sync`. This round applies round 2's fix, so the prompt's dry run now anchors exclude patterns at the same directory as the sync-back. Its shorter output paths expose a parser that skips short lines. With macOS's openrsync, an in-place edit to a top-level file with a one-letter name then goes uncounted, and if nothing else changed, the prompt deletes the guest's copy unsynced.

## Critical Issues

C1. **With openrsync, the dry run drops edits to one-letter top-level names** — `cmd/limactl/shell.go:954` [Codex GPT 6 Astra]

```go
		if len(line) < 12 {
			continue
		}
```

The parser skips every itemized line shorter than 12 characters. macOS ships openrsync as `/usr/bin/rsync`, which prints 9 attribute characters where GNU rsync prints 11, so an edit to a file named `a` gives the 11-character `>f.s..... a`. Until this round every name had a `proj/` prefix, because the dry run copied the synced directory itself; the trailing slash at line 903 drops it.

So when the guest's only change is an in-place edit of a top-level one-letter file, the stats come back empty, the prompt prints "No changes detected" (line 599), and the cleanup deletes the guest copy. Creating or deleting a file also changes the directory's mtime, whose `./` line has 12 characters. GNU rsync is unaffected (reasoned; the review host has only openrsync).

## Important Issues

I1. **The guest can rewrite `.limasyncignore`, and the next session pushes what it excluded** — `cmd/limactl/shell.go:991-993` [Claude Opus 5.5] raised as a design concern in round 2 by Claude Opus 5.5

```go
	if _, err := os.Stat(filepath.Join(nativeDir, ".limasyncignore")); err == nil {
		args = append(args, "--exclude-from", rsyncDir+"/.limasyncignore")
	}
```

Nothing excludes the filter file itself. The push copies it into the guest, and `rsyncBack` (lines 566-575) writes the guest's copy back over the host's. Under `--yes` or `--tty=false` nothing prompts, and in the TUI the change is one modified file among the agent's edits. rsync rereads the host copy on every call, so the current session stays filtered. The next `--sync` pushes everything the original file excluded.

Lima's threat model (`.oss-scanner/threat_model.md` on master) counts everything in the guest as attacker-controlled, including the files that `limactl shell --sync` brings back. The docs offer the feature for credentials (`ai.md:193-194`).

- **An explicit `--sync-exclude-from FILE` would remove I1 by construction** (in-scope) [Claude Opus 5.5] [Codex GPT 6 Astra]. A file outside the synced tree never reaches the guest. The maintainers have not chosen between it and the implicit file; see Unresolved Feedback.

## Review Process Notes

### Skill improvements

- When a change alters what a command prints, or the arguments that decide what it prints, re-read every consumer of that output against the new form at its shortest, on each implementation of the tool that users run. An unchanged parser with a length guard or fixed offsets can stop matching while the diff shows nothing near it.

### Repo context updates

- **[repo] UPDATE "Rsync invocations in `limactl shell --sync`"**: with excludes set there are five rsync calls, because the "View the changed contents" path also copies the host directory into a temporary tree. Replace the sentence about `getRsyncStats` passing the guest directory without the slash with the rule it implies: every call that passes the shared filters must give a source ending in `/` and the synced directory, not its parent, as the destination.
- **[repo]** `parseRsyncStats` reads `rsync --itemize-changes` output, and macOS ships openrsync as `/usr/bin/rsync`, which prints 9 attribute characters where GNU rsync prints 11. Flag any parsing of rsync output by line length or fixed offsets, and any parser fixture that covers only the GNU format.
- **[repo]** A filter file that decides what enters the guest must not travel through the guest. `limactl shell --sync` copies the guest's version of every synced file back over the host's, so a filter inside the synced tree needs its own exclusion, or must live outside the tree. Flag a guest-restricting config file inside a directory that the guest can write and that syncs back.
