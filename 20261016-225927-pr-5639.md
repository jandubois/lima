## Executive Summary

The hostagent now supervises the ssh ControlMaster, restarts it, and replays the guestSocket, static and SSH-forwarder TCP forwards, while Lima clients move to `ControlMaster=no`. The design holds, but the master's new keepalive options turn CI's test-misc job red. A keepalive timeout ends ssh without closing its channels, so every open mux session's stdio stays non-blocking, and Ansible then refuses to run. Every start also waits an extra 3 s, and no test reaches the foreign-master takeover.

## Critical Issues

C1. **A keepalive timeout leaves every open mux session's stdio non-blocking** — `pkg/hostagent/sshmaster.go:80-81`

```go
	args := []string{
		"-o", "ControlMaster=yes",
		"-o", "ControlPersist=no",
		"-o", "ServerAliveInterval=15",
		"-o", "ServerAliveCountMax=4",
	}
```

Each mux client hands the master its stdio, which the master keeps `O_NONBLOCK` until the session's channel closes (OpenSSH `channels.c:462-487`, `:577-587`). A keepalive timeout exits through `cleanup_exit` without closing channels, so the flag stays on every process sharing those descriptors.

The `test-misc.yaml` job fails all three attempts. After `limactl snapshot apply` rewinds the guest, the keepalive ends the master about 74 s later while `limactl shell cat /tmp/test` waits on it (`hack/test-templates.sh:702`). The job's stderr stays non-blocking, and the next `limactl start` dies with "Ansible requires blocking IO on stdin/stdout/stderr". At the merge-base, the master hung 9.6 minutes until its connection closed, and the job passed. Any script that pipes `limactl shell` can hit the same failure.

```python repro
    before = nonblock(w)
    end(server_pid, ctl)

    after = nonblock(w)
    try:

    reason = master.stderr.read().decode().strip().splitlines()
    print(f"{label}: master exit={master.returncode} ({reason[-1] if reason else 'no message'}); "

    os.close(r)
    os.close(w)

    os.kill(pid, signal.SIGTERM)

def hang_then_exit(pid, ctl):
```

I1. **Every start waits an extra 3 s for the master requirement** — `pkg/hostagent/sshmaster.go:108-110` [Claude Opus 5.5] [Gemini 3.1 Pro]


## Suggestions

S1. **The master's INFO-level stderr reaches `ha.stderr.log`** — `pkg/hostagent/sshmaster.go:177-180` [Claude Opus 5.5]

```go
		scanner := bufio.NewScanner(stderr)
		for scanner.Scan() {
			logrus.Infof("[SSH ControlMaster] %s", scanner.Text())
		}
```

The client options do not set `LogLevel`, so the master logs at INFO, and OpenSSH reports each forwarded connection that the guest refuses with `channel %d: open failed` (`channels.c:3721`). A docker CLI retrying against a stopped dockerd adds a line per attempt. At the merge-base, the ControlPersist master detached with its stderr on `/dev/null` (`ssh.c:1887`).

Fix: log these lines at Debug, and attach the last few to the `SSH ControlMaster exited` warning, where the exit reason matters.

S2. **`terminate` can outlast its own kill timeout** — `pkg/hostagent/sshmaster.go:325` [Codex GPT 6 Astra] [Claude Opus 5.5]

```go
	if cmd != nil {
		logrus.Debugf("shutting down the SSH master")
		if _, err := m.control(context.Background(), "exit"); err != nil {
			logrus.WithError(err).Warn("failed to exit SSH master")
		}
	}
	select {
	case <-m.done:
	case <-time.After(sshMasterExitTimeout):
```

The `-O exit` request runs on `context.Background()` before the 10 s timer starts, so a master whose mux listener never answers blocks `close()` before it reaches `cancelHA`. The merge-base's `ssh.ExitMaster` was just as unbounded.

The opposite case wastes the timer. A `terminate` that runs before `runOnce` stores `cmd` skips the request, and `runOnce` then starts a master anyway, so shutdown waits the full 10 s and logs "SSH master did not exit; killing it". A fake-ssh test that called `terminate` right after the first `start` took 10.0 s.

Fix: bound the request with `context.WithTimeout(…, sshMasterExitTimeout)`, and have `runOnce` check `stopped` under `m.mu` before `cmd.Start`.

S3. **A failed replay counts as done** — `pkg/hostagent/port.go:108` [Codex GPT 6 Astra] [Claude Opus 5.5]

```go
		if err := replayForwardTCP(ctx, pf.sshConfig, sshAddress, sshPort, local, intent.remote); err != nil {
			logrus.WithError(err).Warnf("failed to restore TCP forwarding %s -> %s", intent.remote, local)
		}
		intent.gen = gen
		pf.intents[local] = intent
```

Replay stamps the new generation whether or not the forward succeeded, so a forward that fails during replay (a host port still in use, a master that dies mid-replay) waits for the next restart. `replayGuestSockets` does the same (`hostagent.go:936`). The merge-base never re-created a forward at all, so this is a gap, not a regression.

Fix: stamp the generation only on success, and retry the failed forwards while the generation is current.

S4. **`runOnce` polls forever for a master that never serves the socket** — `pkg/hostagent/sshmaster.go:202-205` [Gemini 3.5 Flash]

```go
		case <-ticker.C:
			if m.isReady() {
				continue
			}
			pid, err := m.masterPID(ctx)
			if err != nil {
				continue
			}
```

When our ssh finds `ssh.sock` taken, it runs as a plain connection (`mux.c:1382-1387`). If the holder exits afterwards, it unlinks the socket (`ssh.c:1843-1844`), every `-O check` fails, and the loop polls with neither an exit nor a restart. `exitForeignMaster` narrows this to a race in which the foreign master outlives our ssh's authentication. ## Review Process Notes

### Skill improvements

- When a change alters how a long-lived child process ends (a new timeout, keepalive, signal, or kill fallback), compare the cleanup that each exit path runs. An abnormal exit often skips restoring state the process shares with others, such as file-descriptor flags, terminal modes, or lock and socket files, which the orderly path restores.

### Repo context updates

- An ssh ControlMaster sets `O_NONBLOCK` on the stdio that each mux client hands it and clears the flag only when it exits in an orderly way. A master that ends on a keepalive timeout, a fatal error or SIGKILL leaves those descriptors non-blocking for the client's parent and every later process sharing them, which breaks `ansible-playbook` in CI. Flag any change that lets the master exit that way while sessions may be open.
- The `test-misc.yaml` template job's online-snapshot step rewinds the guest under a live ssh master, so it is the one CI job where the master hangs and dies with a mux session open. Read its log for any change to the master's lifetime or exit path.
- Until the events watcher sets nxadm/tail's `CompleteLines`, a `limactl start` fatal "failed to unmarshal … as events.Event: unexpected end of JSON input" is an older partial-line race, not a regression of the PR under review.

###### Design Observations

###### Concerns

1. **CI Failure on Head Commit (`pkg/hostagent/events/watcher.go`)** `(in-scope)`:
   The `mcp` BATS failure (`level=fatal msg="failed to unmarshal ... as events.Event: unexpected end of JSON input"`) is caused by a **pre-existing race** in `pkg/hostagent/events/watcher.go:19-25`:
   - `haStdoutTail` is instantiated without `CompleteLines: true` in `tail.Config`. In `github.com/nxadm/tail/tail.go:245-251` and `352-358`, when `CompleteLines` is false and a read hits EOF before encountering a newline, `tail` sends the incomplete line fragment (`line, io.EOF`) directly onto `haStdoutTail.Lines`.
   - `events.Watch` assumes every line from `haStdoutTail.Lines` is a complete JSON document, so `json.Unmarshal` fails immediately when it encounters the truncated prefix (`{"time":"...","status":{"sshLocalPort":44227,"portForward":{"type":"fo`).
   - PR #5639 did not modify `events.Watch` or event emission logic in `emitEvent()`. However, because the SSH ControlMaster is now initialized earlier and faster in essential requirement 3, startup progresses more quickly into guest agent connect. The burst of guest agent port events ("Forwarding UDP ... / Not forwarding TCP ...") coincided with concurrent requirement progress writes, causing `tail` on an Azure CI runner to read a partial 97-byte buffer across a page boundary before the newline was committed. Setting `CompleteLines: true` in `pkg/hostagent/events/watcher.go:23` resolves this race.

2. **Value Against Size** `(in-scope)`:
   PR #5631 caps OpenSSH soft NOFILE at 1024 on macOS, preventing master deaths from `select()` file descriptor exhaustion under >1024 connections. PR #5639 adds ~600 lines of production logic to supervise the master as a child process. This additional weight buys:
   - Restoration of `guestSocket` forwards (such as `/var/run/docker.sock`) across host sleep/wake cycles, network drops, and idle flow reaping. On `vz`, guest agent traffic rides vsock and never breaks on sleep, so without this supervisor, dead socket forwards are never detected or healed.
   - Restoration of all TCP forwards when running with `LIMA_SSH_PORT_FORWARDER=true` (Colima's default mode).
   - Recovery from explicit master terminations (`limactl shell --reconnect`).
   - Diagnostic stderr capture from the master into `ha.stderr.log`.
   The supervisor approach is significantly more robust than periodic background liveness polling (such as in #5420's initial prototype), because standardizing clients on `ControlMaster=no` eliminates the race where a client like `limactl shell` starts an unmanaged master that lacks all forwards.

3. **Reverse-sshfs Mount Recovery Gap** `(future)`:
   On non-Windows hosts, reverse-sshfs mounts execute `sshfs` in the guest via a slave process multiplexed over the ControlMaster (`pkg/hostagent/mount.go:88`). When the master terminates and restarts, the slave session terminates and the guest mount is broken. `replayForwards` currently restores only `guestSockets` and TCP forwards; it does not remount reverse-sshfs. Either reverse-sshfs should disable multiplexing (as is already done on Windows hosts via `rsf.SSHConfig.Persist = false` and `DisableControlMasterOptsFromSSHArgs`), or the hostagent should orchestrate a remount upon master generation change.

###### Strengths

1. **Child Supervision over Daemonization**: Running the master with `ControlPersist=no` as a direct child of the hostagent allows `cmd.Wait()` to instantly signal termination, avoiding steady-state CPU polling or heuristic socket probing.
2. **Deterministic Client Multiplexing**: Configuring all Lima clients and `ssh.config` users with `ControlMaster=no` and the shared `ControlPath` elegantly allows clients to multiplex over the supervised master when running, while preventing any client from accidentally becoming a master without the managed forwards.
3. **Intent-based Port Replay**: Recording TCP forward intents with generation tracking (`intents map[string]tcpForwardIntent`) cleanly decouples port publications from master availability, allowing ports opened while the master is restarting to be forwarded seamlessly as soon as the new master is ready.
