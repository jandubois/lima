## Executive Summary

This round applies round 4's two patches. The guard now keeps the guest from creating `.limasyncignore` or writing a case alias over it, and a test pins the filtered host copy behind "View". Two problems remain. A `.limasyncignore` that links to a synced file, such as `.gitignore`, still lets the guest rewrite the filter for the next session. And because the guard is now unconditional, every "View" copies the whole host tree, even for a user with no excludes.

This push closes three of round 4's four paths, and the symlink path remains. `os.Stat` follows a symlink, so when `.limasyncignore` links to a synced file, such as `.gitignore` to reuse its rules, the guard protects the link but not the file. The guest writes `!` into `.gitignore`, the sync-back copies it to the host, and the next session pushes every file that the filter excluded. Lima's threat model (`.oss-scanner/threat_model.md`) treats guest root as the attacker. A hard link is safe, because rsync renames a new copy over `.gitignore`.

I2. **Every "View" now copies the whole host tree** — `cmd/limactl/shell.go:732-734` [Gemini 3.1 Pro] [Gemini 3.5 Flash] [Claude Opus 5.5] [Codex GPT 6 Astra]

```go

```

The guard makes `excludeArgs` non-empty in every session, so this early return never runs in production. The first "View" copies the host tree into `$TMPDIR` before it diffs, where the merge-base diffed the live directory (`shell.go:634` at `9e978f6f`). Without user filters the copy changes nothing in the diff. On a 622 MB tree of 12,461 files it took 7.0 s in the run below and 5.8 to 9.7 s in three earlier runs, with openrsync on macOS. It also doubles the temporary disk use, since the guest copy goes into the same directory. Round 4's patch noted this copy without measuring it.

## Suggestions

S1. **A lone `!` in the user's own filter clears the guard** — `cmd/limactl/shell.go:1001` [Claude Opus 5.5] [Codex GPT 6 Astra]


rsync reads a line holding only `!` as "clear every rule so far", and the guard comes first. ## Review Process Notes

### Skill improvements

- **Measure a side effect that a proposed patch discloses.** When a patch's own description names a cost it adds ("the patch also makes X always do Y"), run that path on a realistic input and state the cost in the finding before publishing the patch. Authors apply review patches as written, so a disclosed but unmeasured cost becomes the next round's regression.
- **Check whether a fix that rejects a policy input fails open.** When a fix refuses a filter, allowlist or other policy file because it is malformed or untrusted, check what happens to the protection that the file provided. A fix that skips the file silently removes that protection at once, which is worse than the attack that it blocks. Flag it and ask for an error instead.

I1. **Unconditional host tree copy on every "View" diff** — `cmd/limactl/shell.go:727-743` (important, regression)

```go
func hostTreeForDiff(ctx context.Context, cmd *cobra.Command, rsync copytool.CopyTool, hostCurrentDir, baseDir string, excludeArgs []string) (string, error) {
	if len(excludeArgs) == 0 {
		return hostCurrentDir, nil
	}
	dir := filepath.Join(baseDir, "host", filepath.Base(hostCurrentDir))
```

In `buildSyncExcludeArgs`, the hardcoded rule `--exclude /.[Ll][Ii][Mm][Aa]*...` is now appended unconditionally, so `excludeArgs` is never empty. As a result, `hostTreeForDiff`'s fast path (`if len(excludeArgs) == 0`) is unreachable. Every time the user selects "View the changed contents", the CLI copies the entire host directory to a temporary directory via `rsync`, even when no user excludes were provided and no `.limasyncignore` file exists. This imposes a severe performance and disk-space penalty for large projects.

Fix: Have `buildSyncExcludeArgs` return a boolean indicating if any *user-provided* rules or `.limasyncignore` file were found, and pass that flag to `hostTreeForDiff` to only perform the copy if it is true. 

I2. **Guest can bypass filter and overwrite a symlinked `.limasyncignore`** — `cmd/limactl/shell.go:999` (important, gap)

```go
	if _, err := os.Stat(filepath.Join(nativeDir, ".limasyncignore")); err == nil {
		args = append(args, "--exclude-from", rsyncDir+"/.limasyncignore")
	}
```

`os.Stat` follows symlinks. If the host's `.limasyncignore` is a symlink (e.g., to `.gitignore`), the guest can modify the target file to contain `!`. `rsync` interprets `!` in an exclude-from file as "clear all previous rules," erasing the hardcoded `--exclude /.[Ll][Ii]...` that precedes it. With the self-exclusion cleared, the guest can sync a regular file named `.limasyncignore` back to the host, permanently taking over the sync rules.

Fix: Use `os.Lstat` to reject symlinks: `if fi, err := os.Lstat(filepath.Join(nativeDir, ".limasyncignore")); err == nil && fi.Mode().IsRegular() { ... }`.

I2. **Symlinked `.limasyncignore` allows guest filter injection** — `cmd/limactl/shell.go:1005-1008` (important, gap)

```go

	}
	return args
```

`buildSyncExcludeArgs` uses `os.Stat` at line 1005, which follows symlinks. If `.limasyncignore` on the host is a symlink pointing to another file in the synced directory (e.g. `.gitignore`), the symlink target is transferred to the guest during initial sync. If a guest process writes `!` into that target, the guest's modification is synced back to the host at session exit. In subsequent sessions, rsync evaluates `--exclude-from` pointing to the modified file; the `!` token resets rsync's filter list, neutralizing all preceding `--exclude` options—including `--sync-exclude` and the internal ignore-file exclusion.

###### Design Observations

###### Concerns

- **Implicit `.limasyncignore` attack surface**: As discussed on PR #4917, introducing an implicit ignore file in user directories carries subtle security implications around symlinks, permission masking, and mid-session mutation. Supporting an explicit `--sync-exclude-from` flag instead would avoid unintended file parsing and give users direct control over which filter files are used. `(future)`

- **Filtered host copy scalability**: Copying the host directory for the diff view (`hostTreeForDiff`) scales with the size of the host working tree. In large codebases, copying the entire host tree into `/tmp` duplicates gigabytes of data. `(in-scope)`

###### Strengths

- **Case-insensitive pattern matching**: Using `/.[Ll][Ii][Mm][Aa]*[Yy][Nn][Cc][Ii][Gg][Nn][Oo][Rr][Ee]` effectively addresses APFS case-folding and Unicode variants like `ſ` (U+017F) without requiring platform-specific branching.
- **Consistent trailing-slash handling**: Unifying `syncBackPaths` between `rsyncBack` and `getRsyncStats` guarantees that anchored rsync filter rules match consistently during dry-run calculation and live execution.
