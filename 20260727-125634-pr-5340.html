	// An extended-length or device prefix spells a path the plain form also

Review Process Notes ¶

Skill improvements ¶

  • Re-verify a decline whose reason is a claim about code nobody opened. When a prior round declined a finding on the grounds that some helper, library, or subsystem "would never" produce the triggering value, open that code and confirm the guarantee exists. A decline resting on an assumed invariant is weaker than one resting on a measured one, and the assumption survives every later round unchecked because it sits in the resolution table rather than in the findings list.
  • Distrust an agent's citation of a CI log for a run still in progress. Hosted CI APIs commonly refuse whole-run logs until every job finishes, so a claim to have read a specific job's output can be unreproducible even when the job itself has passed. Verify the underlying fact from the workflow definition and the job's status instead, and report it by that route.
  • Treat an agent whose limitations section mirrors the prompt's own decline list as unverified. When a review restates injected context item for item and adds no measurement, its clean verdict carries no evidence. Say so in the retro rather than recording it as agreement, because several such agreements can otherwise look like convergence.
