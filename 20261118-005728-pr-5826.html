Executive Summary ¶

The PR adds networks[].guestToGuest: a Linux guest-agent watcher keeps a route through the vzNAT gateway, so vzNAT guests can reach each other. The wiring through validation, defaults, cidata, both init systems and CI is sound. Two things need fixing. A second address in the vzNAT subnet, or two vzNAT networks with the option, make the watcher rewrite its route without end. And embedding a base: template drops the option.

MissingRoutes wants one route per address, and it counts a route as present only when every field matches, PrefSrc and OIF included. But the kernel keeps one IPv4 route per destination, TOS and priority, and the watcher installs with NLM_F_REPLACE (watch_linux.go:220). So when two addresses want a route to one subnet, each install overwrites the other, and its netlink event starts the next round. Two inputs do this: a second address in the vzNAT subnet, and two vzNAT networks with guestToGuest, whose NICs both get 192.168.64.0/24 addresses (checked on a booted guest). The watcher then spins and logs added guest-to-guest route on every pass.

type installCounter struct{ n atomic.Int64 }

func (h *installCounter) Levels() []logrus.Level { return logrus.AllLevels }

func (h *installCounter) Fire(e *logrus.Entry) error {
	if strings.HasPrefix(e.Message, "added guest-to-guest route") {
		h.n.Add(1)
	}
	return nil
}

func probeSh(t *testing.T, cmd string) {
	t.Helper()
	if out, err := exec.Command("sh", "-c", cmd).CombinedOutput(); err != nil {
		t.Fatalf("%s: %v\n%s", cmd, err, out)
	}
}

// runWatcher runs the real watcher for 3 s and reports how often it installed the route.
func runWatcher(t *testing.T, interfaces []string) {
	hook := &installCounter{}
	logrus.AddHook(hook)
	logrus.SetOutput(io.Discard)
	ctx, cancel := context.WithTimeout(context.Background(), 3*time.Second)
	defer cancel()
	if err := Run(ctx, interfaces); err != nil {
		t.Fatal(err)
	}
	out, _ := exec.Command("ip", "-4", "route", "show").CombinedOutput()
	t.Logf("routes after 3 s:\n%s", out)
	t.Logf("route installs in 3 s: %d", hook.n.Load())
}

func TestProbeOneInterface(t *testing.T) {
	addrs := strings.Fields(os.Getenv("PROBE_ADDRS"))

}

Design Observations ¶

Concerns ¶

  • (future) The watcher stops for good after an unexpected receive error. Run returns on any Receive error other than ENOBUFS (watch_linux.go:45-51), and daemon_linux.go logs it once. The agent keeps running, but it never restores the route again. The review did not find a trigger for such an error in mdlayher/netlink v1.11.2. Redialing with a backoff would make the watcher recover. Claude Opus 5.5
  • (future) Every netlink event runs two full dumps. A burst of link, address and route events, such as a container runtime creating bridges, runs reconcile once per event. Coalescing events would cut the dumps. Gemini 3.5 Flash
  • (in-scope) plain: true makes guestToGuest inert without a message. Plain mode skips the boot.Linux/ scripts, so the guest agent never starts (pkg/cidata/cidata.TEMPLATE.d/boot.sh:73-74), and validation accepts the combination. fixUpForPlainMode already clears mounts, non-static port forwards and containerd without a warning, so clearing the field there, or warning in validateNetwork, would match the rest of plain mode. Found during consolidation.

Strengths ¶

  • MissingRoutes is a pure function in a file without build tags, so its tests run on every platform, and the netlink code stays in watch_linux.go. Claude Opus 5.5 Codex GPT 6 Astra Gemini 3.5 Flash
  • Events and requests use separate netlink sockets, the event socket is open before the first reconcile, and ENOBUFS triggers a full resync. Claude Opus 5.5 Codex GPT 6 Astra
  • Setting PrefSrc lets the kernel delete the route together with its address. Claude Opus 5.5
  • The watcher talks netlink directly instead of running ip route from the guest agent. Gemini 3.5 Flash

Acknowledged Limitations ¶

  • One guest in the BATS extra. GitHub's macOS runners lose contact when two hardware-accelerated guests run at once, and a QEMU guest cannot join a vzNAT network, so the extra checks the route in one guest. Do not re-suggest a test that starts two vz guests.

Review Process Notes ¶

Skill improvements

  • When a change adds a field to a struct, grep for every site that handles one of the field's siblings by name (merges, copies, clones, defaults, allow-lists of known fields) and check that each site handles the new field too. The site that drops it is usually outside the diff, where a review driven by the diff never looks.

Repo context updates

  • [repo] networks[] entries are merged field by field in two places. combineNetworks in pkg/limatmpl/embed.go merges base templates at embed time, and the named-network merge in limayaml.FillDefault merges the defaults and override files. A new networks[] field needs a case in both, and an entry in each driver's list of known network fields in its validateConfig.
  • [repo] The guest agent does not run in plain mode, because boot.sh skips the boot.<OS>/ scripts, so none of the guest agent's features work under plain: true. fixUpForPlainMode clears mounts, non-static port forwards and containerd without a warning. When a PR adds a guest-agent feature, check how it behaves in plain mode.
