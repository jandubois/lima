The default value of `sftpDriver` has been set to "openssh-sftp-server" since Lima v0.10, when an OpenSSH SFTP Server binary
such as `/usr/libexec/sftp-server` is detected on the host.
Lima prior to v0.10 had used "builtin" as the SFTP driver.

On Windows, unless `sftpDriver` is "builtin", Lima first looks for an sftp-server in the toolchain of the
`ssh.exe` it selected, either `sftp-server.exe` beside a native OpenSSH or `/usr/lib/ssh/sftp-server` for a

When the toolchain lookup finds one, the server and the host paths it serves come from the same install, which

Design Observations ¶

Concerns ¶

  1. pkg/sshutil now documents a dependency it does not import (in-scope) Claude Opus 5. pkg/sshutil/sshutil.go:224 asserts that sshocker rewrites a /c/... form to C:\..., and line 251 asserts that sshocker resolves the explicit binary through LookPath. I verified both against v0.3.11: convertMSYS2Path fires on len >= 3 && p[0] == '/' && p[2] == '/' (reversesshfs.go:337), and DetectDriver calls exec.LookPath on a non-empty explicit binary (reversesshfs.go:114-119). But pkg/sshutil does not import sshocker, so a version bump falsifies either comment without breaking the build. pkg/hostagent/mount.go constructs the ReverseSSHFS and is where a go.mod bump review would land.
  2. The single-toolchain invariant stops at the transport (future) Codex GPT 5.6 Sol Claude Opus 5 Gemini 3.5 Flash. sshocker's SSHConfig.Binary() is still a hardcoded return "ssh" in v0.3.11 (pkg/ssh/ssh.go:22-24, re-verified this round), so PATH picks the ssh that carries the mount while Lima pins the path form and the sftp-server. Closing this needs an upstream field. Carried from rounds 1 and 2.
  3. Three call sites still convert through the PATH-global helper (future) Gemini 3.5 Flash. cmd/limactl/shell.go:789, pkg/copytool/copytool.go:127, and pkg/limayaml/defaults.go:732 call fsutil.WindowsSubsystemPath, which runs a bare cygpath off PATH. Flash also named pkg/hostagent/mount.go and SSHOpts, which this commit and earlier work already moved off that helper.

Strengths ¶

  • The TestMain-as-fake-cygpath technique closes a branch that previously needed a real Cygwin install, and CI confirms it runs (in-scope) [all four reviewers]
  • exec.LookPath matches the resolution sshocker itself performs, so Lima cannot hand over a path the library will reject, and the comment at pkg/sshutil/sshutil.go:249-252 states that rationale correctly (in-scope) Claude Opus 5 Gemini 3.1 Pro Gemini 3.5 Flash
  • Extracting mountPathAndSftpServer gives the pairing one testable entry point, and the four subtests cover the driver cross-product rather than the happy path alone (in-scope) Claude Opus 5 Gemini 3.1 Pro
  • Caching sshExe on HostAgent reuses the value SSHOpts and writeSSHConfigFile already received, so the mount path cannot drift from the SSH config (in-scope) [all four reviewers]

Review Process Notes ¶

Skill improvements ¶

  • When a test exercises one branch of a two-way selector (a platform detector, a toolchain probe, a driver switch), check whether the same fixture would produce a different result through the other branch. A fixture that yields the same value either way asserts the function's output rather than the selection, so the test stays green after the selector itself regresses. The tell is a fixture whose inputs all sit in the one location both branches consult.
  • When a test replaces an external command with a fake binary or script, check whether the fake asserts the arguments it received. A fake that answers purely from configuration pins the return value and not the call, so a change to the command name, its flags, or its operand leaves the test passing. Weigh this higher when the ignored argument is also documented behavior, because the code and the documentation can then drift with nothing to catch it.
