I3. **Sudoers verification reports a file as current that sudo refuses to load** — `pkg/sudoers/sudoers.go:80` [Codex GPT 5.6 Sol]

```go
	return strings.Contains("\n"+withoutCommentLines(file)+"\n", "\n"+strings.TrimSpace(withoutCommentLines(fragment))+"\n")
```

The newline anchors added this round reject a line broadened with extra commands, which is what round 3's I3 asked for. But sudoers joins physical lines ending in a backslash into one logical rule, and the matcher doesn't. An active line ending in `\` above Lima's fragment splices the grant into the rule above, so `visudo` rejects the whole file while `ContainsActiveFragment` reports the grant present. Both `limactl sudoers --check` (`cmd/limactl/sudoers_darwin.go:129`) and the start-time check in `pkg/networks/sudoers.go` then answer "up-to-date" for a file sudo will not use. The merge-base compared the whole file byte for byte, so it rejected this input; the relaxation to containment is what admits it.

## Design Observations

### Concerns

**The per-VM cleanup goroutine cannot reach its own defer** *(in-scope)* [Codex GPT 5.6 Sol]. The `defer retainedFDs.CloseAll()` at `pkg/driver/vz/vm_darwin.go:109-111` guards a `for { select { … } }` loop with no `return` or `break` anywhere in its body, so it runs only when the goroutine is torn down with the process. Claude's coverage notes credited it as one of three working cleanup paths; that's wrong, though the other two (`vm_darwin.go:93` and `:99`, on the `createVM` and `Start` error paths) are reachable and do run. The merge-base had the same unreachable defer closing `vmNetworkFiles`, so the pattern predates this PR. It matters more now. `disk.md:156` says the whole-disk lock is held "until the VM stops", and that holds only because the hostagent process exits at the same moment.

**The grant names a device slot, not a disk** *(future)* [Claude Opus 5, Gemini 3.1 Pro]. `validateDiskDeviceIdentity` proves the descriptor is the node named a moment earlier, not that the node is the physical disk the user meant. `disk.md:121-123` states this, and macOS reassigns `/dev/diskN` by attach order. Keying the grant on a `diskutil` UUID resolved at open time is the durable answer, which the sudoers argv form cannot express today.

**Verification has three owners and no composed check** *(future)* [Claude Opus 5]. Unchanged from round 3: `pkg/networks` verifies its own fragment, `pkg/blockdevice` renders another, `pkg/sudoers` owns the matcher, and only `cmd/limactl` under `--check` knows the full expected content. I2, I3 and I5 all reduce to a single `sudoers.Verify(file, fragments...)`. @unsuman has signaled a follow-up refactor here, so this is the moment to agree on that interface.

### Strengths

- **All four strengths round 3 credited survive the rebase** *(in-scope)* [Claude Opus 5]. One copy of the argv pin and the `Lstat` → `O_NOFOLLOW` → post-open `Stat` chain in the helper binary, ACL detection on directories as well as files, per-VM rather than per-process descriptor retention with `processRetainedFDs` still serving krunkit's exported entry points, and a metacharacter blocklist that holds under `visudo -c`.
- **The socket handoff is authenticated in both directions before anything is sent** *(in-scope)* [Codex GPT 5.6 Sol, Gemini 3.1 Pro, Gemini 3.5 Flash]. `dialUnixPeer` checks the listener's UID before the nonce is written, and the receiver checks the sender's. The ordering is what closes the `Lstat`-to-connect race, and `TestDialUnixPeerAuthenticatesBeforeSending` pins it by asserting the server reads zero bytes.
- **Block devices are appended after additional disks** *(in-scope)* [Claude Opus 5]. `vm_darwin.go:649` keeps `cidata.diskDeviceNameFromOrder`'s `vd{b+i}` mapping intact. The opposite order would have remapped every existing instance's extra disks.
- **The generated network fragment is byte-identical to the merge-base** *(in-scope)* [Claude Opus 5]. So an installed `/etc/sudoers.d/lima` stays valid across the upgrade for users who have no block devices.

## Review Process Notes

### Skill improvements

- **When several agents propose the same fix for one line, check whether the line is deliberate before accepting the consensus.** Convergence measures how obvious a remedy looks, not whether the code is wrong. Read the comment at the site and the ordering constraint it states; a single dissenting agent that explains why the current form is correct outranks three that agree on the patch. Record the outcome as an acknowledged limitation with an explicit "do not re-suggest", so the next round does not re-derive the same consensus.

- **When a check is replaced rather than repaired, verify the replacement in every binary the build produces, then ask what the new predicate actually tests.** A guard moved from a compile-time constant to a runtime property fixes the reachability problem the prior round reported while introducing a different question: whether the runtime property identifies what the guard claims. Name the property (a filename, an environment variable, a path prefix), then construct the value that satisfies it wrongly and the value that fails it wrongly.

- **A verification command that reports "up to date" is a claim about a third-party parser, so test it against that parser.** Where code checks whether a configuration file already contains what a tool generates, the file's real grammar decides, and line-oriented string matching rarely matches it. Run the system's own validator over the constructed input and compare its verdict with the code's.

### Repo context updates

- **[repo] `flock` in Go binds to the open file description, so a second `os.OpenFile` on the same path conflicts inside one process.** Any Lima code that takes a per-resource lock in a loop over user-configured entries excludes itself when two entries map to one lock key. Check whether the caller can produce two entries with the same key before accepting such a loop.

- **[repo] `make artifact` builds neither privileged helper.** `ARTIFACT_DES` names `$(LIMA_DEPS)` and `$(HELPERS_DEPS)`, and neither includes `libexec/lima/privileged/`. `make native`, `make minimal`, `make binaries` and `make install` all do. When reviewing a change that adds a binary under `libexec`, run `make -n artifact | grep <name>` before crediting it as shipped.

- **[repo] `pkg/networks` sorts network names before rendering sudoers, with a comment saying why.** Any sibling renderer whose output is compared byte for byte against an installed file needs the same stable ordering. The comparison in `cmd/limactl/sudoers_darwin.go` is exact whenever `--block-device` is passed.

- **[repo] Lima has four registered `vmType` backends, not three.** `pkg/limatype/lima_yaml.go` lists `QEMU, VZ, WSL2, HCS`, and `pkg/driver/hcs` is Windows-only so it doesn't compile on a macOS or Linux review host. When a change adds per-driver validation, check all four; a `go build ./...` on the review host will not reveal the missing one.

- **[repo] Instance names starting with an underscore are reserved for Lima's own `${LIMA_HOME}` entries.** `pkg/limatype/filenames/filenames.go:10` states the rule and `_config`, `_disks`, `_networks` and `_templates` follow it. A new file written directly into `${LIMA_HOME}` should carry the prefix, a `filenames` constant, and an entry in `internals.md`'s layout section.

## Design Observations

**Concerns**

- **The grant is a device *slot*, not a disk, and nothing re-checks identity across reboots.** `validateDiskDeviceIdentity` (`block_device_darwin.go:302-312`) compares `st_rdev` between the received descriptor and an `Lstat` of the path taken immediately after — it proves the descriptor is the node named now, not that the node is the physical disk the user meant. `disk.md:121-123` states this. The durable fix would key the grant on a disk UUID (`diskutil info -plist`) resolved at open time, which the sudoers argv form cannot express today. `(future)`
- **The `--check` contract changes shape with a flag.** Presence-checking (tolerant) versus whole-file equality (strict) are two different questions, and which one `limactl sudoers --check` answers depends on whether `--block-device` was passed (I5). A single presence-checking implementation over every expected fragment would remove the branch and the order sensitivity. `(in-scope)`
- **`fd.Get` runs outside the connection's deadline.** `github.com/balajiv113/fd@v0.0.0-20230330094840` calls `via.File()` then a raw `syscall.Recvmsg`, which bypasses the `SetReadDeadline` set at `block_device_darwin.go:630`; only `ctx` cancellation unblocks `Open`, and the accept goroutine can outlive it. `PassFDToUnix` has used this package the same way since before the PR, so this is inherited, not introduced. `(future)`

**Strengths**

- All four round-3 strengths survive: one copy of the argv pin, the `Lstat` → `O_NOFOLLOW` → post-open `Stat` chain (`ServeSudoOpenBlockDevice:64-86`), per-component ACL detection on directories as well as files, and per-VM rather than per-process descriptor retention with `processRetainedFDs` preserved for krunkit's exported entry points.
- The generated sudoers text is byte-identical to the merge-base for the network fragment (four config shapes compared programmatically), so an installed `/etc/sudoers.d/lima` stays valid across the upgrade. A representative combined fragment passes `visudo -c -f`.
- Block devices are appended *after* additional disks in the storage list (`vm_darwin.go:649`), which keeps `cidata.diskDeviceNameFromOrder`'s `vd{b+i}` mapping intact — the opposite order would have silently remapped every existing instance's extra disks.
- The `stat == nil` guards added with the `osutil.SysStat` replacement correctly catch a typed-nil `Sys()`, which a plain `ok` check would not.

## Acknowledged Limitations

S1. **Avoid returning early in BATS teardown** — `hack/bats/extras/vz-block-device.bats:24`

#### Suggestions

##### S1. Duplicate block-devices validation checks string equality only — `pkg/limayaml/validate.go:505-507`

```go
		if slices.Contains(blockDevices[:i], blockDevice) {
			errs = errors.Join(errs, fmt.Errorf("field `%s` is a duplicate block device %q", field, blockDevice))
		}
```

The validation check only identifies duplicates via exact string matches. It does not detect Darwin-specific raw/block aliases (e.g. configuring `/dev/disk4` and `/dev/rdisk4` in the same list). While the lower-level driver locking (`lockHostBlockDevice` in `pkg/driver/vz/block_device_darwin.go:35`) successfully catches such overlap at startup and prevents the VM from booting, catching this in the earlier `pkg/limayaml` validation layer would provide a cleaner and faster validation error.

*Classification: gap*

Fix: Since `pkg/limayaml` is platform-agnostic, Darwin-specific normalization is best kept out of the core config parser. We suggest adding a warning or helper comment in `validateBlockDevices`, or accepting raw/block normalization as a minor gap.

##### S2. BATS test teardown aborts early on sudoers removal failure — `hack/bats/extras/vz-block-device.bats:25`

```bash
	# Revoke the grant before detaching: macOS can reuse this device number.
	remove_block_device_sudoers || return
```

In the BATS test teardown, if `remove_block_device_sudoers` fails (for example, if `sudo rm -f` fails or experiences a transient issue), the `|| return` statement immediately exits the `teardown()` function. This skips the subsequent RAM disk and partition unmounting and detaching steps (lines 26-32), leaving leaked loop/ramdisk devices attached to the host.

*Classification: gap*

Fix: Run the sudoers cleanup without aborting the teardown, allowing best-effort cleanup of all other resources:

```diff
-	remove_block_device_sudoers || return
+	remove_block_device_sudoers || :
```

### Design Observations

#### Concerns

None.

#### Strengths

- **Lifecycle-Scoped FD Retention:** Wrap-around file descriptors and whole-disk locks are registered under a per-VM `retainedFileDescriptors` instance. When a VM fails to start or terminates, `retainedFDs.CloseAll()` is guaranteed to execute, preventing descriptor and file-lock resource leaks.
- **Mutual Unix Socket Peer Authentication:** The unprivileged listener expects root credentials from the dialer; the root connector validates the unprivileged owner's UID on the listener. This prevents local hijackers from intercepting descriptors or feeding spoofed devices.
- **Device Node Rdev Identity Validation:** The caller validates the received descriptor using an `fstat` and matches its `Rdev` (major/minor numbers) against `Lstat(devicePath)`. This guarantees that the helper returned the exact device requested, closing path replacement races.

---

### Acknowledged Limitations

1. **Documented Data-Corruption Risks:** Explicitly documented in `website/content/en/docs/config/disk.md`. It warns against concurrent filesystem mounting and describes the boundary of `LIMA_HOME` locks (they do not coordinate host mounts or other users).
2. **Helper Descriptors Retained on Sudo Failure:** Explained in comments at `pkg/blockdevice/block_device_darwin.go:682`. If sudo fails, the listener does not wait to avoid hanging the foreground shell, leaving the socket to be cleaned up on close.
3. **Guest Device Name Variations:** Documented in `pkg/driver/vz/block_device_darwin.go:94`. The stable identifier in `/dev/disk/by-id` is utilized since guest devfs node naming can be non-deterministic.
4. **ACL Rejections on Network Helper Deferred:** Handled in separate, post-rebase networks-specific PRs as agreed with upstream maintainers.
