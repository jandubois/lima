## Executive Summary

The PR adds `networks[].guestToGuest`: a Linux guest-agent watcher keeps a route through the vzNAT gateway, so vzNAT guests can reach each other. The wiring through validation, defaults, cidata, both init systems and CI is sound. Two things need fixing. A second address in the vzNAT subnet, or two vzNAT networks with the option, make the watcher rewrite its route without end. And embedding a `base:` template drops the option.

## Important Issues

I1. **Two wanted routes share one kernel slot, so the watcher rewrites its route without end** — `pkg/guestagent/guesttoguest/route.go:69-75` [Claude Opus 5.5, Codex GPT 6 Astra, Gemini 3.1 Pro, Gemini 3.5 Flash]

```go
		// A route to the subnet with another gateway, priority or source
		// counts as missing. Our own route must therefore parse back equal
		// to want; otherwise the netlink event that adding it causes would
		// trigger another write.
		if !slices.Contains(routes, want) {
			missing = append(missing, want)
		}
```

`MissingRoutes` wants one route per address, and it counts a route as present only when every field matches, `PrefSrc` and `OIF` included. But the kernel keeps one IPv4 route per destination, TOS and priority, and the watcher installs with `NLM_F_REPLACE` (`watch_linux.go:220`). So when two addresses want a route to one subnet, each install overwrites the other, and its netlink event starts the next round. Two inputs do this: a second address in the vzNAT subnet, and two vzNAT networks with `guestToGuest`, whose NICs both get 192.168.64.0/24 addresses (checked on a booted guest). The watcher then spins and logs `added guest-to-guest route` on every pass.

```go repro
func (h *installCounter) Levels() []logrus.Level { return logrus.AllLevels }

func (h *installCounter) Fire(e *logrus.Entry) error {
	if strings.HasPrefix(e.Message, "added guest-to-guest route") {

func probeSh(t *testing.T, cmd string) {
	t.Helper()
	if out, err := exec.Command("sh", "-c", cmd).CombinedOutput(); err != nil {
		t.Fatalf("%s: %v\n%s", cmd, err, out)
	}
}

// runWatcher runs the real watcher for 3 s and reports how often it installed the route.
func runWatcher(t *testing.T, interfaces []string) {
	hook := &installCounter{}
	logrus.AddHook(hook)
	logrus.SetOutput(io.Discard)
	ctx, cancel := context.WithTimeout(context.Background(), 3*time.Second)
	defer cancel()
	if err := Run(ctx, interfaces); err != nil {
		t.Fatal(err)
	}
	out, _ := exec.Command("ip", "-4", "route", "show").CombinedOutput()
	t.Logf("routes after 3 s:\n%s", out)
	t.Logf("route installs in 3 s: %d", hook.n.Load())
}

// One interface; PROBE_ADDRS lists its addresses.
func TestProbeOneInterface(t *testing.T) {
	addrs := strings.Fields(os.Getenv("PROBE_ADDRS"))
	if len(addrs) == 0 {
		t.Skip("set PROBE_ADDRS and run as root under unshare --net")

	}
	probeSh(t, "ip route add default via 10.9.0.1 dev g2g0 metric 100")
	runWatcher(t, []string{"g2g0"})
}

// Two interfaces on one subnet, as two vzNAT networks in one guest.
```

## Design Observations

### Concerns

- **(future) The watcher stops for good after an unexpected receive error.** `Run` returns on any `Receive` error other than `ENOBUFS` (`watch_linux.go:45-51`), and `daemon_linux.go` logs it once. The agent keeps running, but it never restores the route again. The review did not find a trigger for such an error in mdlayher/netlink v1.11.2. Redialing with a backoff would make the watcher recover. [Claude Opus 5.5]
- **(future) Every netlink event runs two full dumps.** A burst of link, address and route events, such as a container runtime creating bridges, runs `reconcile` once per event. Coalescing events would cut the dumps. [Gemini 3.5 Flash]
- **(in-scope) `plain: true` makes `guestToGuest` inert without a message.** Plain mode skips the `boot.Linux/` scripts, so the guest agent never starts (`pkg/cidata/cidata.TEMPLATE.d/boot.sh:73-74`), and validation accepts the combination. `fixUpForPlainMode` already clears mounts, non-static port forwards and containerd without a warning, so clearing the field there, or warning in `validateNetwork`, would match the rest of plain mode. Found during consolidation.

### Strengths

- `MissingRoutes` is a pure function in a file without build tags, so its tests run on every platform, and the netlink code stays in `watch_linux.go`. [Claude Opus 5.5, Codex GPT 6 Astra, Gemini 3.5 Flash]
- Events and requests use separate netlink sockets, the event socket is open before the first reconcile, and `ENOBUFS` triggers a full resync. [Claude Opus 5.5, Codex GPT 6 Astra]
- Setting `PrefSrc` lets the kernel delete the route together with its address. [Claude Opus 5.5]
- The watcher talks netlink directly instead of running `ip route` from the guest agent. [Gemini 3.5 Flash]

## Acknowledged Limitations

- **One guest in the BATS extra.** GitHub's macOS runners lose contact when two hardware-accelerated guests run at once, and a QEMU guest cannot join a vzNAT network, so the extra checks the route in one guest. Do not re-suggest a test that starts two vz guests.
- **`--guest-to-guest-interfaces` and its value as one argument string.** `generateSystemdUnit` builds `--vsock-port`, `--virtio-port` and `--socket-owner` the same way, and systemd splits `ExecStart` on spaces. Do not re-suggest the `=` form as matching the neighbouring flags.

### [Gemini 3.5 Flash]

###### Executive Summary

This PR introduces `networks[].guestToGuest` to enable vzNAT guests to communicate by maintaining an onlink subnet route through the host gateway via a Linux guest-agent watcher. The implementation is clean and avoids shelling out, but `MissingRoutes` triggers an infinite route-replacement oscillation loop when multiple IPv4 addresses share a subnet on the link, and `pkg/limatmpl/embed.go` omits `guestToGuest`, silently dropping the option when a template extends a base template.

###### Important Issues

I1. **Infinite route-replacement oscillation when multiple IPv4 addresses share a subnet** — `pkg/guestagent/guesttoguest/route.go:57-77` (important, regression)

```go
	var missing []Route
	for _, a := range addrs {
		if a.Index != index || !a.Prefix.Addr().Is4() || a.Prefix.Bits() >= 31 {
			continue
		}
		subnet := a.Prefix.Masked()
		if !subnet.Contains(gateway) {
			continue
		}
		want := Route{
			Dst:      subnet,
			Gateway:  gateway,
			OIF:      index,
			Priority: 0,
			PrefSrc:  a.Prefix.Addr(),
		}
		// A route to the subnet with another gateway, priority or source
		// counts as missing. Our own route must therefore parse back equal
		// to want; otherwise the netlink event that adding it causes would
		// trigger another write.
		if !slices.Contains(routes, want) {
			missing = append(missing, want)
		}
	}
	return missing
```

In `route.go:57-77`, `MissingRoutes` loops over all link addresses `addrs` and builds a `want` route keyed with `PrefSrc: a.Prefix.Addr()`. The Linux kernel routing table for IPv4 only stores a single route for a given destination prefix and metric in `unix.RT_TABLE_MAIN`.

When an interface has multiple IP addresses on the same subnet (e.g. secondary IP, VIP, or during a DHCP address reassignment), `MissingRoutes` generates competing `Route` objects for the same `Dst: subnet` with different `PrefSrc`. Installing one replaces the other via `netlink.Create | netlink.Replace` (`watch_linux.go:785`). That replacement generates an `RTM_NEWROUTE` netlink event, which wakes `events.Receive()` (`watch_linux.go:44-55`) and triggers `reconcile` (`watch_linux.go:68`). On the next iteration, the route with the other `PrefSrc` is now missing, so it is installed and displaces the first. This creates a perpetual 100% CPU live-lock oscillating between the addresses and flooding system logs.

```go repro

	subnet := netip.MustParsePrefix("192.168.64.0/24")
	gw := netip.MustParseAddr("192.168.64.1")
	self1 := netip.MustParseAddr("192.168.64.6")
	self2 := netip.MustParseAddr("192.168.64.10")

	addrs := []Address{
		{Index: lima0, Prefix: netip.MustParsePrefix("192.168.64.6/24")},
		{Index: lima0, Prefix: netip.MustParsePrefix("192.168.64.10/24")},
	}

		Dst:      netip.PrefixFrom(netip.IPv4Unspecified(), 0),
		Gateway:  gw,
		OIF:      lima0,
		Priority: 100,
	}
```

In `pkg/limatmpl/embed.go:537-564`, `combineNetworks` merges network list entries when templates extend a base template (`base:`). Unlike struct merging via reflection, `combineNetworks` copies explicitly hardcoded fields (`lima`, `socket`, `macAddress`, `vzNAT`, `metric`).

Because `guestToGuest` was not added to `combineNetworks`, any template deriving from a base template that defines `guestToGuest: true` (or using wildcard interface matching `interface: "*"`) silently loses the `guestToGuest` configuration when `limactl create`, `limactl start`, or `limactl template copy --embed-all` executes `tmpl.Embed()`. `dest.GuestToGuest` remains `nil` and later defaults to `false`.

###### Design Observations

###### Concerns

- **Synchronous unthrottled netlink reconciliation (`pkg/guestagent/guesttoguest/watch_linux.go:44-55`)** `(future)`:
  `guesttoguest.Run` listens on `RTMGRP_LINK | RTMGRP_IPV4_IFADDR | RTMGRP_IPV4_ROUTE` and immediately runs a full address and route dump on every event. During interface setup or network reconvergence (e.g. link flapping, DHCP renewal, multiple route insertions), netlink generates bursts of dozens of events in milliseconds. Introducing a short debounce or coalesce window (e.g. 50ms) before invoking `reconcile` would reduce dump churn against the kernel netlink socket.

###### Strengths

- **Direct netlink interface without shell execution**:
  Interacting with the kernel FIB directly via `github.com/mdlayher/netlink` avoids shelling out to `ip route` or parsing command-line text inside the guest agent daemon, keeping execution fast and secure.
- **Clear separation of pure routing logic from netlink I/O**:
  `MissingRoutes` in `route.go` is an entirely pure function without OS dependencies or global state. This enabled thorough cross-platform unit testing on Darwin and Windows without requiring a live Linux kernel.

###### Testing Assessment

- **I1** is required under check 3 ("How would a user see it?"): An infinite live-lock consuming 100% CPU and writing thousands of log messages is a severe failure mode that cannot be diagnosed without inspectable logs. Added unit reproducer in `route_test.go` verifies the oscillation.
- **I2** is required under check 1 ("Does an existing test catch it?"): No existing test exercised `tmpl.Embed()` on a base template setting `guestToGuest`, allowing the field to be silently dropped during template inheritance.
- **S1** is optional under check 2 ("Does the code run only for us?"): BATS extra test suite helper.

###### Documentation Assessment

- `templates/default.yaml` and `website/content/en/docs/dev/internals.md` accurately document `networks[].guestToGuest` and `LIMA_CIDATA_GUEST_TO_GUEST_INTERFACES`.
- As planned by maintainers, user-facing documentation in `vznat.md` is intentionally deferred until PR #5825 merges.
