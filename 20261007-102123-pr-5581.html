Acknowledged Limitations ¶

  • External drivers from the registry still ignore hostLoopback: false. The author agreed and deferred a driver feature flag to a follow-up.
  • krunkit, user-v2 and QEMU's disable_host_loopback are deferred, and each rejects false.
  • A host service bound to all interfaces stays reachable through the host's LAN IP (templates/default.yaml:700-701). The change does not make that worse.
  • With the refusals in Validate, limactl create on an unsupported driver writes the instance, and limactl start then refuses it; limactl edit can clear the setting. Round 1 accepted this as the cost of a deletable instance.
  • Do not re-suggest moving the refusals into limayaml.Validate. It runs on every load (pkg/store/store.go:127), so the instance would become unlistable and undeletable.
  • Do not re-suggest remapping the gateway to 127.0.0.2 or 240.0.0.1. On macOS both time out instead of failing at once (round 1 measured 75 s and over 5 s).
  • Do not re-suggest mapping 127.0.0.1 in natTable, or documenting a route_localnet bypass. gvisor drops packets from the guest addressed to 127/8 unless AllowExternalLoopbackTraffic is set (gvisor pkg/tcpip/network/ipv4/ipv4.go:840-849), gvisor-tap-vsock v0.8.9 never sets it, and a frame probe to 127.0.0.1 reached nothing.
  • Do not re-raise the qemu Validate panic on a nil config. CreateConfiguredDriver dereferences inst.Config (pkg/driverutil/instance.go:22) before any driver method runs, and on macOS the merge-base panics on a nil config too, in validateArch.

Review Process Notes ¶

Skill improvements ¶

  • When rating a missing test for a guard, rate the guard's deletion as well as its relocation. A refusal whose deletion leaves an option silently ignored needs a test, even when moving it to the wrong place would fail loudly with an error naming the cause.

Repo context updates ¶

  • [repo] ADD: vz and krunkit each start their own in-process gvisor-tap-vsock netstack, each from its own startUsernet with its own GVisorNetstackOpts literal. An option wired into one does not reach the other, so a driver that refuses a vz-only network option depends on that refusal alone. Check both call sites when a change touches GVisorNetstackOpts.
  • [repo] ADD: gvisor, as gvisor-tap-vsock v0.8.9 configures it, drops packets from the guest with a 127/8 source or destination (AllowExternalLoopbackTraffic is unset) and does not register an IPv6 protocol. A guest cannot reach host loopback by addressing 127.0.0.1 directly, whatever routes it adds; the paths to host loopback are the NAT table's entries and UDP to 0.0.0.0, which macOS treats as a dial to its own loopback.
  • [repo] ADD: driverutil.CreateConfiguredDriver dereferences inst.Config before any driver method runs, so a driver's Configure and Validate always see a non-nil config in production. Rate a nil-config crash inside a driver method as latent, not as a regression.
