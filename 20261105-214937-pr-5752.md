## Executive Summary

The PR copies the guest's synced directory into a host snapshot before the prompt, so the statistics, the diff and "Yes" all read what the user reviewed. That closes the race. But the copy now runs on every tty session, and it causes four regressions. Each session sends the whole tree over SSH (I1), a read-only guest directory leaves the copy behind (I2), a TMPDIR inside the project makes "Yes" fail halfway (I3), and a case-sensitive project loses files (I4).

I2. **A read-only directory in the guest tree leaves the snapshot behind** — `cmd/limactl/shell.go:608` [Claude Opus 5.5, Gemini 3.5 Flash]

```go
	defer func() {
		if err := os.RemoveAll(baseDir); err != nil {
			logrus.WithError(err).Warnf("Failed to clean up temporary directory %s", baseDir)
		}
	}()
```

`-a` gives the snapshot the guest's directory modes. When the guest tree holds a read-only directory, such as a Go module cache, `os.RemoveAll` cannot unlink its entries. Every session then warns and leaves a copy of the guest tree in TMPDIR, including content that the user rejected. At the merge-base only "View" made that copy. The probe's writable directory is the control.

## Review Process Notes

**Skill improvements**

- When a change stages data in an intermediate location before applying it to a destination (a temporary directory, a cache, a snapshot), check that location against the destination. Ask whether it can sit inside the destination, where the apply step's cleanup or `--delete` reaches it; whether it shares the destination's filesystem semantics, such as case sensitivity, links and permissions; and whether cleanup can remove everything that the copy preserved, read-only modes included. A staging copy takes the properties of the filesystem that it is written to, which need not match the source's or the destination's.
- When a change moves work from an optional path onto the default one, such as a copy that ran only on request and now runs every time, measure its cost on a realistic input, including the runs where the work turns out unnecessary.

**Repo context updates**

- [repo] macOS's `/usr/bin/rsync` is openrsync, whose `--link-dest` hard-links a basis file even when its mode differs from the sender's, so a copy built with it can show the host file's mode instead of the guest's. Flag `--link-dest` on any copy that must match the guest; `--copy-dest` saves the same transfer without links.
- [repo] On a macOS host `os.TempDir()` is on the boot volume, which is case-insensitive APFS by default even when the synced project is on a case-sensitive volume. A host-side copy of guest data under TMPDIR merges names that differ only in case, so flag one that is later applied to the project with `--delete`.
- [repo] Every `limactl shell --sync` call in the BATS suite passes `--yes` or `--tty=false`, so no BATS test reaches the interactive sync-back (the statistics, the prompt, "View" and "Yes"). Only unit tests cover a change there, so ask for one that drives the prompt.
