Executive Summary ¶

The PR resumes interrupted cache downloads from a stable data.part with Range and If-Range, and the design holds: the existing lock gives each URL one writer, and resume needs a digest and a cached validator. One branch breaks the digest's guarantee. A 206 that answers a request without Range appends to the stale partial, but the digest covers only the new bytes, so a hostile server or an on-path attacker gets its bytes cached as verified.

// cached on disk. It is sent as If-Range so the server only serves a partial

func ifRangeValidator(etagPath, timePath string) string {

		return etag

	return readFile(timePath)
}

Design Observations ¶

Concerns ¶

  • (future) time has two jobs, and one of them already misfires. Claude Opus 5.5 For a cache entry without a digest, time tells getCached whether data is stale; this PR also makes it the If-Range validator for data.part, so it has to be written before the body. Review Process Notes ¶

Citation lint ¶

  • I2 cites commit 335f6139, which has no file to cite, so the citation lint reports one unresolved reference. That is deliberate.

Skill improvements ¶

  • When a finding needs a peer to break the protocol (a 206 nobody asked for, a malformed header, an out-of-range length), rate it by what a hostile peer gains whenever the threat model treats that peer as untrusted, such as a download server, a mirror, a guest or the network. "No honest server does this" lowers the likelihood only for honest peers, and an integrity check that a hostile peer can step around is the bug that the check exists to stop.

Repo context updates ¶

  • [repo] Several bundled image URLs reach plain HTTP or third-party hosts. Archived Ubuntu releases redirect to http://cloud-images-archive.ubuntu.com, which covers the default templates of Lima v2.0.0 and v2.1.0 and, I expect, of each later release once its pinned image ages out; the freebsd and freebsd-15 templates use http:// directly; Fedora, openSUSE and Debian URLs redirect to third-party mirrors. The template digest is the only integrity check on these downloads, so any downloader path that lets bytes reach the cache without being hashed is open to an on-path attacker or a hostile mirror.
  • [repo] GitHub release assets ignore If-Range and answer a Range with 206 even when If-Range does not match, while Ubuntu, Debian, Fedora and openSUSE honor it. A resume path that relies on If-Range to detect a changed file gets no such protection from GitHub-hosted downloads.
  • [repo] To run limactl prune --keep-referred or any template walk against a scratch LIMA_TEMPLATES_PATH, use a directory without experimental/fedora-rawhide.yaml: its fedora-rawhide: base needs the limactl-url-fedora-rawhide plugin from libexec/lima, and a bare go build of limactl without it fails the whole walk.
