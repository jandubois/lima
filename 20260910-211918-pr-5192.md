S3. **The macOS QEMU BATS step has no retry for its VM boot** — `.github/workflows/test.yml:310` [Claude Opus 5]

```yaml
    - name: "Run BATS port-forwarding test (QEMU, macOS host)"
      run: ./hack/bats/lib/bats-core/bin/bats --timing ./hack/bats/tests/port-forwarding.bats
      env:
        LIMA_BATS_ALL_TESTS_RETRIES: "2"
```

The step above runs `test-templates.sh` under `nick-fields/retry` with three attempts; its comment says "GHA macOS is slow and flaky". This step boots a second VM in `local_setup_file`, and `LIMA_BATS_ALL_TESTS_RETRIES` doesn't reach it. In a probe with retries at 2, a test that failed once ran again and passed, while a `setup_file` that failed once ran once and failed the file. So a boot flake that the template step's retry would absorb now fails the job.

The case against: a retry wrapper hides failed attempts from the failure sweep, and the vz job retries neither of its steps. Nobody has measured how often macOS QEMU boots fail.

Fix: wrap the step in `nick-fields/retry` like the one above. The action spawns its command with the inherited environment (`src/index.ts:82` at the pinned SHA), so the step's `env:` still reaches bats.

## Design Observations

### Concerns

- **Retried tests reuse the first attempt's state** *(in-scope)* [Claude Opus 5]. Both macOS BATS steps set `LIMA_BATS_ALL_TESTS_RETRIES: "2"`. `wait_for_port_forwarding_event` searches the events file from the top (`hack/bats/tests/port-forwarding.bats:323-325`), so a retry finds the first attempt's event. If the first attempt's `socat` still listens, the retry's `socat` fails to bind with its stderr discarded (line 313), while its redirect truncates the shared output file. A retry therefore re-checks delivery but never that the event fires again. Sketch: record the events file's line count in `local_setup`, search only later lines, and kill the test's listener in `local_teardown`.

### Strengths

- The reuse fix waits only under `LIMA_BATS_REUSE_INSTANCE`, and its comment names the 3-second snapshot diff it waits out [Claude Opus 5] *(in-scope)*.
- The embed guard turns a template stub that silently drops the 8888 rule into a setup error [Claude Opus 5, Gemini 3.1 Pro] *(in-scope)*.
- The watcher gate now checks attachment as well as readiness, so a watcher that tails nothing fails setup instead of timing out every test [Claude Opus 5] *(in-scope)*.
