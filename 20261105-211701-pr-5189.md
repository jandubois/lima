I1. **`mount.md` says the guest skips a UNC location, but without a `mountPoint` the host rejects it** — `website/content/en/docs/config/mount.md:159` [Codex GPT 6 Astra, Gemini 3.5 Flash, Claude Opus 5.5]


## Suggestions

S1. **The rerun branch remounts any filesystem at the mount point, including one Lima did not create** — `pkg/driver/wsl2/boot.Linux/03-wsl-mounts.sh:134` [Codex GPT 6 Astra, Claude Opus 5.5, Gemini 3.5 Flash, Gemini 3.1 Pro]

```sh
	if mountpoint -q "$mountpoint"; then
		if [ "$writable" = "0" ]; then
			if is_exact_ro_mount "$mountpoint"; then
				INFO "$mountpoint is already mounted read-only, skipping"
			else
				INFO "Remounting existing mount at $mountpoint as read-only"
				if mount -o remount,ro,bind "$mountpoint" 2>/dev/null; then
```

The round-2 S4 fix treats any mount at `$mountpoint` as Lima's own bind and flips its flags to match `writable`. When a custom `mountPoint` is already a mount, such as the WSL-owned `/mnt/wsl` or `/usr/lib/wsl/lib`, line 140 or line 149 changes that filesystem's flags, the location never gets mounted, and the log says only "Remounting existing mount". Before this round the branch skipped such a mount point and left it alone. Codex's probe, with a `mountpoint` stub that always succeeds, counted one remount request where it expected none. Only an unusual configuration reaches this, so it stays a Suggestion.

Fix: compare the existing mount's source with `$wsl_path` before changing flags, and warn on a mismatch. Nobody has checked what `findmnt` reports as the source of a bind from drvfs, so a patch needs a WSL guest to verify it.

S2. **A missing host directory still leaves a symlink that the next boot binds through** — `pkg/driver/wsl2/boot.Linux/03-wsl-mounts.sh:178` [Codex GPT 6 Astra, Claude Opus 5.5, Gemini 3.1 Pro, Gemini 3.5 Flash]

```sh
			rmdir "$mountpoint" 2>/dev/null || true
			if [ ! -e "$mountpoint" ] && [ ! -L "$mountpoint" ]; then
				if ln -sfn "$wsl_path" "$mountpoint"; then
```

Round 2's S3 is only partly fixed. `ln` is now checked, and an existing link is no longer replaced. But `Validate` only warns about a location that does not exist yet, so the bind at line 157 fails and line 178 creates a dangling link. Once the directory exists, `mountpoint -q` is false for the link and `mount(8)` canonicalizes its target, so line 157 binds the source onto itself. With `writable: false`, line 159 then makes the native `/mnt/<drive>` path read-only. Codex's probe counted one remount of the source after it appeared, and none for a fresh directory. Nobody ran this in a WSL guest.

Fix: before line 155, skip the entry with a warning when `$wsl_path` is not a directory, or create it first as the reverse-sshfs hostagent does (`pkg/hostagent/mount.go:62`).

S3. **Sorting by mount point can resolve one entry's source through another entry's mount** — `pkg/driver/wsl2/boot.Linux/03-wsl-mounts.sh:60-62` [Codex GPT 6 Astra]

```sh
for i in $(for j in $(seq 0 $((LIMA_CIDATA_MOUNTS - 1))); do
	eval "printf '%s\t%s\n' \"\${LIMA_CIDATA_MOUNTS_${j}_MOUNTPOINT}\" $j"
done | LC_ALL=C sort | cut -f2); do
```

The sort orders destinations only. Take `C:\data\child` at `/srv/child` and `D:\replacement` at `/mnt/c/data`. The second entry now mounts first, so the bind for `/srv/child` resolves `/mnt/c/data/child` through it and exposes the D: files. In list order the same configuration came out right; Codex's probe shows both orders. A mount point that shadows a native drive path is rare, so this stays a Suggestion.

Fix: warn and skip an entry whose mount point covers another entry's source, unless the covering entry is a self-bind of its own native path.

S4. **The new comment says the octal escape avoids disabling SC1003, but line 17 still disables it** — `pkg/driver/wsl2/boot.Linux/03-wsl-mounts.sh:84` [Claude Opus 5.5]

```sh
			# \134 is octal for backslash; avoids SC1003 without disabling rules
			rest=$(printf "%s" "$cleaned_loc" | cut -c3- | tr '\134' '/')
```

Line 17 disables SC1003 for `BACKSLASH='\'`, which the trim loop at line 78 still compares against. With the directive removed, shellcheck reports SC1003 at line 18, so the file avoids the rule in one place and disables it in another.

Fix: shorten the comment to `\134 is octal for backslash`.

## Design Observations

### Concerns

- **What `writable: false` means on wsl2 is still unruled** (in-scope) [Claude Opus 5.5, Codex GPT 6 Astra]. Round 1 left it to the maintainers, and the PR comments record no ruling since. The source stays writable under `/mnt/<drive>`, the user has passwordless sudo, and interop runs Windows programs, so a read-only bind guards against mistakes only.
- **An existing wsl2 instance whose mount point cannot be defaulted becomes unloadable, and deleting it leaves the distro registered** (in-scope) [Codex GPT 6 Astra, Claude Opus 5.5]. This corrects round 2, which said such an instance shows as Broken. `Inspect` records the validation error and keeps `StatusUnknown` (`pkg/store/instance.go:71,86-87`). `limactl delete` refuses an instance that is not stopped unless given `--force` (`pkg/instance/delete.go:21-22`). Even then, `Delete` skips `unregister` whenever `inst.Errors` is non-empty (`:27-31`), so `lima-<name>` stays registered with WSL. The commit message does not mention the stricter validation.
- **The script changes mounts while it still reads the mount table for later decisions** (in-scope) [Codex GPT 6 Astra]. S1, S2 and S3 share that cause. Translating every source and checking for overlaps first, then mounting, would address all three.
- **The translator hard-codes `/mnt`** (future) [Claude Opus 5.5, Codex GPT 6 Astra]. With a custom `[automount] root`, `wslpath` and the default mount point disagree. (raised in round 2 by all four agents)

### Strengths

- Splitting the bind from the remount means each failure undoes only what its own iteration did. [Claude Opus 5.5, Codex GPT 6 Astra, Gemini 3.5 Flash]
- Sorting on `mountpoint<TAB>index` puts every parent first in one pipeline, because a tab sorts below every printable byte. [Claude Opus 5.5, Gemini 3.1 Pro, Gemini 3.5 Flash]
- Moving the nil check below the location checks keeps both diagnostics, and `TestValidateMountRelativePathWithoutMountPoint` fails when the check moves back. [Codex GPT 6 Astra, Claude Opus 5.5, Gemini 3.5 Flash]

When `mount --bind` fails (e.g., if the host path is temporarily unavailable), the script falls back to creating a symlink at `$mountpoint`. Because the WSL rootfs is persistent, this symlink remains on the next boot.

On the next boot, `mountpoint -q "$mountpoint"` is false for a symlink, so execution reaches the `mkdir -p` and `mount` lines above.

- If the symlink's target exists, `mkdir -p` succeeds silently, and `mount --bind` follows the symlink, improperly binding the host directory onto itself instead of over the mountpoint.

Fix: Remove any existing symlink before attempting to create the directory.

```diff

+		[ -L "$mountpoint" ] && rm -f "$mountpoint"
 		mkdir -p "$mountpoint"
 		INFO "Mounting $wsl_path to $mountpoint (writable: $writable)"
```
