Executive Summary ¶

The PR adds a repeatable --sync-exclude flag and a top-level .limasyncignore file to limactl shell --sync. The maintainer's amendment fixes all three round-1 Important findings. One new defect needs fixing before merge. The dry run behind the sync-back prompt starts its transfer one directory above the synced one, so anchored patterns report phantom changes, and a pattern matching the synced directory's name makes the prompt delete the guest's work without syncing it back.

+// hostTreeForDiff returns the host tree that the "View" diff compares with the

+func hostTreeForDiff(ctx context.Context, cmd *cobra.Command, rsync copytool.CopyTool, hostCurrentDir, baseDir string, excludeArgs []string) (string, error) {
+	if len(excludeArgs) == 0 {
+		return hostCurrentDir, nil
+	}
+	dir := filepath.Join(baseDir, "host", filepath.Base(hostCurrentDir))
+	if err := os.MkdirAll(dir, 0o755); err != nil {
+		return "", fmt.Errorf("failed to create temporary directory: %w", err)
+	}
+	if err := rsyncDirectory(ctx, cmd, rsync, []string{hostCurrentDir + "/", dir}); err != nil {
+		return "", fmt.Errorf("failed to copy the host directory to a temporary directory: %w", err)
+	}

Design Observations ¶

Concerns ¶

  • .limasyncignore round-trips through the guest it restricts (in-scope) Claude Opus 5.5. Nothing excludes the file itself, so the guest gets a copy and rsyncBack writes the guest's edits back to the host, without a prompt under --yes (line 591). The current session stays protected, but a guest that deletes or trims the file receives the excluded files next session. Adding --exclude /.limasyncignore whenever the file exists (safe once C1 is fixed) keeps the guest from seeing it. The author's --sync-exclude-from FILE proposal, reading a file outside the synced tree, does the same.
  • "View the changed contents" copies the whole host tree when excludes are set (in-scope) Gemini 3.5 Flash. The copy skips excluded paths, usually the large ones such as node_modules, but a large tree with narrow excludes costs time and temporary space before the diff appears.
  • A per-directory merge filter would hand the filtering to the guest (future) Claude Opus 5.5 Codex GPT 6 Astra. Round 1 suggested --filter ':- .limasyncignore'. On the sync-back the guest is the sender, so its copy of the file would decide what comes back; a single file read on the host avoids that.

Strengths ¶

  • The ignore-file lookup probes the native path and names the converted one (in-scope) Claude Opus 5.5 Codex GPT 6 Astra Gemini 3.5 Flash. It mirrors the hostCurrentDirNative/hostCurrentDir split at lines 243-256, so a Cygwin or MSYS rsync gets the same path form as its source argument.
  • validateSyncFlagValue checks the command's real flag set (in-scope) Claude Opus 5.5 Gemini 3.1 Pro Gemini 3.5 Flash. At runtime that includes inherited flags (the built binary rejects --sync -y), and a directory named --data still works.
  • Both trees in the diff view go through the same rsync tool (in-scope) Claude Opus 5.5 Codex GPT 6 Astra Gemini 3.1 Pro. Excluded files drop out of both sides; I2 is about keeping it that way.
  • StringArray keeps each pattern intact (in-scope) Codex GPT 6 Astra. Repeated --sync-exclude values are never split on commas.

Round 1 credited "the same exclude args throughout the pipeline". All five rsync calls do pass the same exclude arguments, but C1 shows the stats call reading them from a different starting directory, so that credit holds for the arguments only.

Review Process Notes ¶

Skill improvements ¶

  • When the probe that decides a finding ran on a different implementation of an external tool than the one most users run (Apple's openrsync versus GNU rsync, BSD versus GNU utilities), re-run it on that implementation before recording the severity. Implementations of one tool differ in filter, option and exit-code semantics, and such a difference would reverse the finding.

Repo context updates ¶

  • [repo] UPDATE "Rsync invocations in limactl shell --sync": the shell runs rsync from five call sites, not four. The "View the changed contents" branch also copies the host directory into a temporary tree when excludes are set. Matching options across those calls is not enough. rsync matches exclude and filter patterns against paths from the directory where the transfer starts, which the trailing slash on the source decides. A source without the slash starts the transfer in its parent, so an anchored pattern (/name) stops matching and an unanchored pattern equal to the directory's own name excludes everything. Flag any call that passes the shared filters with a different source or destination form.
  • [repo] copytool.CopyTool.Command(ctx, paths, opts) replaces the tool's stored Options whole when opts is non-nil, AdditionalArgs included. A per-call override on a tool built with --delete or exclude arguments silently drops them for that call; flag one.
