I2. **Key path is converted for the selected toolchain, then handed to a PATH-resolved `ssh-keygen`** — `pkg/sshutil/sshutil.go:290` [Claude Opus 4.8, Codex GPT 5.5, Gemini 3.1 Pro]

Line 285 formats `privPath` for the `ssh.exe` that `NewSSHExe` selected; line 290

I3. **The native fallback fires on every `cygpath` error, not on a missing binary** — `pkg/ioutilx/ioutilx.go:67-74` [Claude Opus 4.8, Codex GPT 5.5, Gemini 3.1 Pro]

```go
	out, err := exec.CommandContext(ctx, cygpathExe, filepath.ToSlash(orig)).CombinedOutput()
	if err == nil {
		return strings.TrimSpace(string(out)), nil
	}

	logrus.WithError(err).Debugf("cygpath unavailable for %#q (output: %#q), attempting native conversion", orig, strings.TrimSpace(string(out)))

	return windowsSubsystemPathWithoutCygpath(orig)
```

Every failure degrades to the hand-rolled conversion: a non-zero exit, a broken
Cygwin install, a cancelled context. A cancelled context therefore yields a
successful conversion rather than an error. The fallback's `/c/...` formula is the
MSYS2 and Git-for-Windows convention, while stock Cygwin maps `C:\` to
`/cygdrive/c/` and any `fstab` can remap it — so on a host that *has* an
authoritative `cygpath`, a transient failure silently substitutes a path that
resolves elsewhere.

New this round: the pre-PR code logged this at Error with a user-facing hint; line 72
logs at Debug, so a user without `--debug` gets no signal that the path was
fabricated. The message also claims "cygpath unavailable" for a `cygpath` that ran
and failed.

Fix: fall back only when the binary is genuinely absent, and warn when it fires.

```diff

 		return strings.TrimSpace(string(out)), nil
 	}
+	if !errors.Is(err, exec.ErrNotFound) && !errors.Is(err, fs.ErrNotExist) {
+		return "", fmt.Errorf("failed to run %#q on %#q: %#q: %w", cygpathExe, orig, strings.TrimSpace(string(out)), err)
+	}
```

## Design Observations

### Concerns

**The `ioutilx` fallback turns four unrelated call sites from fail-fast into silent-degrade (in-scope)** [Claude Opus 4.8]. `WindowsSubsystemPath` has four callers besides `SSHOpts`: `pkg/limayaml/defaults.go:717`, `pkg/hostagent/mount.go:58`, `pkg/copytool/copytool.go:127`, and `cmd/limactl/shell.go:789`. Making the helper fall back rather than error changes all four at once, and the new behavior is right for only one of them. `defaults.go:717` wants a POSIX guest mount point, so `/c/Users/...` is the desired form — that is the improvement the PR is after. `mount.go:58` feeds `ReverseSSHFS.LocalPath`, which a **host-side** sftp-server opens; on a native-OpenSSH host that binary is `sftp-server.exe`, which cannot resolve `/c/Users/...`. `copytool.go:127` and `shell.go:789` fall in the same class.

The load-bearing detail: **fixing I3 does not close this.** On a native-OpenSSH host `cygpath` is genuinely absent, so the fallback fires legitimately and `mount.go` still receives a Cygwin-form path. Mounts previously failed loudly ("cygpath not found"); they now fail deeper, with a confusing path error. sshocker even logs `"Accepting %q Unix path, assuming Cygwin/msys2 OpenSSH"` (`reversesshfs.go:135`) — an assumption this PR quietly invalidates. Splitting the API by consumer intent (`PathForSSH` for ssh-client arguments, a separate helper for Linux-guest paths) would stop the next reader from "fixing" `defaults.go` into emitting `C:/Users/...` as a mount point, and would let `mount.go` keep its clear error until its follow-up lands.

**Model the selected toolchain explicitly (in-scope)** [Codex GPT 5.5]. Toolchain state is spread across `SSHExe`, `cygpathForSSH`, `PathForSSH`, a direct `"ssh-keygen"` exec, and the PATH-global `WindowsSubsystemPath`. A resolved struct carrying `ssh`, `scp`, `ssh-keygen`, an optional `cygpath`, and a path-conversion method would eliminate I1 and I2 by construction and fold S4 in with them.

**Pre-existing: an empty mount point on conversion failure (future)** [Claude Opus 4.8]. `pkg/limayaml/defaults.go:717` overwrites `mountLocation` with `""` when the conversion fails, warns, and then sets `MountPoint = ptr.Of("")` (line 722). Blame predates this PR, and the new fallback makes it *less* likely to fire — but the result should go to a temporary rather than clobber the input.

### Strengths

- Detecting the toolchain from a sibling `cygpath.exe` rather than sniffing version strings is cheap and correct for all three Cygwin-family installs, and caching by the symlink-resolved path is the right key. [Claude Opus 4.8, Codex GPT 5.5]
- `pickCompleteSSHOnWindows`'s "skip the partial install, keep walking" rule is the right shape for the MinGit problem, and returning `""` rather than erroring preserves the old `exec.LookPath` behavior. [Claude Opus 4.8, Codex GPT 5.5]
- `PathForSSH` stays a no-op on non-Windows, so call sites can shed their `runtime.GOOS` guards over time without behavior change. [Claude Opus 4.8, Codex GPT 5.5]

## Review Process Notes

### Skill improvements

- When a round's only change implements a reviewer's literal suggestion, verify the suggestion itself before crediting the thread as closed. A reviewer's proposed one-liner carries the authority of the reviewer, not of the compiler, and an author who applies it verbatim inherits its defects. Check the suggested code against the language's actual semantics, and when it turns out to be inert, say so in Unresolved Feedback rather than in Suggestions alone — the thread is still open, and only the reviewer can close it.

- When a change replaces a hard error with a fallback in a shared helper, enumerate every caller and classify each by whether the fallback's output is the form that caller's downstream consumer expects. ## Design Observations

### Concerns

**The `ioutilx` fallback converts four unrelated call sites from fail-fast to silent-degrade** *(in-scope)*

`WindowsSubsystemPath` has four callers besides `SSHOpts`: `pkg/limayaml/defaults.go:717`, `pkg/hostagent/mount.go:58`, `pkg/copytool/copytool.go:127`, `cmd/limactl/shell.go:789`. Making the helper fall back rather than error changes all four at once, and the change is only *correct* for one of them:

- `defaults.go:717` — the result is a Linux guest mount point; `/c/Users/...` is the desired form. This is the improvement the PR wants.
- `mount.go:58` — the result is `ReverseSSHFS.LocalPath`, served by a **host-side** sftp-server. On a native-OpenSSH host that binary is `sftp-server.exe`, which cannot open `/c/Users/...`. Previously the mount failed with "cygpath not found"; now it fails deeper with a confusing path error.
- `copytool.go:127`, `shell.go:789` — same class.

The PR description defers `limactl copy` and reverse-sshfs to follow-ups, so this is understood — but the fallback lands *now* and degrades those paths *now*. Consider giving the fallback an explicit opt-in (a second helper, or a `style` parameter) so only `defaults.go` and the ssh-family callers get it, and `mount.go`/`copytool` keep the clear "no cygpath" error until their follow-up lands.

**Pre-existing bug found while tracing: empty mount point on conversion failure** *(future)*

`pkg/limayaml/defaults.go:715-722`: `mountLocation, err = ioutilx.WindowsSubsystemPath(ctx, mountLocation)` overwrites `mountLocation` with `""` on error, then only `Warnf`s and sets `MountPoint = ptr.Of("")`. Not introduced here (blame predates the PR), and the new fallback makes it *less* likely to fire — but it should assign to a temporary.

### Strengths

- `cygpathForSSH` is the right primitive: one resolved-path-keyed probe, cached, that both identifies the toolchain and hands back the exact `cygpath.exe` to shell out to. Wiring `SSHOpts`'s `ControlPath` (I1) and `ssh-keygen` (I2) through it would close the remaining gaps with no new machinery.
- `pickCompleteSSHOnWindows`'s "skip the partial install, keep walking" rule is the correct shape for the MinGit problem, and returning `""` (rather than erroring) to preserve the old `exec.LookPath` behaviour is a careful choice.
