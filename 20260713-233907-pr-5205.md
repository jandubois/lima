## Important Issues

I1. **The `ControlPath` fix from #5196 was dropped** — `pkg/sshutil/sshutil.go:555` [Claude Opus 4.8, Codex GPT 5.5, Gemini 3.1 Pro] (regression against #5196)

```go
		controlSock, err = ioutilx.WindowsSubsystemPath(ctx, controlSock)
```

`SSHOpts` builds one `ssh` command line carrying two paths, and they go through two
different converters. `IdentityFile` is converted by `PathForSSH`, which is
toolchain-aware. `ControlPath` is converted by `ioutilx.WindowsSubsystemPath`, which
runs whatever `cygpath` is first on PATH — and on a native-OpenSSH host with no
`cygpath`, falls through to the new MSYS fallback and yields `/c/Users/.../ssh.sock`.
A native `ssh.exe` reads that leading `/` as the current drive's root.

#5196 already fixes this. #5205 does not:

| ref | conversion |
|---|---|
| `master` | `ioutilx.WindowsSubsystemPath(ctx, controlSock)` |
| **#5196** | **`PathForSSH(ctx, sshExe, controlSock)`** |
| #5205 | `ioutilx.WindowsSubsystemPath(ctx, controlSock)` |

This is live, not theoretical: `forwardSSH` (`hostagent.go:1043`) runs
`ssh -O forward`/`-O cancel` against the ControlMaster for guest-agent port
forwarding, and `hostagent.go:578` states outright that "on Windows, the ControlMaster
is used only for SSH port forwarding." The mux-option stripping elsewhere applies only
to the written `ssh -F` config file, `limactl shell`, the requirement probes, and
reverse-sshfs — never to this path.

Fix: restore #5196's line.

```diff
-		controlSock, err = ioutilx.WindowsSubsystemPath(ctx, controlSock)
+		controlSock, err = PathForSSH(ctx, sshExe, controlSock)
```

I3. **Key path is converted for the selected toolchain, then handed to a PATH-resolved `ssh-keygen`** — `pkg/sshutil/sshutil.go:290` [Claude Opus 4.8, Codex GPT 5.5, Gemini 3.1 Pro] (present in both PRs)

```go
			keygenCmd := exec.CommandContext(ctx, "ssh-keygen", "-t", "ed25519", "-q", "-N", "",
				"-C", "lima", "-f", privPath)
```

Line 285 formats `privPath` for the `ssh.exe` that `NewSSHExe` selected; line 290
executes whichever `ssh-keygen` PATH resolves first. The two diverge whenever
`NewSSHExe` picks a binary outside PATH — via the `SSH` env var, or via the
`%SystemRoot%\System32\OpenSSH` fallback at line 102.

`0fdcd63f`'s subject promises exactly this pairing ("pair its companion tools"), and
`cygpathForSSH` already computes the resolved toolchain directory needed to do it.
`pkg/copytool/scp.go:24` repeats the shape with `exec.LookPath("scp")`.

Fix: resolve the companion from the directory of the selected `ssh`, falling back to
PATH only when the sibling is absent. Shape the helper so the `scp` call site can adopt
it when `limactl copy` lands.

I4. **The native fallback fires on every `cygpath` error, not on a missing binary** — `pkg/ioutilx/ioutilx.go:67-74` [Claude Opus 4.8, Codex GPT 5.5, Gemini 3.1 Pro] (present in both PRs)

```go
	out, err := exec.CommandContext(ctx, cygpathExe, filepath.ToSlash(orig)).CombinedOutput()
	if err == nil {
		return strings.TrimSpace(string(out)), nil
	}

	logrus.WithError(err).Debugf("cygpath unavailable for %#q (output: %#q), attempting native conversion", orig, strings.TrimSpace(string(out)))

	return windowsSubsystemPathWithoutCygpath(orig)
```

Every failure degrades to the hand-rolled conversion: a non-zero exit, a broken Cygwin
install, a cancelled context. A cancelled context therefore yields a successful
conversion rather than an error. The `/c/...` formula is the MSYS2 and Git-for-Windows
convention, while stock Cygwin maps `C:\` to `/cygdrive/c/` and any `fstab` can remap
it — so on a host that *has* an authoritative `cygpath`, a transient failure silently
substitutes a path that resolves elsewhere. The pre-PR code logged this at Error; it
now logs at Debug, so a user without `--debug` gets no signal.

Fix: fall back only when the binary is genuinely absent, and warn when it fires.

```diff
 	if err == nil {
 		return strings.TrimSpace(string(out)), nil
 	}
+	if !errors.Is(err, exec.ErrNotFound) && !errors.Is(err, fs.ErrNotExist) {
+		return "", fmt.Errorf("failed to run %#q on %#q: %#q: %w", cygpathExe, orig, strings.TrimSpace(string(out)), err)
+	}
```

byte-identical for every input — verified by running both forms over `"scp.exe"`,

traversal: `Clean("../scp.exe")` is `"../scp.exe"`, and `Join` still escapes `dir`.


expected one. Callers only test `len(missing) > 0`, so nil and empty behave alike.

Fix: restore `var missing []string`.

## Design Observations

### Concerns

**The `ioutilx` fallback turns four unrelated call sites from fail-fast into silent-degrade (in-scope)** [Claude Opus 4.8]. `WindowsSubsystemPath` has four callers besides `SSHOpts`: `pkg/limayaml/defaults.go:717`, `pkg/hostagent/mount.go:58`, `pkg/copytool/copytool.go:127`, and `cmd/limactl/shell.go:789`. Making the helper fall back rather than error changes all four at once, and the new behavior is right for only one of them. `defaults.go:717` wants a POSIX guest mount point, so `/c/Users/...` is the desired form — that is the improvement the PR is after. `mount.go:58` feeds `ReverseSSHFS.LocalPath`, which a **host-side** sftp-server opens; on a native-OpenSSH host that binary is `sftp-server.exe`, which cannot resolve `/c/Users/...`. `copytool.go:127` and `shell.go:789` fall in the same class.

The load-bearing detail: **fixing I4 does not close this.** On a native-OpenSSH host `cygpath` is genuinely absent, so the fallback fires legitimately and `mount.go` still receives a Cygwin-form path. sshocker even logs `"Accepting %q Unix path, assuming Cygwin/msys2 OpenSSH"` (`reversesshfs.go:135`) — an assumption this PR quietly invalidates. Splitting the API by consumer intent (`PathForSSH` for ssh-client arguments, a separate helper for Linux-guest paths) would let `mount.go` keep its clear error until its follow-up lands. This applies to #5196 as much as to #5205.

**Model the selected toolchain explicitly (in-scope)** [Codex GPT 5.5]. Toolchain state is spread across `SSHExe`, `cygpathForSSH`, `PathForSSH`, a direct `"ssh-keygen"` exec, and the PATH-global `WindowsSubsystemPath`. A resolved struct carrying `ssh`, `scp`, `ssh-keygen`, an optional `cygpath`, and a path-conversion method would eliminate I1 and I3 by construction and fold S4 in with them.

**Pre-existing: an empty mount point on conversion failure (future)** [Claude Opus 4.8]. `pkg/limayaml/defaults.go:717` overwrites `mountLocation` with `""` when the conversion fails, warns, and then sets `MountPoint = ptr.Of("")` (line 722). Blame predates both PRs, and the new fallback makes it *less* likely to fire — but the result should go to a temporary rather than clobber the input.

### Strengths

- Extracting `windowsSubsystemPathWithoutCygpath` (`ioutilx.go:77`) is a genuine improvement over #5196, where the fallback was inlined and therefore unreachable from a unit test. It is what makes `TestWindowsSubsystemPathWithoutCygpath` possible, and it answers Akihiro's review directly. Keep it. [post-review analysis]
- Detecting the toolchain from a sibling `cygpath.exe` rather than sniffing version strings is cheap and correct for all three Cygwin-family installs, and caching by the symlink-resolved path is the right key. [Claude Opus 4.8, Codex GPT 5.5]
- `pickCompleteSSHOnWindows`'s "skip the partial install, keep walking" rule is the right shape for the MinGit problem, and returning `""` rather than erroring preserves the old `exec.LookPath` behavior. [Claude Opus 4.8, Codex GPT 5.5]
- `PathForSSH` stays a no-op on non-Windows, so call sites can shed their `runtime.GOOS` guards over time without behavior change. [Claude Opus 4.8, Codex GPT 5.5]

## Testing Assessment

`go test ./pkg/sshutil ./pkg/ioutilx` passes on darwin. Windows CI runs `go test ./...`, so both new `_windows_test.go` files execute there. Gating the `ioutilx` fallback test by filename is correct, not a gap: `filepath.IsAbs` and `filepath.VolumeName` are OS-dependent.

The headline is I2: **#5205 has strictly less coverage than #5196.** The two biggest holes below are holes only because the tests that filled them were dropped.

1. **`cygpathForSSH` has no test** — the central new primitive (toolchain detection, symlink resolution, the `""`-means-native cache sentinel). #5196's `TestCygpathForSSH` covers the cygwin, native, and empty cases. Restore it.
2. **`SftpServerForSSH` has no test** — #5196's `TestSftpServerForSSH` covers the native sibling, the missing sibling, and empty input. Restore it.
3. **`PathForSSH` has no test in either PR** — nothing asserts `C:\Users\x` becomes `C:/Users/x` on the native branch.
4. **`WindowsSubsystemPathWithCygpath`'s fallback trigger** — `windowsSubsystemPathWithoutCygpath` is tested directly, but nothing exercises the wrapper's *decision* to fall back. A stub `cygpath` that exits non-zero versus one that is absent covers the two cases I4 says must behave differently.
5. **`SSHOpts` on Windows** — no test asserts that `ControlPath` and `IdentityFile` come out in the *same* path form. Such a test would have caught I1 mechanically.
6. **`missingSiblings`** — no direct test, so S1's and S8's changes are unverified through the current call site.

## Review Process Notes

### Skill improvements

- When a PR describes itself as derived from, extracted from, ported from, or superseding another PR or branch, diff it against **that PR's head**, not only against the merge-base. Fetch the referenced head and compare the two trees file by file. A re-derivation that re-types the original rather than cherry-picking its commits can silently drop fixes, tests, and comment corrections, and none of that is visible in a merge-base diff — a dropped fix and a fix that was never written render identically. Report anything the derived PR lost as a regression against its source, and confirm each intentional difference the PR description claims. The setup step should fetch the referenced head and inline the cross-PR diff alongside the merge-base diff, because an agent given only the merge-base cannot recover this no matter how carefully it reads.

- When a round's only change implements a reviewer's literal suggestion, verify the suggestion itself before crediting the thread as closed. A reviewer's proposed one-liner carries the authority of the reviewer, not of the compiler, and an author who applies it verbatim inherits its defects. Check the suggested code against the language's actual semantics, and when it turns out to be inert, say so in Unresolved Feedback rather than in Suggestions alone — the thread is still open, and only the reviewer can close it.

- When a change replaces a hard error with a fallback in a shared helper, enumerate every caller and classify each by whether the fallback's output is the form that caller's downstream consumer expects. A fallback added to serve one caller silently reroutes all of them, and the fix that corrects the fallback's trigger condition does not necessarily correct the callers it now degrades — those are two separate defects, and reporting only the first leaves the second invisible.

## Design Observations

### Concerns

**The `ioutilx` fallback converts four unrelated call sites from fail-fast to silent-degrade** *(in-scope)*

`WindowsSubsystemPath` has four callers besides `SSHOpts`: `pkg/limayaml/defaults.go:717`, `pkg/hostagent/mount.go:58`, `pkg/copytool/copytool.go:127`, `cmd/limactl/shell.go:789`. Making the helper fall back rather than error changes all four at once, and the change is only *correct* for one of them:

- `defaults.go:717` — the result is a Linux guest mount point; `/c/Users/...` is the desired form. This is the improvement the PR wants.
- `mount.go:58` — the result is `ReverseSSHFS.LocalPath`, served by a **host-side** sftp-server. On a native-OpenSSH host that binary is `sftp-server.exe`, which cannot open `/c/Users/...`. Previously the mount failed with "cygpath not found"; now it fails deeper with a confusing path error.
- `copytool.go:127`, `shell.go:789` — same class.

The PR description defers `limactl copy` and reverse-sshfs to follow-ups, so this is understood — but the fallback lands *now* and degrades those paths *now*. Consider giving the fallback an explicit opt-in (a second helper, or a `style` parameter) so only `defaults.go` and the ssh-family callers get it, and `mount.go`/`copytool` keep the clear "no cygpath" error until their follow-up lands.

**Pre-existing bug found while tracing: empty mount point on conversion failure** *(future)*

`pkg/limayaml/defaults.go:715-722`: `mountLocation, err = ioutilx.WindowsSubsystemPath(ctx, mountLocation)` overwrites `mountLocation` with `""` on error, then only `Warnf`s and sets `MountPoint = ptr.Of("")`. Not introduced here (blame predates the PR), and the new fallback makes it *less* likely to fire — but it should assign to a temporary.

### Strengths

- `cygpathForSSH` is the right primitive: one resolved-path-keyed probe, cached, that both identifies the toolchain and hands back the exact `cygpath.exe` to shell out to. Wiring `SSHOpts`'s `ControlPath` (I1) and `ssh-keygen` (I2) through it would close the remaining gaps with no new machinery.
- `pickCompleteSSHOnWindows`'s "skip the partial install, keep walking" rule is the correct shape for the MinGit problem, and returning `""` (rather than erroring) to preserve the old `exec.LookPath` behaviour is a careful choice.
