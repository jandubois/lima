Review Process Notes ¶

Skill improvements ¶

  • When a diff rewrites a comment into a broader policy statement, verify the new claim against every consumer of the behavior it describes, not only the call site the comment sits above. Enumerate the other places that build, copy, or pass the same options or state, and confirm each one follows the stated rule. A rewritten comment reads as freshly checked, so a reviewer who accepts it inherits an unverified generalization, and a maintainer who later trusts it may delete a guard the comment claims is applied elsewhere.
  • When a helper returns a sanitized copy rather than mutating in place, trace what the caller does with its own unmodified value afterwards. A call site that looks protected by the helper can still hand the original to a different consumer further down the function. Grep for later uses of the variable the helper was called on, not just for the helper's own call sites.
  • When the review prompt names a specific change as the round's only delta, require each agent to state a verdict on it explicitly, including whether the commit message accounts for it. Naming a change reads as prior coverage, so agents give it less scrutiny than the rest of the diff rather than more.

Repo context updates ¶

  • [repo] Win32-OpenSSH patches colon() in misc.c under #ifdef WINDOWS so that any x: prefix, and any /x: prefix, returns NULL and is treated as a local path. Upstream portable OpenSSH has no such case and reads C:/foo as host C path /foo. A drive-letter path is therefore safe to hand to a native Windows scp and unsafe for a Cygwin or portable one. Their own comment notes the patch also swallows single-character hostnames.
  • [repo] The hostagent's ssh.SSHConfig is built from the SSH options before any mux stripping, and sshocker appends AdditionalArgs verbatim. Stripping performed inside a callee that clones its input therefore does not reach the commands the hostagent itself runs (agent-forwarding scripts, remote command execution, log tailing, file copies). Treat any claim that Lima strips multiplexing for all command or session invocations on Windows as false until checked against that construction.
  • [repo] Companion-binary lookups should resolve symlinks before taking a sibling from the same directory, as the sshutil path does. A lookup built on a bare exec.LookPath result finds a shim or symlink directory and silently misses the sibling, falling through to a best-effort conversion. Flag a new sibling lookup that skips the resolution step.
  • [repo] UPDATE the "GitHub Actions PATH on Windows runners" entry: it describes an action "on the in-flight windows-plain-ci branch, not yet on master". Repo context should describe merged default-branch reality, so either restate the constraint without the branch reference or drop the entry until the work lands.
  • [repo] The "Windows SSH toolchains" entry still names pkg/ioutilx.WindowsSubsystemPath as the path-translation helper and lists pkg/copytool among the PATH-global callers. Both are now wrong: the helper lives in pkg/fsutil, and copytool converts per backend through the toolchain's own cygpath. Round 2 filed the same correction, so merge with that pending entry rather than adding a second copy.
