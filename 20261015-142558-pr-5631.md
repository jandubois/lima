## Executive Summary

On a macOS host, the hostagent now starts each ssh under `/bin/sh -c 'ulimit -S -n 1024; exec "$0" "$@"'`, and a Lima-side `executeScript` replaces sshocker's `ExecuteScript` so that requirement scripts get the 1024 limit too. The wrapper keeps the PID and the argv, and the hostagent keeps its own raised limit. But no test checks that the call sites use the wrapper. Revert the site that starts the ControlMaster and the suite stays green (I1).

## Suggestions

S1. **`adjustNofileRlimit`'s comment still credits it with ssh's limit on macOS** — `pkg/hostagent/hostagent_unix.go:14-17` [Claude Opus 5.5, Gemini 3.5 Flash]

```go

```

The comment names the macOS terminal's 256 as the reason for the function and ssh as its main beneficiary. On macOS neither holds after this PR. `sshCommand` sets each ssh it starts to 1024 whatever this function did, raising a 256 limit as readily as it lowers an unlimited one. The function still matters for the hostagent's other children, which inherit the raised limit only because it calls `syscall.Setrlimit` (Go otherwise restores the soft limit that the process started with, per `syscall/rlimit.go`), and for ssh on Linux hosts. A reader who trusts the comment could drop the function or the 1024 limit as redundant.

Fix: add a line such as `// On macOS, sshCommand overrides this for ssh and sets its soft limit to 1024.`

**Outcome:** fixed. The comment now says that on macOS, `sshCommand` then lowers the soft limit of each ssh it starts to 1024 when the limit is higher. `sshCommand`'s own doc says "at most 1024", because the limit stays at a hard limit below 1024.

## Design Observations

### Concerns

- **Five ssh launches stay uncapped (future).** [Codex GPT 6 Astra, Claude Opus 5.5, Gemini 3.1 Pro, Gemini 3.5 Flash] They are sshocker's reverse-sshfs `Prepare`, `Start` and `waitForRemoteReady` (`reversesshfs.go:56`, `:153`, `:311`), sshocker's `ExitMaster`, and vz `requestStopViaSSH` (`vz_driver_darwin.go:520`). `ExitMaster` sends `-O exit` and never becomes a master. `requestStopViaSSH` runs during Stop, after `ExitMaster`, and does not carry forwards. Reverse-sshfs is the one that matters. It runs with `ControlMaster=auto` and would create an uncapped master if none exists when `setupMounts` runs. For Linux, FreeBSD and macOS guests an essential requirement creates the master first ("sshfs binary to be installed" when a Linux guest has reverse-sshfs mounts, "Persistent SSH ControlMaster" otherwise), so reverse-sshfs creates one only if the master has died in between. Windows guests are the exception. Their one essential requirement runs with `noMaster`, so a non-plain Windows guest with reverse-sshfs mounts on a macOS host would get its master from `Prepare`, uncapped. The Windows templates say Windows guests require `plain: true`, which skips mounts, but validation does not enforce it. I read this from the code and did not boot a Windows guest. The remaining cases belong with the forward-recovery work still open in #5420. **Outcome:** declined for this PR; it stays with that work in #5420.
- **Logs and errors now show the wrapper (in-scope).** [Claude Opus 5.5] On macOS, `cmd.Path` is `/bin/sh` and `cmd.Args` puts `-c` and the `ulimit` script ahead of the ssh argv, both in the debug lines and in the `failed to run %v` errors of `executeSSH`, `forwardSSH` and `copyToHost` (`hostagent.go:1046`, `:1169`, `:1359`). A missing `ssh` now exits 127, and the shell's `exec: ssh: not found` goes to stderr, which `forwardSSH`'s error leaves out. Requirement errors include stderr, so the first boot step still names the cause. Neither change justifies more code. **Outcome:** declined; no code change.

### Strengths

- **Capping each ssh launch, not the hostagent, keeps the high limit that the in-process gRPC forwarder needs** (in-scope). It still holds after Virtualization.framework raises the hostagent's soft limit during VM start. [Codex GPT 6 Astra, Claude Opus 5.5, Gemini 3.5 Flash]
- **`exec "$0" "$@"` keeps the PID and the argv** (in-scope). Context cancellation and `cmd.Process.Kill()` reach ssh itself, and passing the binary as `$0` does not need quoting. Probes of empty arguments, spaces, quotes and cancellation all passed. [Codex GPT 6 Astra, Claude Opus 5.5, Gemini 3.1 Pro, Gemini 3.5 Flash]
- **Unix and Windows requirement scripts share one helper** (in-scope), and `waitForWinRequirement`'s copy of sshocker's code is gone. [Claude Opus 5.5, Gemini 3.5 Flash]

## Acknowledged Limitations

- **From the PR description:** a master that `limactl shell` or another client re-creates after a death keeps that client's limit, and forwards lost to other kinds of master death are not restored. Both stay open in #5420.
- **Considered and rejected in the design; do not re-suggest:** a generated ssh wrapper script or a `PATH` shim, either of which puts an executable on disk; a command-prefix field in sshocker, which needs an sshocker release for a policy that Lima sets; and lowering the hostagent's own limit, which would limit the in-process gRPC forwarder too.
