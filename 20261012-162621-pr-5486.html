Guests must be able to reach the host's DHCP and DNS ports, which host firewalls
block by default.

- With **firewalld**, the bridge is bound to the first existing zone out of
  `lima`, `nm-shared`, and `libvirt`. All three forward the guests' traffic but
  expose only DHCP, DNS and ICMP on the host itself. Define a `lima` zone to
  override that policy.
- With **ufw**, rules allowing UDP 67 and UDP/TCP 53 on the bridge are added.
- Otherwise, equivalent `iptables` rules are added.

Design Observations ¶

Concerns ¶

  • Concurrent starts can launch two helpers for one network (future) Claude Opus 5.5: nothing serializes Reconcile, so two limactl start runs can both miss the PID file and both start the helper. The second overwrites the PID file, and pkill -F then reaches only one of them, leaving the other running as root. A per-network lock in _networks around startNetwork and stopNetwork would close this.
  • Every LIMA_HOME and every user shares one helper per network (future): the PID file is in the global /run/lima, but Reconcile counts only its own LIMA_HOME's instances. When the last instance of one LIMA_HOME stops, it kills the helper, and down() deletes every Lima tap on the bridge, including those of instances still running under another LIMA_HOME or user. socket_vmnet shares its daemon the same way on macOS, where those instances lose their socket instead.

Strengths ¶

  • Tap names agree everywhere (in-scope) Codex GPT 6 Astra Claude Opus 5.5: qemu.go:929, reconcile.go:256 and the helper's network_linux.go:423 all call TapName(uid, instance, network), and ensureTaps passes TapCmd its arguments in the declared order.
  • startNetwork and stopNetwork loop over RequiredDaemons() (in-scope) Claude Opus 5.5 Gemini 3.5 Flash: the hard-coded socket_vmnet list and its install check moved into that loop.
  • QEMU opens its tap without privileges (in-scope) Codex GPT 6 Astra: script=no with a tap that the user owns does not add a privileged path to the driver.

Testing Assessment ¶

  1. I1 needs its test (rubric check 3), because a broken FORWARD rule on a host network would fail silently. The patch makes both checks run; the isolation check also needs a host-side assertion before it can fail.
  2. I2 needs its test (rubric check 3), since it is a restart-sequence race. The test exists only in the reproducer. run() calls ip, iptables and firewall-cmd directly, and cmd/lima-privileged-net has no test files, so the suite needs a seam first.
  3. pkg/networks/reconcile has no tests for ensureTaps, tapIsAttached or the per-instance activeNetwork map. A regression there fails every start, with QEMU naming the tap, so the test is optional. It would also need a fake sysfs and sudo, so the drop rule applies.

Before launching the agents, I ran go build ./... for darwin and linux, GOOS=linux go vet on the three changed packages, and go test -count=1 ./pkg/networks/... ./pkg/limayaml/... ./pkg/driver/qemu/... on macOS from the lead worktree; all passed. The five reproducers above ran from the same worktree, and the I1 and I2 probes ran again against their patches.

Documentation Assessment ¶

The new page's claims about tap ownership (createTap passes the caller's uid, sys_linux.go:141), the root-owned /run/lima (ensureRunDir), the rejection of a stale networks.yaml, and the sudo cat ... | limactl sudoers --check /dev/stdin recipe match the code. Acknowledged Limitations ¶

  • bridged is not tested in CI. The runner has no pre-existing bridge, as the comment at test.yml:600 says.
  • A tap outlives its instance until the network goes down. reconcile.go:245-248 and the page's bridged warning say so, and deleting one tap would need its own sudoers rule. A future reviewer should not re-raise it as a leak.
  • The helper rejects SUDO_UID 0. limactl exits at startup when run as root (cmd/limactl/main.go:35), so Lima never reaches that check. Do not re-suggest accepting uid 0.

Review Process Notes ¶

Skill improvements ¶

  • Name privilege escalation in the preamble's list of forbidden commands: "Never run sudo, su, doas or any other command that elevates privileges on the host, even to read a value or check a version; describe the probe in the finding instead." A sudo call on the review host can prompt, flush the user's cached credentials, or act as root on the live machine, and the current list names containers, VMs and services only.

Repo context updates ¶

  • [repo] UPDATE "/etc/sudoers.d/lima is matched against rendered text and read unprivileged": replace the paragraph saying a permission error is a hard failure. pkg/sudoers.ReadFile reports an unreadable file as ok=false without an error, and both checks then pass without comparing anything, so a 0440 file that only root can read is never verified by an unprivileged limactl. The Linux docs pipe it in with sudo cat /etc/sudoers.d/lima | limactl sudoers --check /dev/stdin.
  • [repo] hack/test-templates.sh chooses its network checks (vmnet, vmnet-isolated, user-v2) from the template file's networks[].lima, never from LIMACTL_CREATE_ARGS. A CI job that selects a network with --network in LIMACTL_CREATE_ARGS stays green while running none of them, so when a change adds or relies on a network check, confirm in the job log that the check ran.
  • [repo] stopNetwork treats a missing PID file as a finished teardown: it waits up to 5 s for the file to disappear, then returns. Anything a network daemon does after removing its PID file races the next limactl start, so flag shutdown code that removes the PID file before its cleanup.
  • [repo] The firewalld zones nm-shared (installed by NetworkManager) and libvirt (installed by libvirt) do not ship with firewalld, and both open ssh to the interfaces bound to them; libvirt also opens tftp and dhcpv6. Flag any comment or doc that calls them DHCP/DNS/ICMP-only.
