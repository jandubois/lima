I2. mount.md says a UNC location works with an explicit mountPoint, but the boot script skips it Claude Opus 5.5 Codex GPT 6 Astra¶
website/content/en/docs/config/mount.md

The "wsl2" mount type relies on using WSL2's native disk sharing, where the root disk is available by default at `/mnt/$DISK_LETTER` (e.g. `/mnt/c/`).

When using `vmType: wsl2`, entries in `mounts` are supported:
- A drive-letter `location` (e.g. `C:\Users\...`) automatically defaults its `mountPoint` to the corresponding `/mnt/<drive>/...` path.
- Locations without a drive letter (such as UNC network paths) cannot be automatically translated and require an explicit `mountPoint`.
- Custom `mountPoint` paths are bind-mounted to the destination inside the guest at boot.
- When `writable: false` is configured, the mount is remounted read-only to prevent accidental modifications at that path. Note that the underlying host files may still be accessible and writable through WSL2's native drive automounts unless configured otherwise.

A reader takes this to mean that setting mountPoint makes a network share work. Nothing in the PR mounts a share, though. The boot script binds only paths that wslpath or its drive-letter fallback can translate, and for any other location line 73 warns and skips the entry. Validate accepts the UNC location on Windows, so limactl start succeeds, and the warning appears only in the guest's boot log.

Review Process Notes ¶

Skill improvements ¶

  • Extend "Entries over nested paths" in the dimensions: check each nesting pair in both list orders, and find the order that the project's config merging (base templates, default and override files) produces. A user rarely writes the order that breaks, but merging can produce it.

Repo context updates ¶

  • [repo] limatmpl embedding appends a base template's list entries (mounts, networks, disks and the rest) after the template's own; only base, provision and probes are prepended. FillDefault then concatenates _config/default.yaml, the template and _config/override.yaml in that order without sorting. Guest-side code that walks LIMA_CIDATA_MOUNTS_* in index order therefore sees an inherited ~ after a template's own ~/projects, and must not assume parents come first.
  • [repo] Boot scripts run under /bin/sh, which is dash on Debian and Ubuntu guests. dash's echo interprets backslash escapes, so a script that logs a Windows path must use printf '%s\n'.
