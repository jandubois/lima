Concerns ¶

  • sshocker rewrites the path again before the server sees it, so the pairing this section advertises is load-bearing for only one of the three toolchains it names. reversesshfs.Start calls convertMSYS2Path, which turns /c/Users/… into C:\Users\… ahead of both the sftp-server's -d and the guest's sshfs argument; under Git for Windows and MSYS2 the server therefore receives a native path whichever toolchain produced it, and only stock Cygwin's /cygdrive/c/… survives. The user-facing sentence at line 113 stays true. Anyone simplifying SftpServerForSSH should know this first. (future) Claude Opus 5

A Windows host page would let each link once. Round 1 raised the same concern and the author took the cheaper route deliberately. (future) Claude Opus 5

Review Process Notes ¶

Skill improvements ¶

  • In PR mode, compare the PR's head SHA against the local branch of the same name before launching agents. When the local branch is ahead, the hosting platform still reports the older head, and the round re-reviews code whose findings the author has already resolved. Report the divergence and settle which SHA to review before spending a round on it.
  • When you propose a fix, apply to the fix the same verification you applied to the defect. A finding produced by running a program earns its confidence from that run; the patch beside it usually does not, and a patch that trades one broken form for another arrives with the finding's authority attached.
  • Before citing a documentation table as authority, check that its columns distinguish the entities your claim distinguishes. A single row summarising a product that ships as separable components supports no claim about one component alone, and a reviewer reading such a table will produce a confident finding about the wrong half.
  • When you build a probe, script, or scratch program to answer a question, report what it returned even when it confirms the code. An experiment that produced no finding is still evidence, and omitting it leaves a reader unable to tell a checked claim from an unchecked one.

Repo context updates ¶

  • [repo] Building the website needs make docsy before hugo: website/hugo.toml imports ../_output as a Hugo module, and that directory is generated by building limactl and running generate-doc. npm --prefix website ci installs the pinned hugo-extended but the build then fails with module "../_output" not found. Treat any claim that the site cannot be built locally as a missing prerequisite rather than a missing tool.
  • [repo] Hugo's {{< ref "page#fragment" >}} resolves the page and fails the build on a bad path, but it never checks the fragment. An anchor in a cross-reference is verified only by rendering the site and matching the emitted href against the target heading's generated id.
  • [repo] pkg/sshutil.NewSSHExe parses SSH with shellwords.Parse, which treats \ as an escape character. A Windows path therefore loses its separators: C:\Program Files\Git\usr\bin\ssh.exe becomes two tokens with every backslash stripped, and wrapping it in double quotes preserves the space while still stripping them. Only single quotes or forward slashes survive. Flag any documentation or default that hands SSH an unquoted backslash path.
  • [repo] A mount with no explicit mountPoint has its guest path derived in FillDefault from the PATH-global converter, and pkg/instance/create.go persists the pre-defaults YAML, so the value is recomputed on every load rather than pinned at create. Stock Cygwin yields /cygdrive/c/... where MSYS2 and Git for Windows yield /c/..., so changing the host toolchain moves an existing instance's mount inside the guest. Weigh any claim that toolchain changes are safe for default installs against this.
