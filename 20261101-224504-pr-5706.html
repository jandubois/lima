Executive Summary ¶

The PR converts both paths to MSYS2 form before calling the ISO generator, which fixes #5704 on an MSYS2 host. But it takes cygpath from PATH before it picks a generator, so the path form doesn't follow the tool that reads it. A Windows host without cygpath now fails even with a generator installed, and a native generator can receive /c/.... The attached patch converts per candidate through sshutil.PathForTool.

Design Observations ¶

Concerns ¶

  • Lima would have three ways to bind a Windows path conversion (in-scope) Claude Opus 5.5 Gemini 3.1 Pro Gemini 3.5 Flash: PathForTool follows the tool, pathForRsync uses the sibling cygpath of a tool that is always Cygwin-based, and this change uses whichever cygpath PATH finds. Only the third can disagree with the program that reads the path, and I1's patch removes it.
  • pkg/iso9660util would import pkg/sshutil (future) Claude Opus 5.5: the package name looks odd beside an ISO helper, but PathForTool's doc comment names this use, and go list -deps ./pkg/sshutil doesn't list iso9660util, so there's no cycle.

Strengths ¶

  • The conversion stays inside writeJolietCommand (in-scope) Claude Opus 5.5: its parameters are by value, so writeJoliet keeps the native paths for os.RemoveAll and the file writes.
  • The new test runs a real generator (in-scope) Claude Opus 5.5 Codex GPT 6 Astra: TestWriteJolietWindows drives Write and reads the image back, which an argv comparison couldn't show. I1's patch keeps it.
  • CI fails when xorrisofs.exe is missing (in-scope) Claude Opus 5.5 Gemini 3.5 Flash: the job stops in windows_msys2_prep, so the new test can't turn into a silent skip there.

Repo context updates ¶

  • [repo] MSYS2's package index has xorriso but no mkisofs, genisoimage or cdrtools (checked 2026-11-01), and xorrisofs reads a path without a leading slash as relative to its working directory. So on a Windows host, a Joliet ISO needs MSYS2's xorriso or a third-party mkisofs or genisoimage build, which may be Cygwin-based or native. Flag a host-side path conversion for these generators that does not follow the selected binary, as for scp and rsync.
